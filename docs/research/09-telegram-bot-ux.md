## Резюме

1. **Главный риск канала — доступность Telegram в России.** Звонки ограничены с августа 2025, 10.02.2026 РКН официально подтвердил замедление, в марте 2026 — массовые сбои, к 10.04.2026 OONI фиксировал до 95% аномалий (фактическая блокировка); по словам Дурова (апрель 2026), ~65 млн россиян пользуются Telegram через VPN [39][40][41][42]. Следствия: (а) пользователю нужен VPN/прокси в клиенте; (б) серверу в РФ нужен **исходящий прокси только для трафика к api.telegram.org**; (в) ядро агента должно быть **независимым от канала** (адаптер Telegram + запасной веб-интерфейс).
2. **Размещение раздваивается**: T-Invest API из зарубежного хостинга недоступен (эмпирика соседнего отчёта 01: один тест из NL; официально брокер заявляет, что чёрных списков IP нет) и использует цепочку сертификатов **Russian Trusted Root CA (Минцифры)** — это подтверждено нашей проверкой `openssl s_client` 2026-10-09. Значит, бэкенд — на VPS в РФ, а Telegram-трафик — через прокси (паттерн уже применён в open-source FinanceTracker: `xray-client` только для Telegram [52]).
3. **Фреймворк: aiogram 3.31.0** (26.08.2026) — единственная Python-библиотека, уже поддерживающая **Bot API 10.3** (24.08.2026); python-telegram-bot 22.8 (12.06.2026) — только Bot API 10.0 [7][8][9][11]. Для многоэкранных меню — **aiogram-dialog 2.6.0** (виджеты, стек диалогов, Redis) [13][14].
4. **Bot API 10.1–10.3 (июнь–август 2026) принёс «Rich Messages»** — `sendRichMessage`/`sendRichMessageDraft`: заголовки, списки, **настоящие таблицы (до 20 колонок)**, сворачиваемые блоки `<details>`, сноски, формулы, кнопки внутри сообщения, до 32 768 символов и 500 блоков; принимается **GitHub-Flavored Markdown** [1][2][3]. Это снимает главную боль финансовых отчётов в чате (таблицы раньше делали через `<pre>` или картинки) и позволяет отправлять Markdown-ответ LLM почти без преобразований.
5. **Стриминг ответов LLM — нативный**: `sendMessageDraft` (доступен всем ботам с 9.5) и `sendRichMessageDraft` с кнопкой «Стоп» (`can_stop`, апдейт `stopped_message_generation`, 10.3) и тегом `<tg-thinking>` [1][2].
6. **Другие полезные новинки 2025–2026**: топики в личном чате с ботом (9.3/9.4) — можно разнести «Отчёты / Идеи / Алерты / Вопросы»; цветные кнопки `style` (9.4); сущность `date_time` — даты купонов/погашений в часовом поясе пользователя с добавлением в календарь (9.5); `DisabledButton` для «уже принятых» решений (10.3); Mini Apps — fullscreen, DeviceStorage (5 МБ), SecureStorage (Keychain/Keystore, 10 ключей), защита от вызова методов с чужих origin (с 20.07.2026) [1][4][38]. **Чек-листы (`sendChecklist`) доступны только от имени бизнес-аккаунта** — для нашего бота не подходят [2].
7. **Mini App — фаза 2, а не MVP**: для одного пользователя чат + aiogram-dialog + rich messages покрывают 90% сценариев. Mini App нужен для удобного редактора портфеля и интерактивных графиков: Vite + React 19 + **@tma.js/sdk 3.x** (пакеты `@telegram-apps/*` с октября 2025 не обновляются, `@telegram-apps/init-data-node` объявлен устаревшим) + **lightweight-charts 5.2.1** (Apache-2.0, обязательна атрибуция TradingView) + FastAPI с HMAC-проверкой `initData` [28][30][31][32][34].
8. **Графики — серверный рендер в PNG через matplotlib (OO API, Agg)**; mplfinance не обновлялся с 2023 (0.12.10b0), Plotly-экспорт через kaleido ≥1.0 требует установленного Chrome [24][25][26]. Отправлять альбомом (2–10 медиа), подпись ≤1024 символа, текст отчёта — отдельным rich-сообщением.
9. **Планировщик**: для персонального бота достаточно APScheduler 3.11 в процессе (4.0 всё ещё alpha) или Taskiq 0.13 + taskiq-redis, если тяжёлые LLM-задачи выносятся в воркер; у Taskiq планировщик должен быть **строго в одном экземпляре** [19][20][21]. Доставка апдейтов — **long polling** (через прокси), webhook не нужен.
10. **Безопасность**: deny-by-default whitelist по `user_id` во внешнем middleware; T-Invest-токен — **readonly и привязанный к конкретному счёту**, хранится вне чата (секреты сервера или AES-GCM в БД), срок жизни — 3 месяца с последнего использования [49]; фильтр логов от токенов; `protect_content` для отчётов; помнить, что переписка с ботом не E2E-шифруется.

#### 1.2. Последствия для бота

- **Клиентская сторона (пользователь).** Пользователь будет открывать бота через VPN или через встроенную в Telegram поддержку прокси (SOCKS5/MTProto в настройках клиента — общеизвестная функция клиентов, отдельно в этой сессии не перепроверялась). Mini App загружается с нашего домена устройством пользователя — значит, домен Mini App должен быть доступен и через VPN, и без него.
- **Серверная сторона.** Если сервер в РФ, исходящие запросы к `api.telegram.org` могут блокироваться. Типовое решение — выделенный исходящий прокси только для Telegram-трафика (aiogram поддерживает `AiohttpSession(proxy="socks5://...")`, в т. ч. цепочки прокси и BasicAuth; нужен пакет `aiohttp-socks`) [10]. Реальный пример: FinanceTracker поднимает `xray-client` как outbound-прокси **только для Telegram-бота**, остальной трафик (T-Invest, PostgreSQL) идёт напрямую [52].
- **T-Invest API.** Соседний отчёт `01-tinvest-api.md` эмпирически установил, что из зарубежного хостинга (NL, Амстердам, AS216139) TCP-соединение с `invest-public-api.tbank.ru:443` не устанавливается. Это единичный тест из одной сети: официальная документация T-Invest утверждает, что чёрных списков IP со стороны брокера нет, поэтому речь о фактической (вероятно, сетевой) недоступности, а не о задокументированной геоблокировке. Наша проверка 2026-10-09 показала, что сервер отдаёт цепочку `*.tbank.ru → Russian Trusted Sub CA → Russian Trusted Root CA` (Минцифры), т. е. в контейнер нужно добавить корневой сертификат НУЦ (или включить встроенный в SDK через `SSL_TBANK_VERIFY=True`, см. отчёт 01). Итог: **компонент, который ходит в T-Invest, надёжнее всего размещать на российском IP**; если рассматривается зарубежный хостинг, доступность нужно проверить с него до выбора.
- **Long polling предпочтительнее webhook**: webhook требует, чтобы серверы Telegram могли достучаться до нашего RU-сервера (порты 443/80/88/8443, валидный TLS) [6] — при блокировках по IP это ненадёжно. Long polling через исходящий прокси работает без входящих соединений.
- **Независимость от канала.** Ядро (портфель, анализ, отчёты, журнал решений) не должно знать о Telegram: отчёт формируется как доменная модель → рендерер Telegram (rich message + фото) / рендерер веб-страницы / e-mail. Это страховка на случай полной потери канала.

#### 2.2. FSM-хранилище и Redis

- Для aiogram-dialog с Redis обязательно `DefaultKeyBuilder(with_destiny=True)` — так сделано в официальном примере `example/simple.py` [14].
- Redis нужен также для дедупликации алертов, кэша `file_id` графиков, rate-limit Q&A и (опционально) брокера Taskiq. Для одного пользователя допустим и `MemoryStorage`, но тогда незавершённые мастера теряются при перезапуске.

```python
# Пример конфигурации (aiogram 3.31, aiogram-dialog 2.6)
from aiogram import Bot, Dispatcher
from aiogram.client.default import DefaultBotProperties
from aiogram.client.session.aiohttp import AiohttpSession
from aiogram.enums import ParseMode
from aiogram.fsm.storage.redis import RedisStorage, DefaultKeyBuilder
from aiogram_dialog import setup_dialogs

session = AiohttpSession(proxy=settings.tg_proxy_url)  # "socks5://user:pass@proxy:1080"; None, если прокси не нужен
bot = Bot(
    token=settings.bot_token.get_secret_value(),
    session=session,
    default=DefaultBotProperties(parse_mode=ParseMode.HTML, protect_content=True),
)
storage = RedisStorage.from_url(
    settings.redis_url,
    key_builder=DefaultKeyBuilder(with_destiny=True),  # требование aiogram-dialog
)
dp = Dispatcher(storage=storage)
dp.update.outer_middleware(OwnerOnlyMiddleware(allowed_ids=settings.owner_ids))  # whitelist, см. §7
dp.include_routers(commands_router, alerts_router, qa_router, *dialogs)
setup_dialogs(dp)

await dp.start_polling(bot, allowed_updates=dp.resolve_used_update_types())
```

#### 2.3. Middlewares, которые понадобятся

| Middleware | Уровень | Назначение |
|---|---|---|
| `OwnerOnlyMiddleware` | `dp.update.outer_middleware` | Deny-by-default: обрабатывать только апдейты от `user_id` из whitelist; чужим не отвечать |
| `DbSessionMiddleware` | `dp.update.middleware` | Сессия SQLAlchemy 2.x на апдейт, транзакция |
| `ErrorReporting` | `dp.errors` | Логирование с маскированием, уведомление владельца в топик «Система» |
| `ThrottlingMiddleware` | `message`/`callback_query` | Защита от двойных нажатий и спама в Q&A (LLM-стоимость) |
| `CallbackAnswerMiddleware` (`aiogram.utils.callback_answer`) | `callback_query` | Гарантированный `answerCallbackQuery`, чтобы не висели «часики» |
| i18n (опционально) | `update` | Если тексты держать в Fluent-файлах |

#### 3.2. Лимиты, которые определяют дизайн сообщений

| Параметр | Значение | Источник |

#### 3.3. Rich Messages — подробно

Формат задаётся **одним** из полей `InputRichMessage`: `markdown`, `html` или `blocks` [3]. Markdown-режим «совместим с GitHub Flavored Markdown, где возможно», и понимает:

- заголовки `#`…`######`, списки, **task-list** `- [ ]`/`- [x]` (визуальные «галочки»), цитаты, разделитель `---`;
- **таблицы GFM** с выравниванием (`|:---|---:|`); в ячейках — только инлайн-форматирование;
- сноски `[^1]`, формулы `$…$`/`$$…$$` (LaTeX), `==выделение==`, `||спойлер||`;
- HTML-вставки: `<details open><summary>…</summary>…</details>`, `<table bordered striped compact>`, `<tg-time unix=… format=wDT>`, `<tg-button type="callback_data" style="primary" data="…">`, `<tg-button-row align="center">`;
- в черновике — `<tg-thinking>Думаю…</tg-thinking>`.

`sendRichMessage` принимает обычный `reply_markup` (inline-клавиатура), `protect_content`, `disable_notification`, `message_effect_id`, `message_thread_id` (для топиков) [2]. Редактирование — `editMessageText` с параметром `rich_message` [1].

Практические выводы:
- **Отчёт ребалансировки и ответ LLM можно отправлять как Markdown**: LLM естественно генерирует GFM-таблицы; надо лишь валидировать лимиты (≤20 колонок, ≤500 блоков) и иметь fallback.
- Кнопки решений можно размещать **внутри** отчёта (по строкам действий) через `<tg-button>`, а глобальные («Принять всё», «Отложить всё») — в `reply_markup`. Ограничение `callback_data` 64 байта сохраняется.
- **[не проверено]** Как rich-сообщения выглядят на старых версиях клиентов и в Telegram Web/Desktop — документация этого не описывает; нужен fallback-рендерер (обычный HTML + `<pre>`-таблица или PNG-таблица) и флаг в настройках «упрощённый формат».

```python
from aiogram.types import InputRichMessage, InlineKeyboardMarkup, InlineKeyboardButton

md = """## Ребалансировка · неделя 41
**Итог:** 3 действия, оборот ≈ 4,1% портфеля. Отклонение от целей: 6,8 → 1,2 п.п.

| Класс | Факт | Цель | Δ, п.п. |
|:--|--:|--:|--:|

</details>

[^1]: Расчёт на данных T-Invest от <tg-time unix="1791615600" format="wDT">сб 10:00</tg-time>.
"""
await bot.send_rich_message(
    chat_id=owner_id,
    rich_message=InputRichMessage(markdown=md),
    reply_markup=InlineKeyboardMarkup(inline_keyboard=[[
        InlineKeyboardButton(text="Принять всё", callback_data="rb:A:812:0", style="primary"),
        InlineKeyboardButton(text="Отложить", callback_data="rb:P:812:0"),
```

#### 3.4. Прочие элементы интерфейса

- **Menu button и команды.** Кнопка меню у поля ввода показывает список команд (или открывает Mini App); тексты команд можно задавать по областям (`BotCommandScope*`) и языкам; Telegram просит поддерживать глобальные `/start`, `/help` и `/settings` (последнюю — «если применимо») [5]. Для приватного бота команды стоит регистрировать в области `BotCommandScopeChat(chat_id=owner)`, а в области по умолчанию оставить пусто.
- **Reply-клавиатура** (`is_persistent=True`) — постоянная «панель вкладок» из 4–6 кнопок; **inline-клавиатура** — действия внутри конкретного сообщения. Telegram рекомендует **редактировать** сообщение с клавиатурой при навигации, а не слать новое [5] — это ровно модель aiogram-dialog.
- **Топики в личном чате** (9.3/9.4): бот может создать топики `createForumTopic` и запретить пользователю создавать свои (настройка в @BotFather); сообщения адресуются через `message_thread_id` [1]. Для нас: «📊 Отчёты», «💡 Идеи», «🔔 Алерты», «💬 Аналитик», «🛠 Система». Минус — UX топиков на разных клиентах **[не проверено]**; делаем опцией.
- **`date_time`** (9.5): `<tg-time unix=… format="wDT">` или `![…](tg://time?unix=…&format=…)`; формат `r` — относительное время («через 3 дня»), `w` — день недели, `d/D` — дата, `t/T` — время [2]. Тап по дате даёт пользователю «добавить в календарь / напоминание» [38] — идеально для купонов, офферт, погашений ЦФА, дат отсечки.
- **Expandable blockquote** (`<blockquote expandable>`) в обычных сообщениях и `<details>` в rich — для «Почему?» без отдельного экрана [2].
- **Спойлеры** `<tg-spoiler>` — «режим приватности»: суммы в рублях скрыты, пока не тапнешь (полезно, если телефон видят другие).
- **`protect_content=True`** — запрет пересылки и сохранения отчётов (можно задать по умолчанию в `DefaultBotProperties`) [2].
- **Цвет кнопок** `style`: `primary` (синий), `success` (зелёный), `danger` (красный) [2]. У кнопок внутри rich-сообщений (`RichMessageButton`, 10.3) есть ещё стиль `link` — только для callback-кнопок. Рекомендация: не красить «Купить/Принять» в зелёный (лишний nudging), `danger` — только для деструктивных действий («Удалить позицию»).
- **`DisabledButton` / поле `disabled`** (10.3): после решения кнопка остаётся видимой, но неактивной — наглядная история решений прямо в чате [1].
- **Опросы**: до 12 вариантов (9.1), переголосование и описание (9.6) — можно использовать для анкеты риск-профиля, но inline-кнопки с пояснениями и кнопкой «Назад» удобнее и проще в FSM.
- **Эффекты сообщений** (`message_effect_id`, только в личке) — уместны максимум для «Портфель вернулся в целевые коридоры», не для торговых сигналов.

#### 3.5. Стриминг ответов LLM

- `sendMessageDraft(chat_id, draft_id, text, …)` — частичный ответ, пустой `text` показывает плейсхолдер «Thinking…»; одинаковый `draft_id` даёт анимированное обновление. Черновик — временное превью (~30 с), **финал обязательно отправить обычным `sendMessage`/`sendRichMessage`** [2].
- `sendRichMessageDraft` — то же для rich-разметки (таблицы появляются по мере генерации) + `<tg-thinking>` [3].
- `can_stop=True` показывает кнопку «Стоп»; при нажатии приходит апдейт `stopped_message_generation` (в aiogram — `router.stopped_message_generation`, объект `MessageGenerationStopped` с `draft_id`). `keep_on_stop` оставляет черновик в чате лишь ненадолго: он всё равно исчезнет через короткое время или при следующем сообщении бота, поэтому частичный ответ нужно отправить отдельным сообщением [1][2]. Это позволяет прервать дорогой LLM-ответ и сэкономить токены.
- Telegram в майском (07.05.2026) и мартовском (01.03.2026) обновлениях прямо позиционирует стриминг как функцию для AI-ботов, доступную всем [37][38].

```python
import asyncio, itertools
from aiogram.types import InputRichMessage

_draft_ids = itertools.count(1)          # draft_id должен быть ненулевым

async def stream_answer(bot, chat_id: int, llm_stream, thread_id: int | None = None):
    loop = asyncio.get_running_loop()
    draft_id = next(_draft_ids)
    buf, last_push = "", 0.0
    async for chunk in llm_stream:        # токены от LLM
        buf += chunk
        if loop.time() - last_push > 0.6:  # не чаще ~1-2 раз в секунду
            await bot.send_rich_message_draft(
                chat_id=chat_id, draft_id=draft_id, message_thread_id=thread_id,
                rich_message=InputRichMessage(markdown=buf), can_stop=True,
            )
            last_push = loop.time()
    # финальное сообщение — обязательно отдельным вызовом
    await bot.send_rich_message(chat_id=chat_id, message_thread_id=thread_id,
                                rich_message=InputRichMessage(markdown=buf))
```

(Схематичный пример: обработка ошибок разметки, лимитов 32 768 символов / 500 блоков и fallback на `sendMessage` опущены.)

#### 4.3. Аутентификация Mini App

Алгоритм из документации Telegram [4]:
1. Фронтенд передаёт на бэкенд сырую строку `Telegram.WebApp.initData` (в заголовке `Authorization: tma <initData>`).
2. Бэкенд строит data-check-string: все поля, кроме `hash`, отсортированные по алфавиту, `key=value` через `\n`.
3. `secret_key = HMAC_SHA256(key="WebAppData", msg=bot_token)`; сравнить `hex(HMAC_SHA256(secret_key, data_check_string))` с `hash` (constant-time).
4. Проверить свежесть `auth_date`, затем `user.id` ∈ whitelist.
5. Для проверки третьей стороной без токена бота есть вариант с подписью **Ed25519** (поле `signature`, публичные ключи Telegram для test/prod опубликованы) [4].

```python
# FastAPI-зависимость (схема)
import time
from fastapi import Header, HTTPException
from aiogram.utils.web_app import safe_parse_webapp_init_data

MAX_AGE = 3600  # 1 час для чтения; для изменения целей/токена — 5 минут

def tma_user(authorization: str = Header(...)):
    scheme, _, raw = authorization.partition(" ")
    if scheme != "tma":
        raise HTTPException(401)
    try:
        data = safe_parse_webapp_init_data(settings.bot_token.get_secret_value(), raw)
    except ValueError:
        raise HTTPException(401, "bad signature")
    if time.time() - data.auth_date.timestamp() > MAX_AGE:
        raise HTTPException(401, "expired")
    if not data.user or data.user.id not in settings.owner_ids:
        raise HTTPException(403)
    return data.user
```

#### 4.4. Возможности Mini App, полезные здесь

- **Способы запуска** [4]: кнопка меню (`setChatMenuButton` с `MenuButtonWebApp`), inline-кнопка `web_app` (в т. ч. из отчёта: «Открыть график»), reply-кнопка (только она позволяет `sendData` до 4096 байт обратно в чат), Main Mini App с прямой ссылкой `https://t.me/<bot>?startapp=<param>` (параметр приходит в `start_param` — удобно для deep-link «открыть позицию X»), `mode=compact` — половина экрана.
- **Full-screen** (`requestFullscreen`, `safeAreaInset`), `lockOrientation` — для графиков в альбомной ориентации; `addToHomeScreen` — ярлык «Портфель» на рабочий стол [4].
- **BottomButton / SecondaryButton** — «Сохранить» / «Отмена» в редакторе; `enableClosingConfirmation` — защита от потери несохранённых правок; **BiometricManager** — подтверждение чувствительных действий (смена целевых долей, замена токена) [4].
- **Хранилища**: CloudStorage (на серверах Telegram, синхронизируется между устройствами) — только UI-настройки; DeviceStorage (5 МБ) — кэш котировок/графиков; SecureStorage (Keychain/Keystore, 10 элементов) — максимум локальный PIN/флаги. **Источник истины для портфеля и токенов — наш сервер**, не хранилища Telegram [4].
- **Hardening 10.2**: с 20.07.2026 методы Mini App нельзя вызывать с origin, отличного от исходного домена Mini App (можно отключить в @BotFather, но тогда ответственность на разработчике) [1]. Значит: не вставлять в Mini App сторонние страницы/iframe с других доменов, графики рисовать у себя.
- **HTTPS обязателен** в боевой среде; HTTP без TLS разрешён только в тестовом окружении Telegram [4]. Практично: Caddy с автоматическим TLS перед статикой и FastAPI.
- Для `downloadFile` (выгрузка CSV) сервер должен отдавать `Content-Disposition: attachment` и `Access-Control-Allow-Origin: https://web.telegram.org` [4].

#### 5.1. Библиотеки рендера (серверная сторона)

| Библиотека | Версия (дата) | Плюсы | Минусы |
|---|---|---|---|

**Рекомендация:** matplotlib (OO API) для всех PNG в чате; свечи — собственной функцией (или mplfinance с закреплёнными версиями зависимостей). Рендер — в `asyncio.to_thread` или пуле процессов, чтобы не блокировать event loop. Кэшировать `file_id` отправленных картинок (Telegram разрешает считать `file_id` постоянными [6]).

```python
import io
from matplotlib.figure import Figure
from aiogram.types import BufferedInputFile

def render_allocation(fact: dict[str, float], target: dict[str, float]) -> bytes:
    fig = Figure(figsize=(8, 4.5), dpi=200)        # ~1600x900 px, читаемо на телефоне
    ax = fig.add_subplot()
    labels = list(target)
    x = range(len(labels))
    ax.barh([i + 0.2 for i in x], [fact[k] for k in labels], height=0.4, label="Факт")
    ax.barh([i - 0.2 for i in x], [target[k] for k in labels], height=0.4, label="Цель")
    ax.set_yticks(list(x), labels)
    ax.xaxis.set_major_formatter(lambda v, _: f"{v:.0f}%")
    ax.legend(loc="lower right"); fig.tight_layout()
    buf = io.BytesIO(); fig.savefig(buf, format="png"); return buf.getvalue()

png = await asyncio.to_thread(render_allocation, fact, target)
await bot.send_photo(owner_id, BufferedInputFile(png, "allocation.png"),
                     caption="Структура: факт vs цель (пример)", show_caption_above_media=False)
```

| Динамика стоимости vs бенчмарк (IMOEX/RGBI) | Недельный отчёт | Линия, нормированная к 100; подписи последних значений |
| Просадка от максимума | Недельный отчёт / алерт | Область под нулём |
| Карточка идеи | Лента идей | Свечи за 6–12 мес + зона входа + скользящие + маркеры новостей; внизу — полоса сентимента |
| Лестница облигаций/ЦФА | Портфель → Облигации | Бары по месяцам погашений/оферт + точки купонов |
| Календарь выплат | Портфель | Столбцы ожидаемых купонов/дивидендов по месяцам |

#### 5.3. Таблицы: варианты по убыванию качества

1. **Rich-таблица** (`| … |` в Markdown или `<table compact>`) — нативная, адаптивная, до 20 колонок [3]. Для телефона держать 3–5 колонок; остальное — в `<details>` или Mini App.
2. `<pre>`-таблица моноширинным шрифтом (обычный `sendMessage`) — fallback; ширина ≈32–36 символов для портретного экрана телефона (эмпирическое правило, **[не проверено]** на всех клиентах).
3. PNG-таблица (matplotlib `ax.table`) — когда нужна раскраска ячеек.
4. CSV/XLSX-вложение — для полного экспорта (до 50 МБ) [2].

#### 5.4. Лучшие практики финансового отчёта в чате

1. **Перевёрнутая пирамида**: первая строка — вердикт («Нужна ребалансировка: 3 действия, оборот ≈4% портфеля»), затем ключевые цифры, затем детали в сворачиваемых блоках.
2. **Один экран** для сводки (≈800–1200 символов); всё остальное — `<details>`, «Подробнее», вложения. Rich-сообщение длиннее ~8 000 символов клиент обрезает кнопкой «Show More» [36].
3. **Единый формат чисел**: неразрывный пробел в тысячах (`1 234 567 ₽`), знак у изменений (`+2,3%`, `−0,8 п.п.`), доли — в процентах, отклонения — в **процентных пунктах**; одинаковое округление в тексте и на графике.
4. **Цвет/эмодзи — только для фактов** (🟢/🔴 P&L), не для призывов к действию; не полагаться только на цвет (подписи/знаки).
5. **Свежесть и происхождение данных**: «данные T-Invest на `<tg-time>`», версия модели, источники новостей — сносками [3].
6. **Объяснимость каждого действия**: «почему» (факторы с вкладами), неопределённость («уверенность: средняя»), что будет, если ничего не делать.
7. **Учёт издержек**: показывать оценку комиссий и налога (НДФЛ с прибыли, льгота долгосрочного владения) рядом с продажами — детали налогов вне рамок этого отчёта **[уточнить в отчёте 07]**.
8. **Короткий дисклеймер** в футере («аналитика для личного использования, решения принимаете вы»).
9. **Приватность**: опциональный режим «только доли» (рубли под спойлером), `protect_content=True` по умолчанию.
10. **Идемпотентность кнопок**: после нажатия — `answerCallbackQuery` с тостом, редактирование сообщения (статус ✅/⏸/⏭, кнопки → `disabled`), повторное нажатие не создаёт дубль решения.
11. **Тишина по умолчанию**: `disable_notification=True` для некритичных сообщений; срочные алерты — со звуком.

| Критерий | Long polling | Webhook |

| Совместимость | Нельзя одновременно с установленным webhook [6] | — |

**Выбор: long polling.**

### 7. Безопасность

#### 7.1. Доступ к боту

- **Whitelist в `dp.update.outer_middleware`**: проверка `event_from_user.id` до любых фильтров и FSM; апдейты чужих пользователей молча отбрасываются (без ответа — не раскрываем, что бот «живой»), в лог — только счётчик.
- Команды — в `BotCommandScopeChat(owner)`; в @BotFather отключить добавление в группы и inline-режим (не нужны).
- Тот же whitelist — в бэкенде Mini App (после HMAC-проверки `initData`, §4.3).

```python
from aiogram import BaseMiddleware

class OwnerOnlyMiddleware(BaseMiddleware):
    def __init__(self, allowed_ids: set[int]):
        self.allowed = allowed_ids
    async def __call__(self, handler, event, data):
        user = data.get("event_from_user")
        if user is None or user.id not in self.allowed:
            return None            # тихо игнорируем
        return await handler(event, data)
```

#### 7.2. Токен T-Invest

- Типы токенов: **readonly**, full-access, **токен с доступом к конкретному счёту** (с уровнем прав readonly/full), sandbox. Токен показывается один раз; **срок жизни — 3 месяца с даты последнего использования**; ошибка `40003` — токен недействителен (например, завершены все сессии) [49].
- Для бота: **readonly + привязка к нужному счёту** (бот не совершает сделок — full-access не нужен вовсе). Официальный Python SDK теперь называется `t-tech-investments` (импорт `t_tech.invest`), ставится с индекса GitLab Т-Банка (`opensource.tbank.ru`) и поддерживает и боевой контур, и песочницу. Старый `tinkoff-investments` с PyPI удалён (404), а репозиторий `RussianInvestments/invest-python` на GitHub архивирован (см. отчёт 01) [50].
- Хранение: (1) предпочтительно — секрет сервера (Docker secret / `.env` с правами 600 / sops+age), не через чат; (2) если токен вводится через UI — только через Mini App по HTTPS, в БД — шифрование AES-256-GCM (`cryptography` 50.0.2 [53], `AESGCM`), ключ — вне БД (переменная окружения/KMS), `user_id` как AAD, маскирование при показе (`t.…abcd`).
- Если пользователь всё же прислал токен сообщением — бот немедленно удаляет это сообщение (`deleteMessage` работает для входящих в личке в течение 48 ч [2]), предупреждает и предлагает перевыпустить токен.
- Мониторинг: ежедневный вызов API продлевает жизнь токена; при `40003` — алерт в «🛠 Система».

#### 7.3. Утечки через логи и LLM

- Токен бота входит в URL запросов (`/bot<token>/method`) — фильтр логов на регулярные выражения токенов (Telegram: `\d{6,12}:[A-Za-z0-9_-]{30,}`; T-Invest-токены — по фактическому формату, **[не проверено]** что все начинаются с `t.`), отключить DEBUG-логи HTTP-клиентов в проде.
- В LLM-промпты не передавать номера счетов, ФИО, токены; портфель — в нормализованном виде (тикер, доля, количество) с псевдонимизацией счетов; журнал промптов хранить с маскированием и сроком хранения.
- Ошибки, отправляемые владельцу в чат, — без стектрейсов с секретами.

#### 7.4. Канал Telegram и данные

- Переписка с ботом — облачная, **без сквозного шифрования**: отчёты с суммами хранятся на серверах Telegram. Митигировать: режим «только доли», спойлеры для сумм, `protect_content`.
- Mini App: CSP, отсутствие сторонних скриптов (кроме закреплённых версий), сессия на основе `initData` с коротким TTL, повторная проверка для критичных изменений (BiometricManager) [4].
- Если когда-нибудь включать webhook — обязательно `secret_token` [2].
- Бэкапы БД — шифрованные; ключ шифрования токенов — не в том же бэкапе.

Общие принципы, которые следуют из этих примеров:
1. **Двухуровневая подача**: короткая сводка → разбор по кнопке «Подробнее/Почему?».
2. **Распределение пополнения** как главный «бесплатный» способ ребалансировки (покупки вместо продаж — меньше налогов и комиссий).
3. **Календарь событий** (купоны, дивиденды, оферты, погашения ЦФА) — самый частый повод открыть бота.
4. **Детерминированный fallback**: отчёт уходит, даже если LLM недоступна (цифры считает код, LLM только объясняет).
5. **Журнал решений** с последующей оценкой качества рекомендаций.

**Добавление позиции** (aiogram-dialog, одно сообщение редактируется по шагам, кнопка «◀️ Назад» на каждом шаге):

| Шаг | Окно | Виджеты / валидация |
|---|---|---|
| 1 | Класс актива | `Select`: Акция · Облигация · Фонд · ЦФА · Кэш/валюта |

**Форма ЦФА** (ручной ввод; если ЦФА видны через T-Invest API — импорт, см. отчёты 01 и 07):


Для ЦФА бот сам считает график выплат, добавляет события в календарь и учитывает отдельный потолок доли и признак «неликвид» в ребалансировке (такие позиции не продаются в рекомендациях, только учитываются в весах).

**Импорт из T-Invest — всегда через diff-превью**:

```
ПРИМЕР (вымышленные данные)

🔒 Ручные позиции не затронуты: ЦФА × 2
[✅ Применить всё] [👀 По одному] [✖️ Отмена]
```

**CSV/XLSX**: пользователь отправляет файл документом (скачивание ботом — до 20 МБ [2]); бот присылает шаблон по кнопке «Шаблон CSV». Колонки: `class, ticker_or_isin, name, qty, avg_price, currency, buy_date, account, platform, nominal, coupon_rate, coupon_freq, maturity_date`. После разбора — превью первых строк, список ошибок со ссылкой на номер строки и тот же diff-экран.

```
- Новостной фон по сектору X улучшился: сентимент −0,05 → +0,22 (37 публикаций)
- Диагностика: превышен лимит на эмитента (AAAA 12,4% > 10%)

[✅ Принять всё] [⏸ Отложить] [⏭ Пропустить]

```

**Сообщение 2 — альбом из 2–3 PNG** (факт vs цель, динамика vs бенчмарк, просадка) с короткой подписью.

**«Разобрать по одному»** — карточка на действие:

```
ПРИМЕР (вымышленные данные)
Действие 1/3 · Продать AAAA · 10 шт. (≈ 31 200 ₽)
Цель: вернуть долю эмитента к 10% (сейчас 12,4%)
Уверенность: средняя · без действия: риск концентрации сохраняется
[✅ Принять] [⏭ Пропустить] [⏸ Отложить]
[🤔 Почему?] [📋 Скопировать заявку]
```

- `📋 Скопировать заявку` — `copy_text`-кнопка с строкой вида «AAAA SELL 10 LMT 3190» для ручного ввода в приложении брокера [2].
- `⏸ Отложить` → `[Завтра] [Через 3 дня] [До понедельника 10:00] [До следующего отчёта]` → напоминание по расписанию.
- `⏭ Пропустить` → необязательная причина в один тап: `[Не согласен с анализом] [Нет свободных денег] [Налоги/срок владения] [Сделаю иначе] [Без причины]` — ценнейший сигнал обратной связи.
- После решения сообщение редактируется: статус `✅ Принято 10.10 12:41`, кнопки становятся `disabled` (10.3) или убираются; на исходном сообщении можно поставить реакцию бота (`setMessageReaction`, доступен с Bot API 7.0) [1].
- **Подтверждение исполнения**: при следующей синхронизации бот сопоставляет операции T-Invest с принятыми действиями: «🔄 Найдена сделка: продажа AAAA 10 шт. по 3 118 ₽ — засчитать как исполнение действия 1? `[Да] [Нет]`». Ручное «Отметить исполненным» — тоже доступно.

**Жизненный цикл действия:**

```
DRAFT → SENT → PENDING ─┬─ ACCEPTED ──┬─ EXECUTED (сделка найдена/отмечена)
                        │             └─ NOT_EXECUTED (истёк срок)
                        ├─ POSTPONED(until) → PENDING (напоминание)
                        ├─ SKIPPED(reason)
                        └─ EXPIRED (вышел новый отчёт)
```

**Журнал решений (схема БД):**

```sql
create table rebalance_report (
  id bigserial primary key, created_at timestamptz not null default now(),
  snapshot_id bigint not null, ips_version int not null, model_version text not null,
  status text not null, tg_message_ids jsonb
);
create table rebalance_action (
  id bigserial primary key, report_id bigint references rebalance_report(id),
  seq int not null, side text check (side in ('buy','sell')), instrument_uid text not null,
  qty numeric not null, est_price numeric, est_amount numeric,
  rationale jsonb not null,           -- факторы и их вклады, ссылки на новости
  confidence real, state text not null
);
create table decision (
  id bigserial primary key, report_id bigint not null, action_id bigint null, -- null = весь отчёт
  verdict text check (verdict in ('accept','skip','postpone')),
  reason_code text, comment text, postpone_until timestamptz,
  decided_at timestamptz not null default now(), channel text not null default 'telegram'
);
create table execution (
  id bigserial primary key, action_id bigint references rebalance_action(id),
  broker_operation_id text, qty numeric, price numeric, executed_at timestamptz,
  matched_by text check (matched_by in ('auto','manual'))
);
```

Журнал нужен для `/journal` («за 12 недель: N рекомендаций, принято X%, исполнено Y%»), для честной оценки качества рекомендаций (принятые vs пропущенные через 4/12 недель) и как **источник обратной связи для RL/контекстных бандитов** (ранжирование идей, калибровка частоты и агрессивности советов) — см. отчёт 06.

**Callback-схема** (укладывается в 64 байта):

```python
from typing import Literal
from aiogram.filters.callback_data import CallbackData

class RebalCB(CallbackData, prefix="rb"):
    act: Literal["A", "S", "P", "W", "C"]   # accept / skip / postpone / why / copy
    rep: int                                 # report_id
    item: int = 0                            # 0 = весь отчёт

class IdeaCB(CallbackData, prefix="id"):
    act: Literal["why", "more", "wl", "hide", "nav"]
    idea: int
    page: int = 0

# RebalCB(act="P", rep=100234, item=3).pack() -> "rb:P:100234:3"  (13 байт)
```

#### 9.9. Лента идей для входа

```
ПРИМЕР (вымышленные данные)
💡 Идея #17 · Облигации · горизонт 6–12 мес
«Эмитент Г» БО-05 — кандидат на вход частями
Скоринг 72/100 · уверенность средняя · риск: средний
• Доходность выше кривой ОФЗ на сопоставимой дюрации (спред +2,1 п.п.)
• Новостной фон: нейтральный → позитивный (сентимент 14д +0,15)
• Ликвидность: достаточная (оборот ≈ 40 млн ₽/день)
Влияние на портфель: облигации 31,5% → 33,0% (цель 35%)
[🤔 Почему?] [📄 Подробнее] [⭐ В watchlist] [🙈 Скрыть]
[◀️] 2/6 [▶️]
```

- `🤔 Почему?` — разворачивает expandable blockquote: факторы с вкладами, контраргументы («что может пойти не так»), источники-сноски.
- `📄 Подробнее` — rich-сообщение с таблицей метрик + PNG-график с зоной входа; кнопка `web_app` «Открыть интерактивный график» (фаза 2).
- `⭐ В watchlist` — бумага уходит в `/watchlist`, предлагаются алерты (цена/доходность/сентимент).
- `🙈 Скрыть` — с причиной в один тап («не мой сектор», «слишком рискованно», «уже есть»): обратная связь для ранжирования.
- Фильтры ленты: класс актива, горизонт, риск, «только то, что приближает к целям».
- Частота: идеи — не push, а по запросу и в составе недельного отчёта (блок «Топ-3 идеи»); push — только для бумаг из watchlist при срабатывании условий.

## Выводы для архитектуры агента

1. **Канал — сменный адаптер.** Ядро формирует доменные объекты (`PortfolioView`, `WeeklyReport`, `Idea`, `Alert`, `Answer`), а слой `channels/telegram` рендерит их в rich message / PNG / клавиатуры. Второй рендерер (веб-страница Mini App/PWA и e-mail) — страховка от блокировки Telegram в РФ.
2. **Размещение: VPS в РФ + исходящий прокси только для Telegram** (вариант A, §6.3). T-Invest в тесте отчёта 01 был недоступен из зарубежного хостинга и требует корневой сертификат Минцифры; Telegram из РФ — только через прокси. Long polling вместо webhook.
3. **Стек бота:** Python 3.12/3.13, aiogram 3.31 (Bot API 10.3) + aiogram-dialog 2.6 + Redis (FSM с `with_destiny=True`, дедупликация алертов, кэш `file_id`) + PostgreSQL (SQLAlchemy 2.1) + APScheduler 3.11 (MVP) → Taskiq 0.13 (когда LLM-задачи уходят в воркер).
4. **Формат сообщений:** основной — `sendRichMessage` с Markdown (таблицы, `<details>`, сноски, `date_time`), стриминг Q&A — `sendRichMessageDraft` с `can_stop`; обязательный fallback-рендерер (HTML + `<pre>` / `telegramify-markdown`) и проверка лимитов (4096 / 1024 / 32 768 символов, 500 блоков, 20 колонок, 64 байта `callback_data`).
5. **Графики — серверный PNG (matplotlib OO API)** в отдельном потоке/процессе, альбомами по 2–3, с кэшем `file_id`; интерактив — в Mini App (lightweight-charts) в фазе 2.
6. **Журнал решений — first-class сущность**: отчёт → действия → решения (accept/skip/postpone + причина) → исполнение (автосопоставление с операциями T-Invest). Это и UX (`/journal`), и метрика качества, и сигнал обратной связи для RL/бандитов.
7. **Детерминированное ядро, LLM — объясняет**: все числа в сообщениях считаются кодом; при недоступности LLM недельный отчёт уходит в «сухом» виде.
8. **Mini App — фаза 2**: Vite + React 19 + `@tma.js/sdk-react` + lightweight-charts (с атрибуцией TradingView) + FastAPI; авторизация по HMAC `initData` + проверка `auth_date` + whitelist; HTTPS через Caddy; ничего с чужих origin (hardening 10.2).
9. **Безопасность по умолчанию**: whitelist во внешнем middleware, команды только в scope владельца, readonly-токен на один счёт вне чата, AES-GCM для секретов в БД, фильтр логов, `protect_content`, режим «только доли».
10. **Топики в личке** — опция для разделения потоков (отчёты/идеи/алерты/Q&A/система), с fallback на обычный чат.
11. **Расписание в TZ пользователя**, все даты событий в сообщениях — через `date_time`-сущности (тап → календарь/напоминание).

## Риски и подводные камни

- **Блокировка Telegram в РФ** (OONI до 95% аномалий в апреле 2026) [41]: пользователь без VPN/прокси бота не увидит; серверный прокси — единая точка отказа (нужен мониторинг и резервный узел); правовой статус использования средств обхода для такого сервиса — **[уточнить]**.
- **Геодоступность T-Invest**: в тесте отчёта 01 API был доступен не из всех сетей (из NL-хостинга — таймаут), надёжный вариант — российский IP; плюс национальная PKI (Russian Trusted Root CA) — необходимость расширять trust store контейнера; при смене цепочки сертификатов соединение «падает» (см. отчёт 01).
- **Rich messages очень новые** (июнь–август 2026): возможны баги клиентов, неполная поддержка на старых версиях/десктопе **[не проверено]**; aiogram выпускает фиксы почти каждый месяц (3.31.0 исправлял дефолты для новых методов) [8]. Держать fallback и закреплять версию.
- **Лимит `callback_data` 64 байта** — длинные идентификаторы (UID инструментов T-Invest — UUID 36 символов) не помещаются; хранить короткие локальные ID.
- **Черновики стриминга живут ~30 с** — обязательно отправлять финальное сообщение; при ошибке LLM — чистить «висящий» черновик сообщением об ошибке [2].
- **Частота сообщений ≈1/с на чат** [6]: недельный отчёт из сводки + альбома + карточек можно отправлять с паузами; при 429 — ретрай с `retry_after`.
- **`sendChecklist` только для бизнес-аккаунтов** — не проектировать UX на нативных чек-листах [2].
- **mplfinance заброшен** (2023), **kaleido требует Chrome** — не закладываться на них в Docker-образе бота [25][26].
- **`@telegram-apps/*` пакеты замерли**, init-data-node deprecated — легко взять устаревший пример из интернета [30][32].
- **Taskiq scheduler в нескольких экземплярах** дублирует задачи (двойной недельный отчёт) [21].
- **Переписка не E2E**: суммы и состав портфеля хранятся у Telegram; утечки через пересылку/скриншоты (`protect_content` не защищает от фото экрана другим устройством).
- **Токен T-Invest «умирает» через 3 месяца неиспользования** и при завершении всех сессий в приложении брокера [49] — нужен алерт `40003`.
- **Nudging и ответственность**: цветные кнопки, эффекты, «геймификация» решений могут подталкивать к лишним сделкам; если бот когда-нибудь будет предоставляться третьим лицам, индивидуальные инвестиционные рекомендации — регулируемая деятельность (инвестсоветник) **[уточнить в юридическом разделе]**.
- **MAX как запасной канал** требует статуса юрлица/ИП/самозанятого и модерации [48]; вопросы приватности (СОРМ) и санкции против VK [45][46].
- **Деградация UX при отказе источников**: отчёт с частью устаревших данных должен явно помечать свежесть каждого блока, а не молча использовать старые цифры.
