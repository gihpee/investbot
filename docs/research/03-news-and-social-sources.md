# Источники новостей, раскрытий и соцсигналов для сентимента (российский рынок)

> Дата исследования: 2026-10-09
>
> Метод: веб-поиск (RU/EN), чтение первоисточников (proto-контракты T-Invest API на GitHub, справочник MOEX ISS, страницы ЦБ, условия Telegram) и **живые запросы** к RSS/API. Все пометки «проверено» означают реальный HTTP-запрос 2026-10-09 около 13:00–14:30 МСК. Запросы шли с **зарубежного IP (Нидерланды)**, поэтому часть российских сайтов была недоступна. Это само по себе важный архитектурный вывод, см. раздел 1.3.
>
> Ограничение: примерно на середине работы закончился общий лимит веб-поиска сессии. Поэтому часть фактов (Yandex Wordstat API, точные адреса RSS РБК, Коммерсанта, РИА и ПРАЙМ, покрытие GDELT по РФ) осталась **не проверенной** и помечена в тексте.

## Резюме

1. **Бесплатный «скелет» новостного контура собирается из проверенных RSS и открытых API.** Рабочие RSS (проверено 2026-10-09): Интерфакс, ТАСС, Ведомости (общая лента и рубрики «Инвестиции», «Финансы/Рынки»), Frank Media (с полным текстом), The Bell, Финам «Новости компаний», Smart-lab (новости, блоги, раскрытие, форум по тикеру, тег по тикеру), Финмаркет, Forbes, Lenta, Investing.com RU. Сюда же входят 5 RSS-лент ЦБ и новости Мосбиржи (ISS `/iss/sitenews` и RSS-экспорт с полным текстом) [1][3][4][6][7][8][9][13][20][29][30].
2. **У ключевых лент очень маленькая глубина.** В RSS Интерфакса 25 элементов, это примерно 1,4–1,6 часа потока. В ТАСС 100 элементов, это около 1 часа. Поэтому опрашивать их нужно каждые 10–15 минут и с первого дня складывать в свой архив. Исторический бэкфилл через RSS невозможен; ограниченно восстановить заголовки можно только из HTML-архивов по датам (например, `interfax.ru/news/YYYY/MM/DD/`), с учётом лицензионных условий.
3. **Самые ценные структурированные «сентимент-подобные» данные уже есть в T-Invest API**: `GetForecastBy` (прогнозы инвестдомов и консенсус), `GetConsensusForecasts` (buy/hold/sell и целевые цены по всем бумагам), `SignalService.GetSignals` (идеи аналитиков и технические сигналы), `GetInsiderDeals`, `GetAssetReports`, `GetDividends`, `GetBondEvents` [35][36][37]. Лимит сервиса инструментов составляет 200 unary-запросов в минуту [38].
4. **Раскрытие (существенные факты).** У e-disclosure.ru (Интерфакс-ЦРКИ) нет открытого бесплатного API. Есть платные «шлюз (API)», FTP-выгрузка и email-рассылка, цены по запросу. С зарубежного IP портал недоступен. Бесплатная альтернатива — RSS «Лента раскрытия информации» Smart-lab, но в бесплатном доступе наблюдалась задержка около 1,5–2 суток [13][14][62][63].
5. **Telegram-каналы — главный канал розничного сентимента, но с тремя серьёзными ограничениями.**
   - (а) Условия Telegram прямо запрещают скрейпинг и агрегацию данных платформы для обучения и *развёртывания* AI/ML. Это касается и LLM-анализа сентимента [47][48].
   - (б) С 10.02.2026 Роскомнадзор замедляет, а затем фактически блокирует Telegram в РФ, поэтому сборщик и бот должны иметь не-российский сетевой выход [56][57].
   - (в) Риск бана user-аккаунта при Telethon/Pyrogram.
   
   Технически самый простой путь — публичный веб-превью `t.me/s/<channel>` или self-hosted RSSHub. Оба работают без аккаунта (проверено).
6. **У «Пульса» Т-Инвестиций нет официального API.** Неофициальный endpoint (`/api/invest-gw/social/v1/post/instrument/{ticker}`) использовала библиотека tpulse, последний релиз которой вышел в январе 2023. По наблюдениям авторов свежего Go-скрейпера (2026), веб-страница подгружает ленту авторизованными XHR. Однако при верификации 2026-10-09 сам JSON-endpoint `https://www.tbank.ru/api/invest-gw/social/v1/post/instrument/SBER?limit=5&appName=invest&origin=web&platform=web` отвечал **без авторизации** (200, `payload.items`, `nextCursor`, `hasNext`). Это недокументированный интерфейс без гарантий; скрейпить его с токеном или сессией брокерского клиента рискованно для самого счёта. **Не рекомендуется как зависимость** [41][42][43].
7. **Позиционирование физлиц и юрлиц на срочном рынке (FUTOI) — лучший бесплатный количественный прокси сентимента.** Ежедневный CSV «Открытые позиции» на moex.com отдаёт данные за T-1 бесплатно. ISS-эндпоинт `/iss/analyticalproducts/futoi` бесплатно отдаёт данные только с задержкой 14 дней [31][32]. Дополнительно доступны индекс волатильности RVI (аналог «индекса страха») [33] и ежемесячные данные ЦБ (ОРФР) и Мосбиржи о потоках розничных инвесторов [24][29].
8. **Агрегаторы (GDELT, NewsAPI) для российского рынка почти бесполезны.** У GDELT DOC API лимит 1 запрос в 5 секунд, а тестовые запросы по русским источникам вернули 0 статей. Бесплатный план NewsAPI запрещён для продакшена, Business стоит $449 в месяц, оплата из РФ проблематична [72][74].
9. **Сетевая топология определяется источниками данных.** С зарубежных IP часть российских сайтов недоступна, причём набор **зависит от конкретного IP/провайдера и меняется**: с NL-IP не отвечали РБК, Коммерсантъ, РИА, ПРАЙМ, e-disclosure, Яндекс, Альфа; при повторной проверке в тот же день с GB-IP РИА, ПРАЙМ, Коммерсантъ, Яндекс, tbank.ru и sberbank.com отвечали, зато не отвечали smart-lab.ru, moex.com, iss.moex.com и finmarket.ru; РБК (401/таймаут) и e-disclosure (403) были недоступны в обоих случаях. «Недоступность» tbank.ru и sberbank.com с NL была, вероятно, TLS-ошибкой, а не геоблоком. Из РФ, в свою очередь, ограничен Telegram. API T-Invest (и сайты T-Bank и Сбера) используют сертификат с цепочкой **Russian Trusted Root CA (Минцифры)**, которого нет в стандартных trust store (проверено) [59].
10. **Рекомендуемый микс для однопользовательского бота** — 3 уровня (детали в разделе «Выводы»):
    - P0: T-Invest API, MOEX, ЦБ, 6–8 RSS СМИ, раскрытие через Smart-lab RSS.
    - P1: Smart-lab форум и теги по тикерам портфеля, 15–20 Telegram-каналов как сигнал «внимания», FUTOI CSV, RVI.
    - P2 (опционально, платно): e-disclosure API или рассылка, Smart-lab Premium, Cbonds.

#### 1.2. Лицензионные условия СМИ

- **Интерфакс** разрешает воспроизведение без согласия только для личных целей, а цитирование — в ограниченных случаях с обязательной гиперссылкой. Распространение материалов в прессе и эфире, в том числе через RSS, запрещено. Любое иное использование требует договора [2]. Об автоматической обработке и ИИ условия прямо ничего не говорят.
- Для однопользовательского бота безопасная модель такая: хранить заголовок, лид, ссылку и *собственное* резюме или оценку (LLM-summary + score); полные тексты в Telegram-бот не пересылать; в выдаче всегда давать ссылку на первоисточник. Это укладывается в «личное использование» и цитирование с указанием источника (ст. 1273–1274 ГК РФ). Юридическую оценку для конкретного случая стоит подтвердить у юриста.
- Frank Media отдаёт полный текст в RSS. Это удобно для NLP, но и здесь в боте стоит показывать только краткое резюме.

#### 1.3. Сетевой фактор: геоблокировки и блокировка Telegram

Наблюдения 2026-10-09 (IP в Нидерландах):

- **Доступны:** interfax.ru, tass.ru, vedomosti.ru, frankmedia.ru, thebell.io, finam.ru, smart-lab.ru, finmarket.ru, forbes.ru, lenta.ru, cbr.ru, moex.com, iss.moex.com (с перебоями: один из поздних запросов ушёл в таймаут), max.ru, cbonds.ru, disclosure.1prime.ru, t.me.
- **Недоступны:** rbc.ru (все поддомены), kommersant.ru, ria.ru, 1prime.ru, banki.ru, e-disclosure.ru (403 или ECONNREFUSED), tbank.ru (в т.ч. developer.tbank.ru и неофициальный API Пульса), домены Яндекса (yandex.ru, yandex.cloud, wordstat), sberbank.com, alfabank.ru, scan-interfax.ru, mlg.ru.
- По публикациям 2026 года число российских сервисов с гео-ограничением зарубежного трафика растёт [59].
- **Повторная проверка 2026-10-09 с GB-IP дала другую картину:** отвечали ria.ru, 1prime.ru, kommersant.ru (RSS), yandex.ru, tbank.ru, developer.tbank.ru и sberbank.com (последние три — только с корнем НУЦ Минцифры, без него curl падает с `self signed certificate in certificate chain`, что легко принять за «недоступность»); **не отвечали** smart-lab.ru, moex.com, iss.moex.com, finmarket.ru, alfabank.ru; rbc.ru — 401, e-disclosure.ru — 403. Вывод: геоблок зависит от конкретного IP/ASN и меняется во времени, поэтому **все** российские источники (включая MOEX и Smart-lab) надёжнее опрашивать через RU-egress.

**Обратная проблема — Telegram в РФ:**
- 10.02.2026 РКН официально начал замедлять Telegram по всей стране [57].
- К апрелю 2026 OONI фиксировал до 95% аномалий, то есть фактическую блокировку. По словам Дурова, около 65 млн пользователей из РФ заходят через VPN [56].
- Ограничения начались ещё в августе 2025 г. (блокировка звонков). На 09.10.2026 пользователи продолжают массово сообщать о сбоях (Downdetector, «Сбой.РФ»); отдельные публикации о том, что Telegram «заработал» на части устройств, есть, но статус неоднозначен [58].

**Следствие для архитектуры:**
- Коллекторам российских СМИ и раскрытия, а также клиенту T-Invest API нужен **российский IP**.
- Коллектору Telegram и самому боту на Bot API нужен **не-российский** выход (или прокси).
- Это классический split-egress (см. «Выводы»).

**TLS-нюанс (проверено):** сервер `invest-public-api.tbank.ru` отдаёт цепочку `*.tbank.ru → Russian Trusted Sub CA → Russian Trusted Root CA` (Минцифры). Стандартный trust store (macOS/curl, обычные Docker-образы) её не принимает: ошибка `self signed certificate in certificate chain`. В контейнер нужно явно добавить корневой сертификат НУЦ Минцифры. Отключать проверку TLS нельзя. Похожий риск есть и у MOEX: официальная библиотека `moexalgo` с 26.08.2026 (коммит «Add bundled Russian certificate», версия 2.5.x) добавляет к стандартным корням Russian Trusted Root CA для запросов к `iss.moex.com`/`apim.moex.com`. Цепочку MOEX в ходе верификации проверить не удалось (хост недоступен с GB-IP), но trust store коллекторов стоит сразу собирать с этим корнем.

### 2. Официальные раскрытия и регуляторы

#### 2.1. Мосбиржа: ISS и RSS (бесплатно, без авторизации)

Справочник ISS прямо перечисляет методы новостей и событий [28]:

| Метод ISS | Что отдаёт | Проверка 2026-10-09 |
|---|---|---|
| `/iss/sitenews.json` (ID 231) | Лента новостей биржи: `id, tag, title, published_at, modified_at` | 200. Свежие записи: итоги выпуска облигаций, изменения ценовых коридоров, начало торгов БПИФ, статистика по частным инвесторам [29] |
| `/iss/sitenews/{id}.json` (ID 229) | Полный текст (`body`, HTML) | 200 |
| `/iss/events.json` (ID 553) | События (календарь) | 200, но список пуст |
| `/iss/events/{id}.json` (ID 555) | Содержимое события | — |
| RSS-экспорт `https://www.moex.com/export/news.aspx?cat=100` | Новости с полным текстом | 200: 903 элемента (~38 дней), объём ~5 МБ [30] |

Ценность для сентимента:
- **Прямая:** листинг и делистинг, включение в индексы, начало торгов фондами, изменения ценовых коридоров (индикатор резких движений), ежемесячная статистика частных инвесторов. Пример от 09.10.2026: «Частные инвесторы втрое увеличили вложения в ПИФы…».
- **Косвенная:** с 10.02.2026 действует Указание ЦБ от 24.09.2025 № 7183-У (изменения в Положение № 534-П «О допуске ценных бумаг к организованным торгам»; разъяснено информационным письмом ЦБ от 20.02.2026 № ИН-02-28/5). Организаторы торговли обязаны **маркировать** бумаги эмитентов, ограничивающих раскрытие сверх допустимого постановлениями Правительства № 1102 (от 04.07.2023) и № 1173 (от 07.09.2019, для кредитных организаций). Маркировка **не ставится**, если у бумаги/эмитента/поручителя есть рейтинги не менее чем от двух КРА не ниже уровня правил листинга (по сообщениям СМИ: для облигаций — не ниже A-, для акций — некредитный рейтинг не ниже «***»). Мосбиржа начала маркировку по новым правилам листинга с 01.04.2026; для эмитентов из перечня с правом самостоятельно определять объём раскрытия действовало временное исключение до 01.10.2026, после чего в начале октября 2026 были промаркированы, в частности, акции Совкомфлота, Сургутнефтегаза, Башнефти, НМТП [68][70]. Признак маркировки — важный риск-флаг для фильтра «можно ли вообще анализировать эмитента».

### 3. Брокерская аналитика и консенсусы

#### 3.1. T-Invest API (основной программный источник)

Из `instruments.proto` (репозиторий RussianInvestments/investAPI, последний коммит «Release 1.43» от 07.11.2025; в разделе GitHub Releases последний оформленный релиз — v1.27 от 18.12.2024) [35] и `signals.proto` [36]:

| Метод | Назначение | Ключевые поля |
|---|---|---|
| `InstrumentsService.GetForecastBy(instrument_id)` | Прогнозы инвестдомов по бумаге | `targets[]`: `company`, `recommendation` (BUY/HOLD/SELL), `recommendation_date`, `target_price`, `price_change_rel`. `consensus`: `consensus` (цель), `min_target`, `max_target`, `recommendation` |
| `InstrumentsService.GetConsensusForecasts(paging)` | Консенсус по **всем** бумагам постранично | `best_target_price`, `best_target_low/high`, `total_buy/hold/sell_recommend`, `consensus` (здесь это enum-рекомендация BUY/HOLD/SELL, а не цена), `prognosis_date` |
| `SignalService.GetStrategies / GetSignals` | Идеи: фундаментальные (аналитики) и технические (бэктест) | `strategy_type` (TECHNICAL/FUNDAMENTAL), `direction`, `initial_price`, `target_price`, `stoploss`, `probability`, `end_dt`, `info` |
| `InstrumentsService.GetInsiderDeals` | Сделки инсайдеров | `direction` (BUY/SELL/INCREASE/DECREASE), `investor_position`, `percentage`, `disclosure_date` |
| `InstrumentsService.GetAssetReports` | График отчётности | `report_date`, `period_type` |
| `InstrumentsService.GetAssetFundamentals` | Мультипликаторы и дивидендные метрики | (см. отчёт 01) |

- Документация сервиса сигналов говорит, что сигналы также показываются в терминале, Пульсе и приложении. Документация подчёркивает, что сигналы не являются индивидуальной инвестиционной рекомендацией [37].
- REST-эквивалент: `POST https://invest-public-api.tbank.ru/rest/tinkoff.public.invest.api.contract.v1.InstrumentsService/GetForecastBy` (из `openapi.yaml`) [39].
- Лимит: 200 unary-запросов в минуту на сервис инструментов (лимит считается суммарно по всем методам сервиса). Суммарно по всем счетам и токенам с одного адреса T-Bank **рекомендует** не превышать 50 запросов в секунду; бана IP не будет, пока запросов с IP не больше 1000 в минуту [38]. Отдельного лимита для `SignalService` в таблице limits.md нет. Для портфеля из 20–40 бумаг ежедневный опрос `GetForecastBy` занимает доли лимита.
- Пример использования на практике: скрипт по 89 акциям, собирающий консенсус через `GetForecastBy` [40].
- Важно: официальный Python SDK на GitHub (`RussianInvestments/invest-python`) **архивирован** (09.10.2025), а пакет `tinkoff-investments` на PyPI не находится [81]. Подробности — в отчёте 01 по T-Invest API.

**Сентимент-фичи из консенсуса:**
- `upside = consensus/current_price − 1`;
- `buy_share = buy/(buy+hold+sell)`;
- **изменения** этих величин за неделю (ревизии таргетов и рекомендаций). На практике ревизии информативнее уровня;
- дисперсия таргетов `(max−min)/consensus` как мера неопределённости.

**Ограничения по Условиям Telegram (критично):**
- API ToS, п. 1.5: запрещено использовать, получать или агрегировать данные платформы для обучения, дообучения или иного развития, улучшения либо **развёртывания** AI/ML-моделей [47].
- «Terms of Service for Content Licensing»: доступ к пользовательскому контенту для целей, отличных от обычного использования, запрещён. Отдельно и прямо запрещены **скрейпинг, индексация, сбор и агрегация** данных платформы для AI/ML, включая deployment и benchmarking. Исключение возможно только при явном информированном согласии всех соответствующих пользователей [48].
- Буквально это делает **LLM-анализ сентимента постов Telegram-каналов нарушением условий Telegram**, независимо от способа сбора (MTProto или веб-превью). Оговорка: слово «инференс» в условиях не используется; вывод опирается на широкую формулировку «use of data … to engage in … deployment of AI/ML» и на запрет «aggregation», то есть это толкование, а не прямой текст. Однако API ToS п. 1.5 прямо отсылает к «Terms of Service for Content Licensing and AI Scraping», так что консервативное прочтение оправдано. Практический риск для одного пользователя невелик, но он есть: бан аккаунта, отзыв `api_id`. Это нужно явно зафиксировать в архитектурных решениях.
- **Компромиссный дизайн (рекомендация):** использовать Telegram только для *неML* метрик — частоты упоминаний тикеров по словарю, всплесков внимания, скорости распространения, просмотров. Содержательный NLP и LLM-анализ выполнять по **первоисточникам** (RSS СМИ, раскрытие, ЦБ, MOEX), на которые такой всплеск указывает. Если пользователь сознательно решит анализировать тексты каналов LLM-ом, это должно быть отдельным, явно включаемым флагом.

**Миграция в MAX:** MarketTwits указывает зеркальный канал в MAX (`max.ru/markettwits`, страница доступна) [61]. Платформа MAX для партнёров (боты, каналы) доступна только **резидентам РФ — юрлицам, ИП и самозанятым** [60]. Публичного API для чтения чужих каналов MAX в ходе исследования не обнаружено. Если блокировка Telegram усилится, часть каналов может «переехать» в MAX, где программный сбор пока неочевиден. Это открытый риск.

### 5. «Пульс» Т-Инвестиций

- **Официального API нет.** В proto-контрактах T-Invest API (instruments, marketdata, operations, orders, sandbox, signals, stoporders, users) нет методов для постов Пульса [35][36]. Неофициальность подтверждают и разборы сообщества [44].
- **Неофициальный endpoint:** `https://www.tinkoff.ru/api/invest-gw/social/v1/` с путями `post/instrument/{ticker}`, `profile/nickname/{name}`, `profile/{id}/post`, параметрами `limit=30`, `cursor`, `appName=invest&origin=web&platform=web`. Его использует библиотека `tpulse` (последний релиз 0.1.9 от 06.01.2023) [41][42]. С NL-IP проверить не удалось (TLS-ошибка из-за цепочки НУЦ Минцифры). **Верификация с GB-IP 2026-10-09:** `GET https://www.tbank.ru/api/invest-gw/social/v1/post/instrument/SBER?limit=5&appName=invest&origin=web&platform=web` без cookie и токена вернул 200 и JSON `{status: "Ok", payload: {items, nextCursor, hasNext}}` со свежими постами (тикеры в тексте вида `{$SBER}`); тот же ответ на `www.tinkoff.ru`.
- Go-проект `tbank-pulse-auto` (опубликован в июне 2026) сообщает, что веб-страница подгружает ленту **авторизованными XHR** после гидратации и что голый HTTP-запрос к странице получает только счётчики профиля [43]. Это относится к HTML-странице; JSON-endpoint выше на дату верификации отвечал без авторизации, но он недокументирован и может быть закрыт в любой момент.
- **Привязка к тикерам** в самом Пульсе есть: посты из карточки бумаги автоматически получают тикер, в тексте используется `$TICKER` [45]. В веб-карточке бумаги есть вкладки «Пульс», «Новости», «Идеи» [83].
- **Виджет «настроение по бумаге»** (доля позитивных и негативных постов) в открытых источниках **не подтверждён**.
- Рыночный индекс **Tinkoff InvestIndex** (2021) строился по обезличенным данным более 1 млн пользователей Пульса по шкале 0–100 [46]. Актуальность публикации в 2025–2026 не подтверждена.

**Рекомендация:** не строить критичную зависимость от Пульса. Скрейпинг с использованием сессии или токена брокерского клиента — прямой риск для самого брокерского счёта и вероятное нарушение условий брокера. Если сигнал Пульса нужен, допустим только опциональный P2-коллектор по анонимному JSON-endpoint (после проверки пользовательских условий T-Bank; без сессии, с низкой частотой, с feature-flag и health-check на случай закрытия), либо ручной просмотр пользователем, либо (при появлении) официальный способ.

### 10. Источники по ЦФА (цифровые финансовые активы)

У ЦФА нет биржевого стакана, а вторичная ликвидность низкая. Поэтому «сентимент» здесь — это прежде всего **кредитные и регуляторные новости** об эмитенте и операторе (ОИС):

- **ЦБ (RSS eventrss и RssPress):** реестр ОИС, решения по операторам. Пример: 08.10.2026 НАУФОР стала первой СРО операторов ИС, 25 ОИС должны вступить в СРО за 180 дней [27]. Frank Media 09.10.2026 сообщила об исключении НРД из реестра операторов выпусков ЦФА по его ходатайству [6].
- **Frank Media** — регулярная тема ЦФА; RSS с полным текстом [6].
- **Раскрытие по ЦФА:** с октября 2026 расширены требования к раскрытию условий выпуска [71]. Где именно раскрываются решения о выпуске, зависит от ОИС: сайты операторов, а не e-disclosure.
- **Telegram-каналы операторов:** например, `@tokeon_ru` («ТОКЕОН — Платформа цифровых активов», ~2K). Тематических агрегаторов ЦФА с заметной аудиторией по угаданным handle найти не удалось. Это открытый вопрос, нужен ручной подбор.
- **Кредитный фон эмитента ЦФА** (часто это МСБ или компании без облигаций): рейтинговые агентства (`@expert_ra`), новости по ИНН. Платные СПАРК и Контур.Фокус здесь были бы особенно полезны, но это B2B.

### 11. Обработка: от сырого потока к сентимент-фичам (кратко)

Подробно NLP разобран в отчёте 04 (`04-nlp-sentiment.md`); здесь только то, что следует из свойств источников.

1. **Entity linking к инструментам.** Мастер-справочник — инструменты T-Invest (`ticker`, `isin`, `figi`, `uid`, `asset_uid`, `name`) плюс словарь алиасов: «Сбер», «Сбербанк», `$SBER`, «Газпромнефть», «ГПН», ИНН эмитента для раскрытий. В Smart-lab per-ticker RSS тикер задаётся URL, в постах Пульса — тегом `$TICKER`.
2. **Дедупликация между источниками.** URL-канонизация, затем near-duplicate по MinHash или SimHash заголовка с лидом. Кластер «одна новость» хранит первый источник, время первой публикации и число повторов (это мера «вирусности»).
3. **Классификация событий:** дивиденды, отчётность, СД/ГОСА, байбэк, M&A, санкции, регуляторика, ставка ЦБ, рейтинговые действия, оферта/дефолт/техдефолт (облигации), ЦФА-события.
4. **Тональность и релевантность.** Предфильтр по entity и словарям, затем LLM со структурированным выводом. Для дешёвого предскоринга годятся общедоменные русские модели тональности `blanchefort/rubert-base-cased-sentiment`, `seara/rubert-tiny2-russian-sentiment` (MIT), `cointegrated/rubert-tiny-sentiment-balanced` [76][77][78]. Они **не финансовые**, их точность на финтекстах нужно валидировать.
5. **Агрегация по дню и бумаге** с весами источников и экспоненциальным затуханием; внимание (число уникальных кластеров) в виде z-score относительно 60–90 дней истории бумаги.

Оценка объёма: RSS P0+P1 дают примерно 1 500–3 000 элементов в сутки (ТАСС и Lenta — основной «шум»), Telegram ещё 800–1 500 постов. После фильтра по сущностям портфеля и вотчлиста (≈50 тикеров) и дедупликации на LLM-разметку уходит порядка **100–400 кластеров в сутки**. Это порядок, а не измерение; уточнить на реальном потоке.

#### 12.1. Инкрементальный RSS-коллектор (conditional GET, кодировки, дедуп)

```python
# pip install httpx feedparser   (feedparser 6.0.14, 07.2026)
import hashlib, httpx, feedparser, datetime as dt

FEEDS = {
    "interfax":      ("https://www.interfax.ru/rss", 600),            # сек между опросами
    "tass":          ("https://tass.ru/rss/v2.xml", 600),
    "vedomosti_inv": ("https://www.vedomosti.ru/rss/rubric/investments", 3600),
    "frank":         ("https://frankmedia.ru/feed", 1800),
    "finam_conews":  ("https://www.finam.ru/analysis/conews/rsspoint/", 1800),
    "smartlab_news": ("https://smart-lab.ru/news/rss/", 900),
    "smartlab_disc": ("https://smart-lab.ru/disclosure/rss/", 1800),
    "cbr_press":     ("https://www.cbr.ru/rss/RssPress", 1800),
    "cbr_events":    ("https://www.cbr.ru/rss/eventrss", 1800),
    "finmarket":     ("https://www.finmarket.ru/rss/mainnews.asp", 3600),  # windows-1251
}

def item_key(entry) -> str:
    base = entry.get("id") or entry.get("link") or entry.get("title", "")
    return hashlib.sha256(base.strip().encode()).hexdigest()

async def poll(client: httpx.AsyncClient, name: str, url: str, state: dict, store):
    headers = {"User-Agent": "investbot/0.1 (+personal use)"}
    if et := state.get("etag"):          headers["If-None-Match"] = et
    if lm := state.get("last_modified"): headers["If-Modified-Since"] = lm
    r = await client.get(url, headers=headers, timeout=30)
    if r.status_code == 304:
        return 0
    r.raise_for_status()
    state["etag"], state["last_modified"] = r.headers.get("etag"), r.headers.get("last-modified")
    feed = feedparser.parse(r.content)            # feedparser сам разбирает encoding из XML-пролога
    new = 0
    for e in feed.entries:
        k = item_key(e)
        if store.exists(k):
            continue
        store.insert(
            key=k, source=name, title=e.get("title"), link=e.get("link"),
            summary=e.get("summary"),
            content=(e.get("content") or [{}])[0].get("value"),   # Frank Media отдаёт content:encoded
            category=[t.get("term") for t in e.get("tags", [])],
            published=e.get("published_parsed"), fetched_at=dt.datetime.utcnow(),
        )
        new += 1
    # мониторинг: если ВСЕ элементы новые, интервал опроса слишком велик и что-то потеряно
    if feed.entries and new == len(feed.entries) and state.get("seen_before"):
        store.alert(f"{name}: possible gap, shorten poll interval")
    state["seen_before"] = True
    return new
```

#### 12.2. Новости Мосбиржи через ISS (инкремент по `id`)

```python
import httpx

ISS = "https://iss.moex.com/iss"

def fetch_sitenews_since(last_id: int, page: int = 50) -> list[dict]:
    out, start = [], 0
    with httpx.Client(timeout=30) as c:
        while True:
            j = c.get(f"{ISS}/sitenews.json",
                      params={"iss.meta": "off", "start": start, "limit": page}).json()
            cols, rows = j["sitenews"]["columns"], j["sitenews"]["data"]
            batch = [dict(zip(cols, r)) for r in rows]
            fresh = [b for b in batch if b["id"] > last_id]
            out += fresh
            if len(fresh) < len(batch) or not batch:
                break
            start += page
        for item in out:   # полный текст отдельным запросом: columns = id, title, published_at, body
            body = c.get(f"{ISS}/sitenews/{item['id']}.json", params={"iss.meta": "off"}).json()
            item["body_html"] = body["content"]["data"][0][3]
    return out
```

Пагинация `start/limit` — стандартный механизм ISS; конкретный предел `limit` для sitenews стоит уточнить. Технические сообщения о ценовых коридорах фильтруются регуляркой `изменены значения (верхней|нижней) границы ценового коридора`.

#### 12.3. Консенсус и прогнозы из T-Invest API (REST)

```python
import httpx

BASE = "https://invest-public-api.tbank.ru/rest/tinkoff.public.invest.api.contract.v1"
# ВАЖНО: цепочка сертификата — Russian Trusted Root CA (Минцифры).
# Передайте путь к bundle, включающему этот корень (не отключайте verify!).
CA_BUNDLE = "/etc/ssl/certs/ca-bundle-with-russian-trusted-root.pem"

def forecast_by(token: str, instrument_uid: str) -> dict:
    r = httpx.post(f"{BASE}.InstrumentsService/GetForecastBy",
                   headers={"Authorization": f"Bearer {token}"},
                   json={"instrumentId": instrument_uid},
                   verify=CA_BUNDLE, timeout=30)
    r.raise_for_status()
    return r.json()   # {"targets":[...], "consensus":{...}}

def consensus_features(resp: dict) -> dict:
    q = lambda v: (int(v.get("units", 0)) + v.get("nano", 0) / 1e9) if v else None   # Quotation
    c = resp.get("consensus", {})
    cur, tgt = q(c.get("currentPrice")), q(c.get("consensus"))
    lo, hi = q(c.get("minTarget")), q(c.get("maxTarget"))
    recs = [t.get("recommendation") for t in resp.get("targets", [])]
    n = len(recs) or 1
    return {
        "upside": (tgt / cur - 1) if cur and tgt else None,
        "dispersion": ((hi - lo) / tgt) if tgt and hi and lo else None,
        "buy_share": recs.count("RECOMMENDATION_BUY") / n,
        "sell_share": recs.count("RECOMMENDATION_SELL") / n,
        "n_analysts": len(recs),
    }
```

Имена JSON-полей в REST-шлюзе (camelCase против snake_case) нужно сверить с `openapi.yaml` [39]. Здесь они даны в предположении стандартного gRPC-gateway маппинга.

#### 12.4. FUTOI: нетто-позиция физлиц из ежедневного CSV

```python
import io, httpx, pandas as pd, datetime as dt

def open_positions(day: dt.date) -> pd.DataFrame:
    url = "https://www.moex.com/ru/derivatives/open-positions-csv.aspx"
    r = httpx.get(url, params={"d": day.strftime("%Y%m%d"), "t": 1},
                  headers={"User-Agent": "Mozilla/5.0"}, timeout=30)
    df = pd.read_csv(io.StringIO(r.content.decode("utf-8-sig")))
    df = df[df["contract_type"] == "F"]                       # только фьючерсы
    df["group"] = df["iz_fiz"].fillna(0).astype(int).map({1: "FIZ", 0: "YUR"})
    piv = df.pivot_table(index="isin", columns="group",
                         values=["long_position", "short_position"], aggfunc="sum")
    out = pd.DataFrame({
        "fiz_net": piv[("long_position", "FIZ")] - piv[("short_position", "FIZ")],
        "fiz_long_share": piv[("long_position", "FIZ")] /
                          (piv[("long_position", "FIZ")] + piv[("short_position", "FIZ")]),
    })
    out["date"] = day
    return out   # isin = код базового актива (SBRF, GAZR, SBPR, MIX, Si ...)

# Сигнал: z-score fiz_long_share за 60 торговых дней; |z|>2 — экстремум позиционирования розницы.
```

В CSV колонка `isin` содержит **код базового актива** (например `SBPR`, `HYDR`, `TATN`), а не ISIN. Нужна таблица соответствия «код БА → тикер акции». Имена колонок перед реализацией сверить с фактическим файлом (при верификации 2026-10-09 moex.com был недоступен с GB-IP) и, если MOEX перешёл на сертификаты НУЦ Минцифры (см. п. 1.3), передавать в `httpx` CA-bundle с этим корнем.

import re, html, httpx
from datetime import datetime

def fetch_channel(handle: str, before: int | None = None) -> list[dict]:
    url = f"https://t.me/s/{handle}" + (f"?before={before}" if before else "")
    t = httpx.get(url, headers={"User-Agent": "Mozilla/5.0"}, timeout=30).text
    out = []
    # каждый пост начинается с атрибута data-post="<channel>/<id>"
    for chunk in t.split('data-post="')[1:]:
        ch_id = chunk.split('"', 1)[0]                       # "markettwits/388175"
        ch, _, mid = ch_id.partition("/")
        ts = re.search(r'<time datetime="([^"]+)"', chunk)
        txt = re.search(r'tgme_widget_message_text[^>]*>(.*?)</div>', chunk, re.S)
        views = re.search(r'tgme_widget_message_views">([^<]+)<', chunk)
        out.append({
            "channel": ch, "msg_id": int(mid),
            "ts": datetime.fromisoformat(ts.group(1)) if ts else None,
            "text": html.unescape(re.sub(r"<[^>]+>", " ", txt.group(1))).strip() if txt else "",
            "views": views.group(1) if views else None,        # "12.3K" — нормализовать отдельно
        })
    return out
# Пагинация вглубь: before=<минимальный msg_id из предыдущей страницы>.

from telethon import TelegramClient, errors
import asyncio

async def pull(client: TelegramClient, channel: str, min_id: int):
    msgs = []
    try:
        async for m in client.iter_messages(channel, min_id=min_id, reverse=True, limit=500):
            msgs.append((m.id, m.date, m.message, m.views, m.forwards))
    except errors.FloodWaitError as e:      # ждать ровно столько, сколько сказал сервер
        await asyncio.sleep(e.seconds + 5)
    return msgs

### B. Компоненты (data plane)

```
            ┌──────────────── RU egress (VPS в РФ) ────────────────┐
            │ rss-collector (СМИ РФ, ЦБ, Smart-lab)                │
            │ iss-collector (sitenews, FUTOI CSV, RVI)             │
            │ tinvest-collector (consensus, signals, insider, ...) │  ← Russian Trusted Root CA в trust store
            └───────────────┬──────────────────────────────────────┘
                            │ raw_item (Postgres) / очередь
            ┌───────────────▼──────────────────────────────────────┐
            │ normalizer: дедуп (URL + MinHash) → story_cluster     │
            │ entity-linker (справочник T-Invest + алиасы + ИНН)   │
            │ event-classifier → LLM-annotator (tos_ml_allowed!)   │
            │ aggregator → daily_signal (на бумагу/день)           │
            └───────────────┬──────────────────────────────────────┘
                            │
            ┌───────────────▼─────── foreign egress ───────────────┐
            │ tg-collector (t.me/s или RSSHub; только счётчики)    │
            │ telegram-bot (Bot API): дайджесты, алерты, отчёты    │
            └──────────────────────────────────────────────────────┘
```

- **Split-egress** обязателен: либо два хоста (RU-VPS и зарубежный), либо один хост с прокси в нужную сторону. Каждому источнику в реестре `source.egress` назначается сетевой выход.
- **Реестр источников с health-check:** для каждой ленты хранятся `last_ok` и доля новых элементов за опрос. Если все элементы новые, лента «пробита» и интервал нужно уменьшить. Если 0 элементов N раз подряд, лента сломалась (так было 2026-10-09 с общей лентой Ведомостей в одном из запросов).
- **Архив с первого дня.** RSS не даёт истории: глубина Интерфакса — 1,4 часа. Для будущего бэктеста и RL нужен собственный архив, пусть даже только заголовков и метаданных.
- **Два класса текстов.** Тексты с разрешённой ML-обработкой (СМИ, ЦБ, MOEX, Smart-lab — с учётом их условий) и тексты только для метрик (Telegram). Флаг `tos_ml_allowed` проверяется в LLM-аннотаторе.

### C. Сигналы для недельного ребаланса и RL

На каждую бумагу и неделю (агрегаты из `daily_signal`):

- `news_tone_7d` — взвешенный тон кластеров, где вес = вес источника × релевантность × новизна;
- `news_attention_z` — число уникальных кластеров относительно 90-дневной истории;
- `forum_tone_z` (Smart-lab) и `tg_mentions_z` (Telegram, без NLP);
- `consensus_upside`, `consensus_revision_7d`, `buy_share_change`, `dispersion`;
- `insider_net_30d`;
- `fiz_long_share_z` (для бумаг с фьючерсами), `RVI_level/change`;
- флаги событий: дивгэп, отсечка, отчётность на следующей неделе, оферта, заседание ЦБ, маркировка «неполное раскрытие», техдефолт.

Для RL эти признаки входят в state. Обязательны строгая point-in-time-дисциплина (время `fetched_at`, а не `published_at`, для лаговых источников вроде Smart-lab раскрытия и FUTOI-ISS) и учёт того, что первые месяцы архива будут короткими.

### D. Алерты (между недельными отчётами)

Критические триггеры, требующие немедленного сообщения в бот:
- существенный факт по бумаге из портфеля (дивиденды, СД, оферта, дефолт);
- решение ЦБ по ставке;
- маркировка или делистинг на MOEX;
- всплеск `news_attention_z > 3` или `tg_mentions_z > 3` с отрицательным тоном первоисточника;
- рейтинговое действие по эмитенту облигаций или ЦФА.

## Риски и подводные камни

1. **Юридический риск по Telegram.** API ToS п. 1.5 и Content Licensing Terms запрещают скрейпинг и агрегацию для AI/ML, включая deployment [47][48]. Нарушение может привести к бану аккаунта или отзыву `api_id`. Митигирование: Telegram только как счётчики внимания, LLM только по первоисточникам, отдельный технический номер, без массовых join.
2. **Блокировка Telegram в РФ** (замедление с 10.02.2026, сильная блокировка к апрелю) [56][57][58]. Это бьёт и по сбору каналов, и по самому интерфейсу бота. Нужен зарубежный хост или прокси; стоит предусмотреть запасной UI (веб-страница или MAX, где для ботов требуется резидентство РФ и статус юрлица, ИП или самозанятого [60]).
3. **Гео-блокировка российских сайтов для зарубежных IP:** набор заблокированных сайтов зависит от конкретного зарубежного IP и меняется (2026-10-09 с NL-IP не отвечали РБК, Коммерсантъ, РИА, ПРАЙМ, e-disclosure, Яндекс, Альфа; с GB-IP — РБК, e-disclosure, Smart-lab, MOEX, Финмаркет, Альфа). Без RU-egress часть P0 недоступна, включая потенциально MOEX и Smart-lab.
4. **Сертификаты НУЦ Минцифры** для `invest-public-api.tbank.ru`. Без них TLS-ошибка; соблазн выключить `verify` создаёт угрозу безопасности токена.
5. **Короткая глубина RSS** (Интерфакс ~1,4–1,6 ч, ТАСС ~1 ч, РИА ~1,75 ч). Простой коллектора на пару часов означает потерю новостей из RSS (частично восполнимую только парсингом HTML-архивов по датам, например `interfax.ru/news/YYYY/MM/DD/`, с учётом лицензии). Нужны мониторинг «пробития» и, по возможности, резервный путь: Telegram-каналы тех же СМИ (`@interfaxonline`, `@prime1`) как источник ссылок.
6. **Лаг и неполнота раскрытия.** Бесплатное зеркало Smart-lab отстаёт примерно на 1,5–2 суток. Постановление 1102 позволяет части эмитентов раскрывать меньше [69]. Агент должен явно учитывать «информационную тень» (маркировку MOEX [68][70]).
7. **Эхо-камера и дубли.** MarketTwits, headlines, Smart-lab, Интерфакс-TG пересказывают одно и то же. Без кластеризации один факт засчитывается 5–10 раз, и тон с вниманием искажаются.
8. **Манипуляции и pump-каналы.** ЦБ регулярно выявляет манипулирование; пример — пресс-релиз от 08.10.2026 о группе аффилированных организаций [22]. Соцсигналы по малоликвидным бумагам и ВДО нужно брать с пониженным весом, а для 3-го эшелона — с порогом ликвидности.
9. **Нестабильность лент.** URL меняются, встречаются анти-бот-заглушки (БКС), пустые ответы (Ведомости в одном из запросов), кодировка windows-1251 (Финмаркет), CDATA в ссылках (ТАСС). Нужны устойчивый парсер (feedparser) и health-check.
10. **Пульс.** Нет официального API; неофициальные эндпоинты недокументированы и могут измениться. На 2026-10-09 JSON-endpoint `invest-gw/social/v1/post/instrument/{ticker}` отвечал без авторизации, хотя HTML-страница, по данным [43], грузит ленту авторизованными XHR. Использование брокерской сессии для скрейпинга ставит под риск сам брокерский счёт.
11. **Модели тональности.** Готовые русские модели общедоменные [76][77][78]. Финансовая лексика («снижение ставки», «байбэк», «дивгэп», «оферта») требует LLM или дообучения и валидации на размеченной выборке.
12. **Лицензии СМИ.** Интерфакс запрещает перераспространение без договора [2]. Бот не должен ретранслировать полные тексты; хранить и показывать надо резюме со ссылкой.
13. **Задержка FUTOI в ISS.** Бесплатный ISS-доступ отстаёт на 14 дней [31]. Для текущего сигнала используется CSV T-1 [32], для истории ISS. Нельзя смешивать их без учёта момента доступности.
14. **Зависимость от архивированных SDK.** `RussianInvestments/invest-python` архивирован, пакета на PyPI нет [81]. Разумно генерировать клиент из proto или обращаться к REST напрямую.

## Открытые вопросы

1. **Где хостить?** Один RU-VPS с прокси наружу для Telegram или зарубежный хост с RU-прокси? Это зависит от того, где будет жить сам бот (Telegram ограничен в РФ) и от требований безопасности токена T-Invest.
2. **Готов ли пользователь к «серой зоне» Telegram ToS** (LLM-анализ текстов каналов)? Или ограничиваемся метриками внимания, как рекомендовано?
3. **Бюджет на платное раскрытие:** e-disclosure API или рассылка, либо Smart-lab Premium. Нужно запросить цены (dc1@e-disclosure.ru) и проверить, действительно ли Premium снимает лаг.
4. **Актуальные адреса RSS РБК и Банки.ру** — проверить из российской сети; проверить, отдаёт ли РБК полный текст. (RSS Коммерсанта, РИА и ПРАЙМ подтверждены при верификации 2026-10-09 с GB-IP.)
5. **Wordstat API в Yandex Cloud:** проверить существование, методы и тарифы (в этом исследовании не проверено).
6. **GDELT:** реальное покрытие русскоязычных деловых СМИ — проверить с неразделяемого IP (ответы 0 статей могли объясняться лимитами).

10. **Политика хранения:** сколько хранить сырые тексты (место и лицензии) и что достаточно для RL (заголовки, метаданные, аннотации).
