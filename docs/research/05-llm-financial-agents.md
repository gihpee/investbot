# Архитектуры LLM-агентов для финансового анализа и трейдинга (state of the art)

> Дата исследования: 2026-10-09
>
> Контекст: исследование для проекта персонального агента-аналитика по российскому рынку (акции, облигации, фонды, ЦФА; данные из Т-Инвестиций; Telegram-бот; агент только рекомендует, сделки не совершает; еженедельная перебалансировка + идеи для входа; возможно RL).
>
> Оговорка: документ описывает устройство систем и методологию. Он не содержит рекомендаций по конкретным ценным бумагам. Все цифры доходности из статей являются результатами бэктестов или коротких live-тестов, которые авторы получили сами, если не указано иное.
>
> Ограничение по ходу работы: лимит веб-поиска в этой сессии исчерпан ближе к концу исследования. Несколько фактов (Alpha Arena Season 1.5, точные цифры «Финам Арены», полный список инструментов официального MCP Т-Инвестиций) остались непроверенными по первоисточнику. Такие места помечены. При последующей верификации (см. раздел «Верификация ключевых утверждений» в конце) технические детали официального MCP Т-Инвестиций уточнены по разбору команды T-Invest API на Хабре. Российские сайты (developer.tbank.ru, habr.com, rb.ru, vc.ru) были недоступны для прямого чтения из среды исследования, поэтому сведения о них взяты из поисковых выдач и вторичных публикаций.

## Резюме

1. **Доминирующий архитектурный шаблон 2024–2026 — «виртуальная инвестиционная фирма».** Параллельные аналитики (фундаментал, новости, сентимент, техника), затем дебаты bull/bear, трейдер или портфельный менеджер и риск-контур. Так устроены TradingAgents [1][2], FinCon [12], ai-hedge-fund [3][4], БПИФ «Первая — Фонд искусственный интеллект» [45]. Шаблон хорошо подходит для объяснимых рекомендаций. При этом нет доказательств, что именно дебаты дают альфу: обзор 2026 года прямо называет этот вопрос нерешённым и рекомендует абляции [33].

2. **Самые зрелые системы 2026 года прямо разделяют работу: «LLM рассуждает, код считает».** FinRobot формулирует это так: «models reason, software computes, agents orchestrate, systems verify», и в V2 все оценки (DCF, DDM, comps) считает кодом [5]. В ai-hedge-fund LLM формирует взгляды и тезисы, а размер позиций, ордера и риск-лимиты задаёт детерминированный код с жёсткими ограничениями [4]. FactFin использует LLM как генератор кода стратегии, а не как того, кто принимает решения [27]. Для нашего агента это главный архитектурный принцип.

3. **Опубликованные доходности LLM-агентов сильно завышены.** Profit Mirage (окт. 2025) переоценил FinMem, FinAgent, FinCon, QuantAgent и TradingAgents на данных после даты отсечки знаний модели. Sharpe упал на 51–62%, совокупная доходность на 50–72% [27]. FINSABER (KDD 2026) прогнал стратегии на 20 годах и более чем 100 акциях: buy-and-hold статистически значимо обыгрывает FinMem и FinAgent, значимой альфы у LLM-агентов нет [26]. KTD-Fin (май 2026) показал, что при маскировке тикеров и дат доходность агентов в основном объясняется рыночной бетой и стилевыми экспозициями [32].

4. **Живые бенчмарки дают скромную картину.** В StockBench (мар.–июн. 2025) результаты 13 моделей легли в диапазон от −2,8% до +2,5% при +0,4% у пассивного портфеля (лучшие +2–2,5%, бенчмарк обыграли 8 из 13), а в падающем окне никто не обыграл бенчмарк [34]. В LiveTradeBench (50 дней, 21 модель) корреляция между рейтингом LMArena и доходностью на акциях составила 0,054 [35]. В DeepFund даже топовые модели (DeepSeek-V3, Claude 3.7 Sonnet) ушли в минус в основном 24-дневном окне, хотя на полном Q2 2025 часть из них в итоге вышла в плюс [37]. В Agent Market Arena устройство фреймворка влияло на поведение сильнее, чем выбор модели [36]. На российском рынке: на тестовом этапе хакатона MOEX AI (промежуточные итоги на 01.06.2026) в плюсе оказались 5 команд из 50 [44]. В тесте «Финама» практически все популярные модели показали просадку по депозиту [44].

5. **Числа нельзя доверять LLM.** FinanceBench: GPT-4-Turbo с общим векторным индексом ответил неверно или отказался отвечать на 81% вопросов [40]. Vals Excel Modeling (июль 2026): лучшая модель проходит 87% проверок структуры формул, но только 61% проверок чисел (вторичный источник) [41]. StockBench фиксирует арифметические ошибки у instruct-моделей и ошибки формата JSON у reasoning-моделей [34]. Значит, все числа берутся только из инструментов, вывод строго структурирован, а цифры в тексте проверяет детерминированный валидатор.

6. **Память и рефлексия переходят от «векторной базы воспоминаний» к журналу решений с последующим расчётом исхода.** TradingAgents с v0.2.4 (апр. 2026; доработано в v0.4–0.6) записывает каждое решение в журнал. Когда горизонт истекает, система считает сырую и альфа-доходность против бенчмарка и пишет короткую рефлексию, которую менеджер читает при следующих решениях [1]. Обзор 2026 года добавляет обязательные правила: «outcome embargo» (исход нельзя достать до момента его наблюдения), retrieval с учётом времени, provenance фактов, а позиции и лимиты хранить как read-only состояние, а не как «память» LLM [33].

7. **Оркестрация.** LangGraph (1.0 GA в октябре 2025, ветка 1.2.x в 2026) остаётся стандартом для графов с чекпоинтами и human-in-the-loop-прерываниями. На нём построены TradingAgents и QuantAgent, а по вторичным источникам и ранние версии ai-hedge-fund [1][15][50]. PydanticAI (V2 с июня 2026) лучше всего подходит, когда нужны типизированные выходы, и поддерживает durable execution через Temporal, DBOS, Prefect, Restate и AWS Lambda; FinRobot V2 перешёл на него [5][51]. AutoGen находится в режиме поддержки, его сменил Microsoft Agent Framework 1.0 (апр. 2026) [53]. Для маленькой персональной системы разумен детерминированный Python-конвейер с LLM-узлами на PydanticAI или LangGraph.

8. **MCP-экосистема для РФ появилась в 2026 году.** Т-Инвестиции запустили официальный MCP-сервер: анонс в июне 2026 (по выдаче, не проверено), пресса 11.09.2026, разбор команды T-Invest API на Хабре 26.09.2026. Это удалённый сервер `https://invest-public-api.tbank.ru/mcp` (есть песочница) с транспортом Streamable HTTP и авторизацией `Authorization: Bearer <токен T-Invest API>`. Права задаются уровнем токена: «только чтение», «торговля» или «переводы». Пресса пишет, что операции требуют подтверждения человека, но по техническому разбору сервер подтверждения не навязывает: агент с торговым токеном может ставить заявки сам, а подтверждение реализуется на стороне клиента [47]. Есть десяток сторонних MCP-серверов для MOEX ISS и T-Invest, например read-only `market-mcp`, `mcp-moex`, `moex-algopack-mcp` [48]. Для нашего агента разумно держать собственный типизированный слой инструментов (его можно опубликовать и как MCP) с read-only токеном, без инструментов записи.

9. **RL в этих системах применяют точечно.** Trading-R1 использует SFT и трёхступенчатое RL на 100 тыс. примеров для обучения reasoning-модели [20]. FinCon применяет «вербальное RL»: обновляет промпты-убеждения без изменения весов [12]. R&D-Agent(Q) выбирает направление исследований многоруким бандитом [18]. В FINSABER классические DRL-агенты (A2C, PPO, SAC, TD3) системно не обыгрывали buy-and-hold [26]. Для личного агента RL уместно на мета-уровне (веса источников сигналов, пороги ребалансировки), но только после накопления журнала исходов и с честной walk-forward-оценкой.

10. **Оценка — отдельная подсистема, а не постфактум.** Нужны форвардный paper-трекинг «теневого портфеля» по рекомендациям, сравнение с пассивным бенчмарком (IMOEX/MCFTR, RGBI/RUCBTR, микс), атрибуция доходности (бета, стиль, отбор), журнал всех кандидатов и дефляция метрик по числу попыток. Работа «What survives honest evaluation» (авг. 2026) показала: намеренно «протекающий» оракул с Sharpe 35 проходит Deflated Sharpe и PBO, поэтому защита от look-ahead должна быть структурной (через инструменты), а не только статистической [31].

## Детальные находки

### 1. Карта ландшафта: классы систем

Если упростить, LLM-системы в финансах делятся на пять классов. Для нашего агента важны первые два, а классы 3–5 служат источником отдельных приёмов.

| Класс | Что делает LLM | Примеры | Частота | Релевантность для нас |
|---|---|---|---|---|
| 1. Мультиагентная «фирма» (decision agent) | Читает данные, рассуждает, выдаёт BUY/SELL/HOLD или веса | TradingAgents, FinCon, ai-hedge-fund, MarketSenseAI, AlphaAgents, ContestTrade | день, неделя, месяц | Высокая: шаблон ролей, дебатов, риск-контура |
| 2. Аналитик-репортёр (research agent) | Пишет отчёт или тезис, числа считает код | FinRobot (Equity Research), MarketSenseAI (объяснения), GigaChat в «СберИнвестициях» | по запросу | Высокая: формат еженедельного отчёта |
| 3. Агент с памятью и рефлексией (single-agent) | Торгует одним активом, учится на исходах через вербальную рефлексию | FinMem, FinAgent | день | Средняя: схемы памяти |
| 4. Генератор стратегий и факторов | Генерирует гипотезы, факторы и код, которые проверяет бэктест | Alpha-GPT, AlphaAgent, R&D-Agent(Q), FactFin, Vibe-Trading | офлайн | Средняя: «LLM пишет гипотезу, код проверяет» |
| 5. Внутридневная техника (price-only) | Индикаторы и паттерны по графикам, в том числе через vision | QuantAgent/QuantHarness | минуты–часы | Низкая: горизонт не наш |
| 6. Fine-tuned финансовые LLM | Сентимент, классификация, прогноз направления | FinGPT, Trading-R1, Fin-R1 | — | Средняя: сентимент-классификатор как инструмент |

Актуальные каталоги систем, MCP-серверов и навыков ведутся сообществом, например awesome-trading-agents [43]. Звёзды и популярность репозиториев в 2026 году сильно расходятся между агрегаторами, поэтому как индикатор качества мы их не используем.

### 2. Разбор ключевых систем

#### 2.1 TradingAgents (TauricResearch / UCLA / MIT)

**Статус на октябрь 2026.** Репозиторий активно развивается: v0.6.0 вышла в октябре 2026, v0.5.x в сентябре 2026, v0.4.0 в августе 2026. Лицензия Apache-2.0. Построен на LangGraph [1]. На GitHub на 09.10.2026 около 110 тыс. звёзд; агрегаторы дают от 80 до 108 тыс., поэтому как индикатор качества эти цифры не используем.

**Роли и граф** [1][2]:
- **Analyst team**, начиная с v0.5.2 работает параллельно: Fundamentals, Sentiment (заголовки новостей, StockTwits, Reddit), News/macro, Technical (MACD, RSI и т. п.).
- **Researcher team**: Bull и Bear researchers спорят `max_debate_rounds` раундов, Research Manager подводит итог.
- **Trader** превращает отчёты в торговое предложение (тайминг, размер). В v0.4.0 добавлен «price grounding»: цена в решении трейдера привязана к реальным данным.
- **Risk management**: агрессивный, нейтральный и консервативный аналитики спорят отдельное число раундов (`TRADINGAGENTS_MAX_RISK_ROUNDS`).
- **Portfolio Manager** одобряет или отклоняет предложение. В v0.5.0 появился `PortfolioContext` с кэшем и позициями, так что трейдер, риск-аналитики и PM работают с реальной книгой.
- **Structured output**: Research Manager, Trader и Portfolio Manager выдают структурированный вывод (v0.2.4, апрель 2026).
- **Два уровня моделей**: `quick_think_llm` для аналитиков, исследователей и трейдера, `deep_think_llm` для менеджеров. С v0.6.0 провайдер можно задать отдельно для каждого уровня.
- **Протокол коммуникации** (из статьи): агенты обмениваются в основном структурированными документами (отчёты аналитиков, отчёт трейдера). Естественный язык используется только в дебатах, итог которых фасилитатор фиксирует структурированной записью [2]. Это сделано против «испорченного телефона» в длинных диалогах.

**Память и рефлексия (2026)** [1]. Персистентный журнал решений появился в v0.2.4 (апр. 2026), look-ahead в нём исправлен в v0.4.0. Каждое завершённое решение дописывается в Markdown-журнал (`~/.tradingagents/memory/trading_memory.md`). При следующем запуске решения, чей горизонт удержания истёк, «рассчитываются» (settle): система подтягивает сырую доходность и альфу против регионального бенчмарка и пишет рефлексию в один абзац. PM читает недавние решения по тому же тикеру и «уроки» по другим тикерам. Есть отдельный вызов `ta.settle_all_pending()`. Этот паттерн почти напрямую переносится на еженедельные рекомендации.

**Чекпоинты.** Включаются опционально (`checkpoint_enabled`). LangGraph сохраняет состояние после каждого узла в SQLite по тикеру, так что прерванный прогон можно возобновить [1].

**Point-in-time.** В версиях 0.3.1–0.5.2 (июль–сен. 2026) исправлен look-ahead (Alpha Vantage, FRED, соцсентимент, память; в v0.5.0 «point-in-time integrity» и SEC EDGAR «as filed»). Фундаментал берётся из SEC EDGAR «as filed» с датой публикации, бэктест ограничен данными, опубликованными к дате анализа [1]. Значит, оригинальная версия статьи 2024 года такой дисциплины не имела.

**Результаты статьи и критика.** Тест шёл с 1 января по 29 марта 2024 года на AAPL, GOOGL и AMZN. Совокупная доходность 23–27%, Sharpe 5,6–8,2 [2]. Сами авторы признают, что Sharpe выше ожидаемого диапазона, а окно короткое из-за стоимости LLM-вызовов: около 11 LLM-вызовов и 20+ вызовов инструментов на одно решение [2]. Окно пересекается с обучающими данными моделей того времени. В Profit Mirage Sharpe TradingAgents упал на 55,7% при переносе на период после отсечки знаний модели [27]. README предупреждает, что результаты недетерминированы и бэктест не гарантированно воспроизводим [1].

**Стоимость.** По оценке хостинг-шаблона Railway, один анализ одного тикера стоит примерно $0,20–0,80 при gpt-4o как deep-модели, gpt-4o-mini как quick-модели и одном раунде дебатов. Удвоение раундов примерно удваивает стоимость. Это маркетинговая оценка без методики [58].

**Прецедент локализации.** TradingAgents-CN (около 32 тыс. звёзд) адаптирует фреймворк под рынок A-shares. Данные идут из Tushare, AKShare и BaoStock, LLM — DeepSeek и Qwen, хранилище — MongoDB и Redis, интерфейс — FastAPI + Vue. Лицензия смешанная: ядро под Apache-2.0, интерфейс source-available с запретом коммерческого использования [25]. Это показывает объём работы для адаптации к MOEX: заменить нужно в первую очередь слой данных, а не граф.

**Вывод для нас.** TradingAgents ориентирован на один тикер и одну дату (`propagate(ticker, date)`). Наша задача портфельная и еженедельная. Мы заимствуем паттерны (роли, структурированные отчёты, ограниченные дебаты, журнал решений с расчётом исхода, разные уровни моделей, чекпоинты), но не форкаем код целиком: data layer под SEC/Yahoo для MOEX не подходит.

#### 2.2 ai-hedge-fund (virattt) → пакет `aihf`

**Статус.** Около 64 тыс. звёзд. Проект перестроен в устанавливаемый пакет `aihf` (`pipx install aihf`). Данные идут из Financial Datasets API, LLM-провайдеры — Anthropic, OpenAI, DeepSeek, Google, xAI, Kimi [3].

**Архитектура (по VISION.md)** [4]:
- **Аналитики**: LLM-персоны «в стиле» известных инвесторов (Buffett, Munger, Lynch, Druckenmiller) плюс квант-модели. Каждый аналитик выдаёт **conviction score от −1 до +1** и письменный тезис.
- **Portfolio manager** переводит взгляды в целевые позиции.
- **Risk model** («CRO») задаёт **жёсткие лимиты, которые аналитики не могут переопределить**.
- **CIO/allocator** распределяет капитал между «подами» (стратегиями).
- **LLM формирует взгляды и пишет тезисы. Детерминированный код определяет размер позиций и выставляет ордера, риск-лимиты работают как жёсткие гейты.**
- Режимы backtest, paper и live идут через один путь кода `advance`. Live выключен по умолчанию.
- **Append-only журнал с хэш-цепочкой**: позиции, P&L и каждое решение; каждая сессия хэш-связана с предыдущей. Расхождение при сверке с брокером поднимается как ошибка, а не «чинится» молча.
- Новые стратегии проходят валидационный гейт с проверками на переобучение (CPCV/PBO). Перевод в live по умолчанию одобряет человек.
- **Оговорка:** VISION.md — целевое видение. Сам документ указывает, что многое в нём пока аспирационно (например, полностью автономный режим исследовательской лаборатории запланирован, а не выпущен). Поэтому это референс архитектуры, а не доказанная практика.

**Вывод для нас.** Это ближайший к нашей задаче референс по разделению ответственности: шкала conviction от −1 до +1 вместо BUY/SELL, детерминированный конструктор портфеля, неизменяемый журнал, одобрение человеком. Персоны «великих инвесторов» сомнительны: они усиливают зависимость от «памяти» модели о публичных высказываниях и плохо переносятся на рынок РФ.

#### 2.3 FinRobot (AI4Finance Foundation)

- Архитектура из четырёх слоёв: Financial AI Agents (финансовый CoT), Financial LLM Algorithms, LLMOps/DataOps и Multi-source Foundation Models. **Smart Scheduler** (Director Agent, реестр агентов, адаптер, Task Manager) выбирает LLM под задачу [5][6].
- Цикл агента: Perception, затем Brain, затем Action [5].
- **Эволюция стека показательна**: V0 на AutoGen (теперь учебная), V1 на OpenAI Agents SDK, V2 (Desktop, «production») на PydanticAI, V3 в разработке [5].
- V2 строит отчёт из 13 глав с 12-месячной целевой ценой, уровнем уверенности и оговорками о данных. Оценки DCF, DDM, LBO и comps **считаются кодом, а не LLM**. Данные берутся у семи провайдеров с failover [5].
- Статья об Equity Research (2411.08804) утверждает, что качество отчётов сопоставимо с брокерскими. Это самооценка авторов [7].

**Вывод.** Принцип «models reason, software computes, agents orchestrate, systems verify» стоит взять дословно как правило архитектуры. Failover между провайдерами данных полезен и для MOEX ISS / T-Invest.

#### 2.4 FinGPT

Это data-centric проект 2023–2024 годов: LoRA-дообучение открытых моделей на сентимент (v1–v3) и FinGPT-Forecaster (недельный прогноз направления по Dow30 на Llama-2-7B). Последняя подтверждённая активность в репозитории — конец 2024 года, статья пересмотрена в ноябре 2025 [8][9]. По вторичным обзорам, классификация сентимента и заголовков сопоставима с GPT-4 (F1 до ~0,88–0,95), а прогноз направления движения цены близок к монетке (accuracy/F1 45–53%) [9]. **Вывод**: дообученные сентимент-модели полезны как дешёвый детерминируемый инструмент. Для русского языка нужна своя модель или LLM-разметка. Использовать прогноз направления цены от LLM как сигнал не стоит.

#### 2.5 Линия FinMem → FinAgent → FinCon (Stevens / Yu, Suchow и др.)

**FinMem** (2023) [10]:
- Профиль агента с риск-характером: risk-seeking, self-adaptive или risk-averse.
- **Слоистая долговременная память**: shallow, intermediate и deep слои с окнами примерно 14, 90 и 365 дней и разной скоростью затухания. Retrieval-скор складывается из recency (кривая забывания), relevancy (косинусная близость) и importance. Из каждого слоя берётся top-k.
- Рабочая память: суммаризация, наблюдение, рефлексия.

**FinAgent** (2024) [11]: мультимодальный агент (текст, числа, графики), технические индикаторы как инструменты, двухуровневая рефлексия (рыночная и по собственным решениям).

**FinCon** (NeurIPS 2024) [12]:
- Иерархия manager–analyst. Аналитики работают по источникам данных, менеджер консолидирует.
- **CVRF (Conceptual Verbal Reinforcement)**: риск-модуль периодически запускает самокритику по траекториям P&L. «Инвестиционные убеждения» обновляются как текст и **адресно** уходят только тем аналитикам, которых касаются. Это снижает коммуникационные издержки. Формально это POMDP, где политика — это текстовые промпты, без изменения весов.
- Два таймскейла риск-контроля: внутри эпизода и между эпизодами.
- Это одна из немногих систем, где явно решается задача портфеля, а не одного тикера.

**Критика.** В FINSABER на 20-летнем горизонте FinMem обыграл buy-and-hold только на TSLA из четырёх выбранных акций. В композитной выборке buy-and-hold значимо лучше (p до 3·10⁻⁶), альфа FinMem отрицательна во всех сценариях. В бычьих годах Sharpe FinMem около −0,19 против около 0,61 у buy-and-hold [26]. Profit Mirage фиксирует падение доходности FinMem на 71,85% вне периода памяти модели. У FinMem самая высокая «консистентность предсказаний» при контрфактических возмущениях данных (0,82): модель меняет решение лишь в 18% случаев, даже когда входные данные изменены, а это признак запоминания [27].

**Вывод.** Взять механику слоёв памяти с затуханием и адресной рефлексии. Не брать идею «агент сам решает каждый день BUY/SELL по одному тикеру».

#### 2.6 MarketSenseAI 2.0 (2025, IEEE ICDM 2025)

Архитектура [13]:
- **News Agent** ведёт «бегущий нарратив»: дневные сводки сворачиваются в накопительный, и старые, но релевантные истории не теряются.
- **Fundamentals Agent** строит Chain-of-Agents по отчётности: сводка 10-Q/10-K и риск-факторов, затем сводка earnings call (тон менеджмента, прогнозы), затем консолидация с числами за последние 5 кварталов.
- **Dynamics Agent** сравнивает цену с пирами и индексом (волатильность, Sharpe, MDD).
- **Macro Agent** работает как RAG по отчётам ЦБ, международных институтов и sell-side (чанкинг, векторная база, HyDE-запросы по фиксированному набору вопросов). Качество retrieval проверено через Ragas (context precision ≥ 0,98).
- **Signal Agent** выдаёт buy/hold/sell с объяснением.
- Сигналы ежемесячные, портфели long-only, взвешивание равное или по капитализации. Стек: GPT-4o, Pinecone, LlamaIndex, VectorBTPro.
- Результаты (самоотчёт): на S&P 100 за 2023–2024 гг. 125,9% против 73,5% у индекса. Издержки 10 б.п. на сделку срезают немного (до 123,0%). Look-ahead, point-in-time и survivorship в статье явно не разобраны [13].

**Вывод.** Самый близкий к нашей частоте (неделя или месяц) дизайн. Полезны «бегущий нарратив» новостей, Chain-of-Agents для длинных отчётов (МСФО/РСБУ, пресс-релизы) и макро-RAG по документам ЦБ РФ. Делать по образцу MarketSenseAI портфель «все BUY равными весами» не стоит: конструирование портфеля должно быть детерминированным с ограничениями.

#### 2.7 QuantAgent / QuantHarness (Stony Brook и др., 2025)

Работает только на ценах. Четыре агента: Indicator, Pattern, Trend (Pattern и Trend строят графики и анализируют их vision-моделью), Decision/Risk выдаёт LONG/SHORT со стопами. Построен на LangGraph. Данные из yfinance, последние 30 свечей, есть Flask-UI [14][15]. Авторы называют его HFT, хотя оценка шла на 4-часовых интервалах. **Вывод**: для недельного горизонта нерелевантен. Максимум, что можно взять, — идею «технического суб-агента», но технику лучше считать детерминированно.

#### 2.8 Генераторы альф и стратегий: Alpha-GPT, AlphaAgent, R&D-Agent(Q), FactFin

- **Alpha-GPT / 2.0** — human-in-the-loop майнинг альфа-факторов. Агент с инструментами вычисления альф, бэктеста и поиска, плюс «база альф» с аннотациями (стиль, рыночные условия, описание пользователя) [17].
- **AlphaAgent** (2025) борется с «alpha decay» тремя регуляризаторами: оригинальность через сравнение AST формулы с существующими альфами, согласованность «гипотеза ↔ фактор» (проверяет LLM) и ограничение сложности. Самоотчёт: около 11% годовой избыточной доходности (IR 1,5) на CSI 500 и 8,74% (IR 1,05) на S&P 500 за 2021–2024 гг. после издержек [16].
- **R&D-Agent(Q)** (Microsoft, NeurIPS 2025 D&B) работает циклом Research (гипотезы), Development (Co-STEER пишет код), реальный бэктест, Feedback. Следующее направление выбирает **многорукий бандит**. Заявлено до 2× годовой доходности против классических библиотек факторов при на 70% меньшем числе факторов [18].
- **FactFin** (из Profit Mirage) использует LLM как генератор кода стратегии плюс RAG, эволюцию стратегий через MCTS и контрфактический симулятор, который штрафует стратегии, чувствительные к утечке [27].

**Вывод.** Для идей входа и скринеров надёжнее схема «LLM формулирует гипотезу или фильтр, код проверяет на истории с point-in-time и считает метрики», чем «LLM напрямую говорит купить». При этом каждая проверенная гипотеза должна логироваться для дефляции метрик [31].

#### 2.9 StockAgent (2024)

Это симулятор рынка из многих LLM-инвесторов (gpt-3.5, gemini-pro) для изучения влияния внешних факторов: ставок, новостей, «BBS-обсуждений». Это не торговый советник [19]. **Для нас нерелевантен**, кроме идеи сценарного стресс-теста («что если ставка ЦБ +200 б.п.»).

#### 2.11 Практика на российском рынке (2026)

- **Официальный MCP-сервер Т-Инвестиций.** Анонс в разделе новостей T-Invest API за июнь 2026 (по выдаче; страница developer.tbank.ru не прочитана) [47]. Пресса от 11 сентября 2026 сообщает, что доступ получили все клиенты, а доступ к операциям настраивается в профиле: от чтения данных и аналитики до исполнения поручений. По версии прессы агент действует только в активной сессии чата и не может выполнять операции без подтверждения и участия клиента; финальные решения о сделках остаются за человеком (цитата А. Гусева, Т-Инвестиции) [47].
  - **Технические детали** (разбор команды T-Invest API на Хабре, 26.09.2026) [47]: endpoint `https://invest-public-api.tbank.ru/mcp` и песочница `https://sandbox-invest-public-api.tbank.ru/mcp`; транспорт Streamable HTTP; авторизация заголовком `Authorization: Bearer <token>`, где токен — обычный токен T-Invest API. При выпуске токена выбираются счёт и уровень доступа: «только чтение», «торговля» или «переводы»; рекомендуется отдельный токен с минимальными правами на каждый сценарий. Для подключения нужны корневые сертификаты Минцифры (поэтому developer.tbank.ru и не открывался из среды исследования). Группы инструментов: счёт и портфель (например, `invest_get_portfolio`), рыночные данные (стаканы, свечи, сделки, теханализ, календарь), торговля (лимитные и рыночные заявки, стоп-лосс, тейк-профит, трейлинг-стоп), справочник инструментов (акции, облигации, фонды, фьючерсы, валюта), аналитика (стратегии и сигналы, инсайдерские сделки, новости, фундаментал), выплаты (дивиденды, купоны, НКД, события облигаций), пополнения и переводы между своими счетами.
  - **Важно:** в техническом разборе нет серверного шага подтверждения. Агент с торговым токеном может ставить заявки сам (в примере с Hermes Agent тейк-профиты ставятся по крону в 03:00 без подтверждения), а подтверждение через inline-кнопки Telegram реализовано на стороне клиента (пример с n8n). Значит, для нашего агента защитой является **токен «только чтение»**, а не обещание подтверждения. Полный список имён инструментов и лимиты всё ещё нужно сверить с документацией.
- **Хакатон MOEX AI.** Соревнование запущено в середине апреля 2026 года. Подано 340 заявок, к торгам допущены 50 команд, по 1 млн виртуальных рублей у каждой, 20 акций. Виртуальные торги начались 28 мая. По итогам первых двух недель тестов (тестовый этап, публикация 01.06.2026) большинство агентов обогнали IMOEX, но **в плюсе были только 5 из 50**. Лучший агент сделал 875 сделок за 10 активных дней, а самый активный (2539 сделок) оказался последним. После тестового этапа начинался этап полностью автономных торгов до 15:00 мск 10 июня 2026 года; его итоги в цитируемых источниках не приведены. Эксперты называют главными рисками галлюцинации, ошибки и нарушения правил, синхронные действия агентов с похожей логикой [44].
- **Тест «Финама»** (вторичные данные). 6 моделей, по 100 тыс. ₽ и $10 тыс., со 2 февраля по 31 марта 2026 года, только long, без деривативов (параметры по пересказу обзора, не проверены). По пересказу обзора, почти все модели закрыли период в минусе, а «ИИ-ансамбль» показал минимальную волатильность. Ведомости подтверждают общий вывод: практически все популярные модели показали просадку по депозиту на виртуальных счетах [44]. Точные цифры по моделям не проверены.
- **БПИФ «Первая — Фонд искусственный интеллект»** (окт. 2026). Четыре агента: анализ конкурентов (портфели других активных фондов), фундаментальный анализ, новости и супервизор, который агрегирует и разрешает конфликты. Первые три работают параллельно и независимо. **Управляющий обязан проверить рекомендации до исполнения** [45].
- **GigaChat в «СберИнвестициях»** (8 окт. 2026). Сервис объясняет изменение стоимости портфеля: выделяет бумаги, сильнее всего повлиявшие на результат, и сопоставляет их с новостями и аналитикой SberCIB. Доступен при наличии трёх и более активов (акции, облигации, фонды) [46]. Это объяснительный, а не торговый агент, и хороший UX-ориентир для «что случилось с портфелем за неделю».

**Вывод.** Рынок РФ движется к той же модели: LLM-аналитика плюс человек принимает решение плюс брокерский MCP с гранулярными правами. Это совпадает с требованиями пользователя.

#### 3.2 Что из этого следует

1. **Общий «интеллект» модели не означает инвестиционного навыка.** LMArena не коррелирует с доходностью [35]. Reasoning-модели не дают стабильного преимущества в StockBench и LiveTradeBench [34][35]. Выбор модели должен опираться на собственную оценку на нашей задаче: качество извлечения, следование схеме, стоимость. Публичные рейтинги для этого не подходят.
2. **Архитектура и риск-контур важнее модели** [36][37]. В DeepFund наибольшие просадки связаны с концентрацией и низкой долей кэша, а не с «глупостью» модели [37]. На хакатоне MOEX самый активный агент оказался последним [44]; для Alpha Arena гипотезу об овертрейдинге и комиссиях по первоисточнику проверить не удалось [42].
3. **Доходность LLM-агентов сильно зависит от режима рынка** [26][34]. Еженедельный советник должен знать текущий режим (тренд, волатильность, ставка) и ограничивать активность в неблагоприятных режимах детерминированными правилами.
4. **Число сделок не равно результату** [42][44]. Еженедельный ритм с no-trade-зоной и порогами отклонения от целевых весов прямо защищает от главной причины проигрышей в live-тестах.
5. **LLM полезнее как аналитик и объяснитель, чем как предсказатель.** Сентимент, классификация и извлечение работают хорошо [9][39], прогноз направления цены почти случаен [9].

### 4. Методологические ловушки (критика всей области)

#### 4.1 Look-ahead из претрейна («память» модели)

- **Profit Mirage** [27] переоценил пять агентов на GPT-4o (отсечка знаний — октябрь 2023). Бэктест шёл на Q2–Q3 2021, проверка обобщения — на Q3–Q4 2024, рынок в оба периода около +13%. Падение Sharpe составило от 51,5% (QuantAgent) до 62,2% (FinCon), падение совокупной доходности — от 50,2% (TradingAgents) до 71,9% (FinMem). Дообучение на финансовых новостях повышает точность внутри распределения и **ухудшает** её на невиданных данных на 18,1–21,5% (относительное изменение по метрике ΔGen: Llama-3.1-8B и Qwen2.5-7B). На FinLake-Bench (2000 вопросов за янв. 2022 – июн. 2023; GPT-4o, Claude 3.7 Sonnet, Grok-3) точность «вспоминания» по категориям 85–93%.
- **The Memorization Problem** [28]: если модель видела исход, навык прогноза и запоминание неразличимы. Инструкции «не используй знания после даты X» не работают, маскировка тоже: модель восстанавливает сущности и даты по контексту. После даты отсечки воспроизведения из памяти нет.
- **Утечка через инструменты.** Даже при «чистой» модели утечка возможна через тексты, которые достаёт retrieval: новости с объяснениями задним числом, ревизии данных [33]. Формальная работа 2026 года [30] вводит понятие look-ahead-freedom как «временной невмешательности». Ключевая инженерная идея: **у каждого факта два времени — когда событие относится (reference time) и когда стало доступно (availability time)**. Retrieval и join должны фильтровать по availability time.

**Следствие для нас.** Агент работает в live-режиме: рекомендации даются на будущее, поэтому look-ahead в продакшене не возникает. Но **любой бэктест нашего агента на истории до даты отсечки модели будет завышен**. Валидировать агент можно только форвардным paper-трекингом или на периоде после отсечки модели. Для истории до отсечки можно бэктестить только детерминированные компоненты (скоринг, оптимизатор, правила ребалансировки).

#### 4.2 Короткие окна, малые выборки, survivorship

TradingAgents тестировался 3 месяца на 3 мегакапах (AAPL, GOOGL, AMZN в таблице результатов) [2], MarketSenseAI — 1–2 года [13]. FINSABER показывает, что на длинных периодах с делистингами преимущество исчезает [26]. Обзор 2026 года (80 систем): время сплита указано только в 62,5% работ, издержки в 58,8%, контроль survivorship в 60% [33]. В первоначальной выборке из 19 работ издержки указала лишь одна [33].

#### 4.3 Смещение отбора при поиске стратегий

«What survives honest evaluation» [31]: все LLM-сгенерированные стратегии (две frontier-модели, до 100 кандидатов, 5 повторов) отвергнуты после дефляции по полному числу проб. При этом пассивные бенчмарки сертифицированы. Порог дефляции растёт быстрее, чем лучший in-sample Sharpe при расширении поиска. Предзарегистрированные гипотезы требуют меньшего порога доказательств.

**Следствие.** Если агент сам перебирает фильтры для «идей входа», надо логировать каждую попытку и показывать пользователю не лучший бэктест, а дефлированную оценку. Ещё лучше ограничить пространство гипотез заранее.

#### 4.4 Недетерминированность и дрейф моделей

README TradingAgents прямо предупреждает о недетерминированности [1]. Повторные прогоны с теми же входами дают разные решения; temperature=0 сужает разброс, но не устраняет, а reasoning-модели часто игнорируют temperature [59]. Плавающие алиасы моделей у провайдеров тихо переключаются на новые снапшоты [59]. **Следствие**: фиксировать конкретную версию модели в конфиге, логировать её в каждой рекомендации, при важных решениях использовать self-consistency (N прогонов, затем агрегирование или флаг «модель не уверена»).

#### 4.5 Стоимость и задержка

- TradingAgents: около 11 LLM-вызовов и 20+ вызовов инструментов на решение по одному тикеру [2]. По внешней оценке $0,2–0,8 за тикер, стоимость растёт линейно с числом раундов дебатов [58].
- Для портфеля из 30–50 бумаг полный граф по каждой бумаге еженедельно обойдётся примерно в $6–40 в неделю по ценам этой оценки. Это допустимо для личного использования, но выгоднее каскад: дешёвый скрининг кодом, потом LLM только по изменившимся и топовым кандидатам.
- FINSABER рекомендует включать стоимость API в оценку эффективности стратегии [26]. Обзор 2026 года отмечает, что для рефлексивных методов стоимость инференса обычно не сообщается [33].
- Задержка для недельного горизонта некритична, но LLM нельзя ставить на критический путь стоп-сигналов [33]. Нам это не нужно: мы не исполняем сделки.

#### 5.2 Рекомендации по выбору

- Anthropic в «Building effective agents» советует начинать с простейшего решения, предпочитать **workflows** (заранее заданные пути кода) там, где задача хорошо определена, и инвестировать в дизайн инструментов (ACI, poka-yoke) [57]. Еженедельная перебалансировка — это хорошо определённый workflow, а не открытая агентная задача.
- **Рекомендуемая схема**: детерминированный конвейер на Python (планировщик, шаги данных и расчётов) плюс LLM-узлы на **PydanticAI** со строгими схемами. **LangGraph** как оркестратор оправдан, если нужны (а) пауза на одобрение пользователя с durable-возобновлением, (б) параллельные ветки аналитиков с чекпоинтами, (в) переиспользование паттернов TradingAgents. Комбинация «LangGraph-граф + Pydantic-схемы для structured output» распространена и совместима.
- Агентный цикл со свободным выбором инструментов (Claude Agent SDK, OpenAI Agents SDK) уместен только для режима «свободный вопрос пользователя в Telegram» («почему упал фонд X?»). Даже там инструменты должны быть только на чтение.
- Не стоит строить на AutoGen (maintenance) и на CrewAI Crews (низкая воспроизводимость) [52][53].

#### 6.3 Выводы по MCP

1. **Для ядра конвейера MCP не обязателен.** В детерминированном конвейере данные проще и надёжнее брать прямыми типизированными клиентами (gRPC/REST T-Invest API, MOEX ISS) с кэшем и point-in-time-хранилищем. MCP ценен для режима свободного диалога и для переиспользования инструментов разными клиентами (бот, Claude Desktop, IDE).
2. **Собственный MCP-сервер, а не сторонний.** Сторонние серверы — это неаудированный код с доступом к брокерскому токену. Лучше написать свой тонкий read-only сервер поверх своего data layer (по образцу `market-mcp`: маскирование, отсутствие write-методов, логи в stderr) или аудировать и запиннить конкретный коммит.
3. **Права.** Токен Т-Инвестиций «только чтение». Агенту по ТЗ не нужен доступ к заявкам, и это самая сильная защита от prompt injection через новости или MCP-выходы.
4. **Качество данных.** Учитывать задержку ISS 15 мин без подписки, нескорректированные на сплиты и дивиденды ряды, расхождения AlgoPack и ISS [48]. Нужен слой нормализации и сверки.
5. **Инъекции через данные.** Тексты новостей, постов и описаний инструментов попадают в контекст LLM и могут содержать инструкции. Правило: выход инструментов — это данные. Агент не имеет инструментов с побочными эффектами, а итоговые рекомендации проходят детерминированную валидацию.

### 7. Переиспользуемые паттерны и анти-паттерны

#### 7.1 Граница «детерминированное вычисление ↔ LLM-рассуждение»

Главный принцип, общий для FinRobot V2, ai-hedge-fund и FactFin [4][5][27]: **LLM никогда не производит число, которое затем используется в расчёте или показывается пользователю как факт.** LLM производит качественные суждения, категории, ранжирования и тексты, а числа получает из инструментов и передаёт дальше по ссылке.

| Задача | Кто делает | Почему |
|---|---|---|
| Синхронизация портфеля (Т-Инвестиции + ручной ввод), сверка | Код | Источник истины; расхождение сигнализируется, а не «чинится» [4] |
| Цены, доходности, волатильность, бета, корреляции, просадки | Код | Арифметика и ошибки схемы у LLM [34] |
| Облигации: YTM, дюрация, купоны, оферты, амортизация, НКД | Код | Чистые формулы; ошибки дорого стоят |
| Фундаментальные мультипликаторы, DCF, сравнения с пирами | Код (LLM может выбрать пиров и объяснить) | FinRobot V2: оценки в коде [5] |
| Технические индикаторы, режим рынка (тренд или волатильность) | Код | Детерминированность, воспроизводимость |
| Сводка новостей, извлечение событий, классификация сентимента | LLM (или fine-tuned классификатор) | Сильная сторона LLM [9][39] |
| Агрегированная «сентимент-метрика» по бумаге | Код поверх LLM-разметки (счётчики, взвешивание, затухание) | Разметку делает LLM, метрику считает код |
| Качественный тезис (почему бумага интересна или рискованна) | LLM, со ссылками на ID фактов | Объяснимость |
| Conviction / view по бумаге (−1…+1, уверенность) | LLM в строгой схеме | Шкала как в ai-hedge-fund [4] |
| Целевые веса портфеля | **Код** (оптимизатор с ограничениями) из views LLM | LLM-аллокации нестабильны и зависят от стиля модели [35] |
| Список сделок (лоты, комиссии, налоги, минимальный размер) | Код | Точность |
| Жёсткие риск-лимиты (концентрация, класс актива, ликвидность, ЦФА-квота) | Код, без возможности переопределить | «Hard limits analysts cannot override» [4]; защиты вне генеративного цикла [33] |
| Критика плана (soft risk review) | LLM | Ловит качественные риски (событийные, регуляторные) |
| Текст отчёта в Telegram | LLM из структурированных данных + валидатор чисел | Объяснимость без галлюцинаций |

**Механика «numbers only from tools»:**
1. Каждый результат инструмента — это типизированный объект с `fact_id`, `value`, `unit`, `as_of` (availability time), `ref_time`, `source`.
2. LLM в структурированном выходе ссылается на `fact_id`, а не переписывает число.
3. Рендерер отчёта сам подставляет числа по `fact_id`.
4. Валидатор проверяет: каждое число в свободном тексте LLM либо совпадает с числом из использованных фактов (с допуском), либо отчёт отклоняется и перегенерируется. Для этого достаточно regex-извлечения чисел и сопоставления.

```python
# Схемы (Pydantic v2) — основа structured output для LLM-узлов
from datetime import datetime
from enum import Enum
from typing import Literal
from pydantic import BaseModel, Field, conlist

class Fact(BaseModel):
    fact_id: str                 # напр. "px:SBER:2026-10-09"
    value: float | str
    unit: str | None = None
    ref_time: datetime           # к какому моменту относится
    available_at: datetime       # когда стало доступно (защита от look-ahead)
    source: Literal["tinvest", "moex_iss", "news", "manual", "calc"]

class AssetClass(str, Enum):
    equity = "equity"; bond = "bond"; fund = "fund"; dfa = "dfa"  # ЦФА

class AssetView(BaseModel):
    """Выход LLM-аналитика по одной бумаге. Никаких чисел — только ссылки на факты."""
    instrument_uid: str
    asset_class: AssetClass
    conviction: float = Field(ge=-1, le=1)          # медвежий..бычий
    confidence: float = Field(ge=0, le=1)
    horizon_weeks: int = Field(ge=1, le=52)
    thesis: str = Field(max_length=800)
    key_risks: conlist(str, max_length=5)
    evidence_fact_ids: conlist(str, min_length=1)   # обязательные ссылки на факты
    invalidation: str = Field(description="Что должно случиться, чтобы тезис стал неверным")

class RebalanceAction(BaseModel):
    instrument_uid: str
    action: Literal["increase", "decrease", "hold", "exit", "enter"]
    # target_weight НЕ генерирует LLM — его заполняет оптимизатор
    rationale_fact_ids: list[str]

class WeeklyReport(BaseModel):
    run_id: str
    model_versions: dict[str, str]                  # фиксируем точные версии моделей
    views: list[AssetView]
    actions: list[RebalanceAction]
    portfolio_summary_md: str                       # текст, проходящий numeric-grounding валидатор
```

#### 7.2 Structured outputs: практические правила

- Использовать нативный structured output провайдера или валидацию с ретраями (PydanticAI `output_type`) [51]. В StockBench reasoning-модели чаще ломали JSON-схему [34], поэтому ретраи и fallback-модель обязательны.
- Схемы должны быть **узкими**: enum, диапазоны, max_length, обязательные `evidence_fact_ids`. Свободный текст только в ограниченных полях.
- Межагентный обмен должен идти структурированными документами, а не диалогом (TradingAgents) [2]. Дебаты, если они есть, заканчиваются структурированной записью фасилитатора.
- Роли задаются **конкретными задачами** с чек-листами и выходной схемой, согласованной с тем, что нужно следующему шагу. Это даёт значимый прирост против абстрактных ролей «ты аналитик» [22].

#### 7.3 Дебаты bull/bear и риск-менеджер

- **Что известно.** Дебаты есть в TradingAgents, FinCon (через иерархию), Macro Economists (hawk/dove) и в мультиагентной системе для крипто-портфеля [1][12][23][24]. Эффект небольшой или не доказан: прирост Sharpe +0,04 при p<0,10 против rule-агента, но лучшего одиночного агента дебаты не обыгрывают (ΔSharpe −0,004, p=0,769), а польза объясняется коррекцией смещённого агента, а не самим обсуждением [23]. Обзор 2026 года указывает, что при равных вычислительных ресурсах и доступе к данным преимущество координации над одиночным агентом не установлено, и требует абляций [33]. В Agent Market Arena различия создаёт фреймворк, то есть дизайн риск-поведения [36].
- **Рекомендация.** Дебаты не нужно запускать для всех бумаг. Их стоит применять как **адресный критический проход** для (а) новых идей входа, (б) предлагаемых изменений веса выше порога, (в) бумаг с противоречивыми сигналами (сильный разброс conviction между аналитиками). Достаточно одного раунда: bull и bear, затем судья в структурированном выходе.
- **Риск-менеджер в два слоя**: (1) детерминированные hard limits (концентрация на эмитента и сектор, доля класса актива, минимальная ликвидность, лимит доли ЦФА, кредитное качество облигаций, лимит оборота за неделю); (2) LLM-критик, который ищет качественные риски (корпоративные события, санкционные и регуляторные новости, оферты и колл-опционы облигаций) и может только **понизить** уверенность или заблокировать действие, но не увеличить позицию.
- **Анти-паттерн**: персоны «великих инвесторов» как источник альфы. Они опираются на память модели о высказываниях и плохо переносятся на MOEX.

#### 7.4 Память прошлых рекомендаций и рефлексия

Сводный паттерн по TradingAgents (2026), FinMem, FinCon и обзору 2026 года [1][10][12][33]:

1. **Журнал решений (append-only, с хэш-цепочкой по образцу ai-hedge-fund [4]).** Для каждой рекомендации сохраняются входные факты (снапшот), версии моделей и промптов, view, действие, целевой вес, горизонт, критерий инвалидации и решение пользователя (принял, отклонил, изменил).
2. **Settlement.** Когда горизонт истекает (например, 1, 4 и 12 недель), код считает исход: доходность бумаги, доходность против бенчмарка класса актива, вклад в портфель, а также выполнился ли критерий инвалидации.
3. **Рефлексия.** Дешёвая LLM пишет 2–3 предложения «урока» в структурированной схеме (тип ошибки: тайминг, оценка, новости, режим, данные). Рефлексия **ссылается на расчёт**, а не пересчитывает его.
4. **Retrieval в следующих прогонах.** Берутся уроки по той же бумаге и сектору плюс top-k общих уроков, с затуханием по давности (идея слоёв FinMem 14/90/365 дней) и с **outcome embargo**: исход недоступен до момента наблюдения [33]. Брать нужно немного: избыток контекста ухудшает рассуждение («Lost in the Middle») [33].
5. **«Убеждения» по FinCon.** Периодически (раз в месяц или квартал) выполняется агрегирование уроков в короткий список «убеждений» (например, «новостной сентимент по облигациям второго эшелона даёт ложные сигналы при росте ключевой ставки»). Убеждения адресно добавляются в промпт соответствующего аналитика [12]. Пользователь видит и может удалить убеждения: так рефлексия не превращается в неконтролируемый дрейф.
6. **Состояние портфеля — не «память».** Позиции, лимиты и цели хранятся в БД как read-only истина, а не в тексте памяти LLM [33].

```python
# Settlement + reflection (эскиз)
def settle_due(now, journal, prices, benchmarks, llm_reflect):
    for rec in journal.pending(due_before=now):
        r_asset = prices.total_return(rec.instrument_uid, rec.created_at, rec.due_at)  # код
        r_bench = benchmarks.total_return(rec.asset_class, rec.created_at, rec.due_at)  # код
        outcome = Outcome(rec_id=rec.id, r_asset=r_asset, excess=r_asset - r_bench,
                          invalidated=check_invalidation(rec, prices))
        journal.attach_outcome(outcome)                       # append-only
        lesson = llm_reflect(rec=rec.to_struct(), outcome=outcome.to_struct())  # схема Lesson
        memory.add(lesson, available_at=rec.due_at)           # outcome embargo
```

#### 7.5 Human-in-the-loop

- По ТЗ агент не торгует, поэтому HITL встроен по определению. Но и здесь есть паттерны:
  - Каждая рекомендация в Telegram сопровождается кнопками **«Принял / Отклонил / Изменил / Отложить»**. Ответ записывается в журнал, а это ценнейший сигнал для оценки и будущего RL или бандита.
  - Отслеживаются **два портфеля**: «теневой» (если бы все рекомендации исполнялись) и фактический (из Т-Инвестиций). Расхождение показывает, насколько пользователь доверяет агенту, и позволяет честно оценить агента.
  - Пауза графа на одобрение (LangGraph `interrupt` или durable execution в PydanticAI) нужна, только если после одобрения агент что-то делает дальше, например пересчитывает план с изменёнными пользователем ограничениями [50][51].
- Индустрия подтверждает эту модель: Т-Инвестиции публично заявляют, что финальные решения о сделках остаются за человеком (при этом технически подтверждение обеспечивает клиент, а не MCP-сервер, поэтому опора — токен «только чтение») [47], в БПИФ «Первая — ИИ» рекомендации проверяет управляющий [45], ai-hedge-fund в своём VISION требует ручного одобрения перевода в live [4].

#### 7.6 Контроль стоимости

1. **Каскад**: детерминированный скрининг и расчёты (бесплатно) → LLM только по (а) бумагам портфеля с существенными новостями или изменениями, (б) top-N кандидатам в идеи → дебаты только по спорным и крупным изменениям.
2. **Уровни моделей**: quick-модель для суммаризации и разметки новостей, deep-модель для синтеза и критики (как `quick_think_llm` и `deep_think_llm` в TradingAgents) [1].
3. **Кэш аналитических артефактов**: сводка новостей по бумаге за день или отчётность за квартал считается один раз и переиспользуется. Ключ кэша включает `available_at`.
4. **Инкрементальность**: «бегущий нарратив» новостей по образцу MarketSenseAI [13] вместо повторной суммаризации всей истории.
5. **Prompt caching** у провайдера для длинных стабильных системных промптов и описаний инструментов, batch-API для недельного прогона (если провайдер поддерживает).
6. **Бюджет на прогон**: жёсткий лимит токенов и денег, учёт стоимости в журнале на уровне каждой рекомендации (FINSABER рекомендует включать стоимость API в оценку стратегии [26]).

#### 7.7 Оценка (evaluation) как подсистема

| Уровень | Что мерить | Как |
|---|---|---|
| Данные | Свежесть, полнота, расхождения T-Invest ↔ ISS, корректировка на сплиты | Автотесты конвейера данных |
| Числа | 0 расхождений между числами в отчёте и фактами | Numeric-grounding валидатор (блокирующий) |
| Извлечение и сентимент | Точность разметки новостей на русском | Ручная «золотая» выборка из 100–300 новостей; периодическая перепроверка |
| Качество текста | Полнота, обоснованность, ссылки на факты | LLM-as-judge по рубрике + выборочная ручная проверка |
| Рекомендации | Избыточная доходность против бенчмарка класса актива; hit-rate по горизонтам; оборот; издержки | Форвардный paper-трекинг теневого портфеля; **атрибуция** на бету, стиль и отбор (по образцу KTD-Fin) [32] |
| Устойчивость | Стабильность решения при повторном прогоне и перефразировании | Self-consistency: N прогонов; доля совпадений |
| Абляции | Дают ли что-то новости, сентимент, дебаты, память | On/off-абляции по рекомендациям обзора [33]; минимум несколько месяцев данных |
| Статистика | Значимость | Deflated Sharpe, учёт числа проверенных гипотез, предрегистрация правил [31]; честно: на недельных данных за год значимости почти не будет |

**Ключевая мысль.** Для персонального агента реалистичная цель — дисциплина (соблюдение целевых долей, риск-лимитов, своевременная реакция на события), объяснимость и экономия времени пользователя. Устойчивая альфа нереалистична. Метрики оценки надо выбирать под эту цель.

#### 7.8 Анти-паттерны (сводка)

1. LLM напрямую генерирует целевые веса или количество лотов.
2. Бэктест LLM-агента на периоде до отсечки знаний модели как доказательство качества [27][28].
3. Короткое окно, несколько мегакапов, нет издержек и делистингов [26][33].
4. Перебор фильтров или стратегий без учёта числа попыток [31].
5. Дебаты «на всё» со многими раундами: дорого, а эффект не доказан [2][33].
6. Персоны «известных инвесторов» как источник сигнала.
7. Неконтролируемая «самообучающаяся» память, которая переписывает поведение без ведома пользователя.
8. Брокерский токен с правами торговли у агента, сторонний MCP с отключённым подтверждением сделок [48].
9. Плавающие алиасы моделей без фиксации версии [59].
10. Частые сделки и реакция на каждую новость: на хакатоне MOEX самый активный агент оказался последним [44], а в DeepFund худшие просадки дали концентрация и низкая доля кэша [37]. Для Alpha Arena роль овертрейдинга по первоисточнику не проверена [42].
11. Суммаризация новостей без дат и источников, то есть без provenance [33].
12. Использование нескорректированных рядов MOEX ISS для расчёта доходности [48].

## Выводы для архитектуры агента

### A. Принципы

1. **Workflow, а не автономный агент.** Еженедельный цикл — это фиксированный граф шагов. Автономный агентный цикл нужен только для свободных вопросов пользователя в Telegram, и только с read-only-инструментами [57].
2. **«Models reason, software computes, agents orchestrate, systems verify»** [5]. Числа берутся только из инструментов, веса считает оптимизатор, отчёт проверяет валидатор.
3. **Views → optimizer.** LLM выдаёт по каждой бумаге `conviction ∈ [−1, 1]` и `confidence`. Детерминированный модуль превращает их в ограниченные наклоны относительно стратегической аллокации пользователя (например, ±N п.п. от целевой доли класса актива) с жёсткими лимитами [4].
4. **Ребалансировка с no-trade-зоной.** Действия предлагаются только при выходе за полосу отклонения или по сильному событию. Это прямая защита от овертрейдинга [33][42][44].
5. **Журнал, settlement и рефлексия** по паттерну TradingAgents 2026 и ai-hedge-fund [1][4], с outcome embargo и редактируемыми пользователем «убеждениями» [12][33].
6. **Point-in-time по умолчанию.** Каждый факт хранит `ref_time` и `available_at`, retrieval фильтрует по `available_at` [30][33]. Это нужно и для будущих бэктестов детерминированных частей, и для честных рефлексий.

### B. Эскиз еженедельного конвейера

```
[Cron: воскресенье/понедельник утро]
  │
  ├─ 1. Sync ───────── T-Invest API (read-only токен) + ручные позиции (ЦФА и др.) → сверка → Portfolio (истина)
  ├─ 2. Data refresh ─ MOEX ISS / T-Invest: свечи, параметры облигаций, купоны/дивиденды, состав фондов;
  │                    новости (RSS/Telegram-каналы/раскрытие) → point-in-time store (ref_time, available_at)
  ├─ 3. Quant layer ── код: метрики риска, drift от целевых долей, режим рынка, скоринг кандидатов,
  │                    YTM/дюрация, ликвидность; сентимент-метрика = агрегат LLM-разметки (код)
  ├─ 4. Analyst layer ─ LLM (quick), параллельно, только по «изменившимся» бумагам портфеля + top-N кандидатам:
  │                    NewsAnalyst, FundamentalAnalyst, BondAnalyst, FundAnalyst (look-through), DFAAnalyst
  │                    → AssetView (схема, ссылки на fact_id); кэш артефактов
  ├─ 5. Debate (адресно) ─ bull/bear 1 раунд + judge (deep) для новых идей / крупных изменений / противоречий
  ├─ 6. Risk ───────── hard limits (код, непереопределяемые) + LLM-критик (может только понизить/заблокировать)
  ├─ 7. Construct ──── оптимизатор: стратегическая аллокация + наклоны из views + ограничения + no-trade-зона
  │                    → целевые веса → список действий (лоты, комиссии, налоговые эффекты — код)
  ├─ 8. Report ─────── LLM пишет текст из структуры → numeric-grounding валидатор → Telegram
  ├─ 9. HITL ───────── кнопки «Принял/Отклонил/Изменил/Отложить» → журнал
  └─ 10. Settle+Reflect ─ расчёт исходов прошлых рекомендаций (1/4/12 нед.) → уроки → память;
                          теневой портфель vs фактический vs бенчмарк → еженедельная сводка качества
```

Идеи входа (entry ideas) идут той же цепочкой 3 → 4 → 5 → 6 → 8, но скрининг кандидатов задаётся **предопределёнными, версионируемыми** фильтрами (а не свободным перебором LLM). Каждая проверенная гипотеза логируется [31].

### D. Где уместно RL

- **Не на старте.** Без нескольких месяцев журнала исходов RL не на чем обучать. Дообучение LLM через RL (Trading-R1) требует больших корпусов и GPU и даёт сомнительный перенос на MOEX [20].
- **Реалистичные точки применения (этап 2+):**
  1. Контекстный бандит или RL на мета-уровне: веса источников сигналов (новости, фундаментал, моментум) и аналитиков по реализованным исходам. Это аналог внутреннего конкурса ContestTrade [21] и бандит-планировщика R&D-Agent(Q) [18].
  2. Подбор порогов no-trade-зоны и частоты ребалансировки (оптимизация «доходность минус издержки минус оборот»).
  3. Использование реакций пользователя («принял/отклонил») как сигнала предпочтений, по сути как reward-модели персонализации.
- **«Вербальное RL»** по образцу FinCon (CVRF) [12] дешевле и прозрачнее: обновляется текст «убеждений», а не веса модели. С него стоит начать.
- Любое RL проверяется walk-forward-тестом, сравнением с простыми правилами (FINSABER: классические DRL не обыгрывали buy-and-hold [26]) и дефляцией по числу конфигураций [31].

## Риски и подводные камни

1. **Иллюзия качества из-за look-ahead.** Бэктест LLM-части на истории до отсечки модели почти гарантированно завышен на десятки процентов [27][28]. Валидировать можно только форвардом.
2. **Галлюцинации чисел и фактов.** Даже frontier-модели ошибаются в расчётах [40][41]. Нужен блокирующий валидатор, иначе ошибка уйдёт пользователю как факт.
3. **Prompt injection через новости, Telegram-каналы и сторонние MCP.** Агент без write-инструментов и с read-only токеном теряет главный вектор ущерба, но может выдать искажённую рекомендацию. Поэтому рекомендации проходят детерминированные лимиты.
4. **Стадность и режимная хрупкость.** LLM-агенты консервативны в росте и агрессивны в падении [26]. Нужны детерминированные режимные правила.
5. **Овертрейдинг и издержки** [42][44]. Нужны no-trade-зона и лимит оборота.
6. **Недетерминированность и дрейф моделей** [1][59]. Нужны фиксация версий, self-consistency и логирование.
7. **Неконтролируемая память.** Рефлексии могут закрепить случайные совпадения как «уроки». Нужны редактируемые пользователем убеждения, затухание и минимальный объём выборки перед формированием убеждения.
8. **Качество данных MOEX:** задержки, нескорректированные ряды, расхождения источников [48]. Для ЦФА данных мало и они разрознены (см. открытые вопросы).
9. **Зависимость от провайдера LLM и его доступности.** Нужна абстракция провайдера (OpenAI-совместимые эндпоинты, локальные модели) и fallback-модель; доступность конкретных API из РФ надо проверять отдельно (вне рамок этого отчёта).
10. **Стоимость** растёт линейно с числом бумаг и раундов дебатов [58]. Нужны каскад и бюджет на прогон.
11. **Регуляторно-правовой аспект.** Персональный инструмент для себя отличается от сервиса рекомендаций для других. В первом случае рекомендации, по сути, являются аналитикой для себя. Статус «индивидуальной инвестиционной рекомендации» по российскому праву (39-ФЗ, требования к инвестсоветникам) нужно проверить отдельно, если бот когда-либо будет доступен третьим лицам.
12. **Ложная уверенность пользователя.** Объяснимые, убедительные тексты могут создать доверие, превышающее реальную точность. В отчёте нужно показывать статистику качества агента (hit-rate, избыточная доходность теневого портфеля) рядом с рекомендациями.

## Открытые вопросы

1. Точные имена инструментов и лимиты **официального T-Invest MCP**; покрывает ли он ЦФА и внебиржевые позиции. Уже известно по разбору на Хабре: endpoint `invest-public-api.tbank.ru/mcp`, Streamable HTTP, Bearer-токен T-Invest API с уровнем «только чтение» / «торговля» / «переводы», нужны корневые сертификаты Минцифры [47]. Документация (developer.tbank.ru/invest/mcp) не прочитана: TLS-цепочка с сертификатом Минцифры не проходит проверку в среде исследования.
2. Какие LLM доступны и экономически оправданы для нас (frontier-API против GigaChat/YandexGPT против open-weight локально) с учётом качества на русскоязычных финансовых новостях. Нужен собственный мини-бенчмарк на 100–300 размеченных новостях и 20–50 вопросах по отчётности.
3. Источники новостей и сентимента для РФ (раскрытие e-disclosure и Интерфакс, RSS СМИ, Telegram-каналы, «Пульс» Т-Инвестиций): легальность и стабильность доступа, лицензии, качество.
4. Данные по ЦФА: где брать котировки и параметры выпусков, как оценивать ликвидность и кредитный риск; возможно, только ручной ввод.
5. Какой бенчмарк считать «рыночным» для смешанного портфеля пользователя (IMOEX/MCFTR, RGBI/RUCBTR, денежный рынок) и как задавать стратегическую аллокацию (ручной ввод или анкета риск-профиля).
6. Как лучше превращать `conviction` в веса: простые ограниченные наклоны, Black-Litterman или ранговая схема. Нужна симуляция на детерминированной части.
7. Минимальный объём журнала исходов, после которого рефлексия и бандит или RL дают статистически осмысленные выводы на недельных решениях.
8. Не проверено по первоисточникам: итоги Alpha Arena Season 1.5 (акции США), точные цифры «Финам Арены», полные результаты InvestorBench по моделям, детали архитектуры AlphaAgents. Лимит поиска в сессии исчерпан.

- Claude Agent SDK: авторизация не «только API-ключом». Поддерживаются ключ Anthropic, Amazon Bedrock, Claude Platform on AWS, Google Cloud и Microsoft Foundry; вход через claude.ai для сторонних продуктов не разрешён (https://code.claude.com/docs/en/agent-sdk/quickstart).
