# Исследование: персональный ИИ-аналитик инвестиций для рынка РФ (Т-Инвестиции, Telegram)

> **Дата:** 2026-10-09. **Статус:** сводный обзор по 11 детальным отчётам из каталога [`research/`](research/). Каждый отчёт заканчивается таблицей верификации. Если верификация расходится с исходным текстом отчёта, здесь приводится вариант верификации (см. раздел 13).
>
> **Задача пользователя.** Персональный агент-аналитик для российского рынка. Он анализирует историю активов, новостной фон и сентимент, предлагает точки входа, знает портфель (задаётся вручную, торговля идёт в Т-Инвестициях) и раз в неделю рекомендует перебалансировку. Классы активов: акции, облигации, фонды, ЦФА. Сделок агент не совершает. Интерфейс — Telegram-бот. RL возможен.
>
> **Что это за документ.** Обзор состояния области и ландшафта: как устроены подобные агенты, какие есть данные, решения, ограничения и риски. В конце разделов кратко сказано, что из этого следует для архитектуры. Подробное архитектурное предложение строится на этой базе отдельно.
>
> **Оговорки.** (1) Документ описывает системный дизайн. **Это не инвестиционная рекомендация**: тикеры (SBER, ОФЗ 26238, LQDT, TMOS и др.) приводятся только как примеры вызовов API. (2) Факты, которые меняются со временем (ставки, тарифы, версии, лимиты), датированы. (3) Во время исследования лимит веб-поиска был исчерпан, часть российских сайтов была недоступна из зарубежной среды. Непроверенные утверждения помечены, их сводка — в разделе 13.

## 1. Резюме исследования

1. **Ниша свободна.** Ни один найденный продукт не закрывает целиком проактивный недельный цикл «портфель → отклонения от целей → новости и сентимент по позициям → план ребалансировки с обоснованием» по акциям, облигациям, фондам и ЦФА в Telegram, в режиме только чтения и с журналом рекомендаций. Брокерские ИИ-ассистенты отвечают только на вопросы. Робо-эдвайзеры работают на отдельных счетах с автосделками. Трекеры не читают новости. Open-source-проекты не используют LLM ([08](research/08-existing-solutions.md)).
2. **Индустриальный шаблон — «виртуальная инвестиционная фирма»:** параллельные аналитики, дебаты bull/bear, трейдер, риск-контур, портфельный менеджер. Так устроены TradingAgents, FinCon, ai-hedge-fund и БПИФ «Первая — ИИ». Альфа от дебатов не доказана. Зрелые системы 2026 года работают по принципу **«LLM рассуждает, код считает»**: FinRobot V2, ai-hedge-fund, n8n-робот Т-Банка ([05](research/05-llm-financial-agents.md)).
3. **Опубликованные доходности LLM-агентов завышены.** После даты отсечки знаний модели Sharpe падает на 51–62% (Profit Mirage). На 20-летнем горизонте buy-and-hold значимо обыгрывает FinMem и FinAgent (FINSABER, KDD 2026). Live-бенчмарки дают скромные цифры: в StockBench от −2,8% до +2,5% против +0,4% у пассивного портфеля; на тестовом этапе хакатона MOEX в плюсе 5 команд из 50. Реалистичная цель агента — дисциплина, объяснимость и экономия времени, а не устойчивая альфа ([05](research/05-llm-financial-agents.md)).
4. **Числам от LLM доверять нельзя.** GPT-4-Turbo с общим векторным индексом не справился с 81% вопросов FinanceBench. В Vals Excel лучшая модель проходит 87% проверок структуры формул, но только 61% проверок чисел. Отсюда правило: все числа берутся из инструментов, вывод строго структурирован, отдельный валидатор сверяет числа в тексте ([05](research/05-llm-financial-agents.md)).
5. **Полноценный DRL на MOEX неоправдан.** Простые бейзлайны (1/N, Min-Var) обыгрываются с трудом. Выигрыши DRL в литературе получены в основном против слабого MVO. Недельной истории мало: около 1000 баров с 2007 года и около 237 недель после разрыва 2022 года. RL уместен только в низкоразмерной форме (доля риска, ширина no-trade-полосы, бандиты для идей) и только после накопления журнала. Ядро — классический оптимизатор на skfolio ([06](research/06-rl-and-portfolio-optimization.md)).
6. **T-Invest API (контракты 1.51 от 11.09.2026) закрывает почти все read-only-потребности:** портфель, операции, справочники, свечи, купоны и оферты, дивиденды, фундаментал (`GetAssetFundamentals`: 56 полей, из них 50 числовых показателей, 13 из них TTM), консенсус, сигналы, инсайдеры, ленту `News` (с 1.49), рейтинги облигаций `Bond.ratings` (с 1.51) и «внимание толпы» `interested_count`. Read-only-токен — штатный тип. Узкое место — лимит сервиса инструментов 200 запросов в минуту. Полный недельный прогон занимает 5–10 минут ([01](research/01-tinvest-api.md)).
7. **SDK переехал.** Актуальный пакет — `t-tech-investments` 1.51.0, ставится только с индекса GitLab Т-Банка. На PyPI проект в карантине, старый `tinkoff-investments` удалён, версия 1.0.0 сломала обратную совместимость, по умолчанию включена телеметрия ([01](research/01-tinvest-api.md)).
8. **Официальный T-Invest MCP** (`invest-public-api.tbank.ru/mcp`) с 10.09.2026 доступен всем клиентам. Он отдаёт то, чего нет в gRPC: новости по эмитентам с оценкой сентимента и инвестидеи. Подтверждение сделок сервер не обеспечивает, это задача клиента. Поэтому единственная надёжная защита — токен только на чтение ([01](research/01-tinvest-api.md), [08](research/08-existing-solutions.md)).
9. **Пробелы API:** нет котировок и позиций ЦФА, нет свечей внебиржевых ЗПИФ, нет числового сентимента и состава фондов. Фундаментал и консенсус отдаются как снимок без point-in-time-истории. После корпоративного действия история старого инструмента пропадает. Вывод: свою копию данных нужно хранить с первого дня ([01](research/01-tinvest-api.md), [11](research/11-signals-and-evaluation.md)).
10. **Бесплатный каркас данных:** MOEX ISS (задержка 15 минут, история, КБД с 2014 года, доходности и спреды облигаций, индексы, iNAV), ЦБ (DailyInfo, Data Service, КБД с 2003 года) и T-Invest. По наблюдению исследования, дивиденды и корпоративная информация в ISS стали платными (ЦКИ); верификацией это не перепроверено (❔, §13.6). Cbonds запрещает автоматизированный доступ. Бесплатный машиночитаемый источник рейтингов один — `Bond.ratings` ([02](research/02-market-data-sources.md)).
11. **Сеть раздваивает размещение.** Российские ресурсы выборочно недоступны из части зарубежных хостингов, набор зависит от конкретной сети. Telegram в РФ фактически заблокирован: 10.04.2026 OONI фиксировал до 95% аномалий. Для T-Invest, MOEX и GigaChat нужен корень Russian Trusted Root CA. Рабочая схема: VPS в РФ плюс исходящий туннель только для `api.telegram.org`, long polling, канал доставки как сменный адаптер ([03](research/03-news-and-social-sources.md), [09](research/09-telegram-bot-ux.md), [10](research/10-infra-llm-legal.md)).
12. **Новости.** Бесплатный каркас собирается из RSS: Интерфакс, ТАСС, Ведомости, Frank Media, Финам, Smart-lab, ЦБ, MOEX. Глубина ключевых лент около 1–2 часов, поэтому опрашивать их нужно примерно раз в 10 минут и с первого дня копить свой архив. У e-disclosure нет бесплатного API. Условия Telegram запрещают агрегацию данных для AI/ML, включая deployment, поэтому каналы годятся только как счётчики внимания. У Пульса нет официального API ([03](research/03-news-and-social-sources.md)).
13. **Сентимент — слабый сигнал.** Русской «FinBERT» промышленного качества нет. Тональность к сущности в русских новостях — трудная задача: лучший результат RuSentNE-2023 — 66,67% F1. По эмпирике MOEX сентимент во многом реактивен, а негатив действует сильнее позитива. Поэтому **события важнее тона**, а сентимент служит риск-фильтром и модификатором уверенности, а не триггером покупки ([04](research/04-nlp-sentiment.md), [11](research/11-signals-and-evaluation.md)).
14. **Макрорежим на 09.10.2026.** Ключевая ставка 14% действует с 27.07.2026, следующее заседание ЦБ — 23.10.2026. Инфляция 6,26% на 28.09 с всплеском в начале октября. Кривая ОФЗ рекордно крутая: 1 год — 13,73%, 10 лет — 16,82% на 08.10. IMOEX с начала года −16,6%. Идёт волна дефолтов ВДО, поэтому кредитный фильтр важнее купона ([07](research/07-russian-market-instruments.md)).
15. **Регуляторные и налоговые правила кодируются детерминированно.** Это доступ неквалифицированного инвестора (облигации от A+ без теста, `required_tests`), ЦФА по Указанию 7176-У (лимит 600 тыс. руб. в год **по каждому оператору**), НДФЛ 13/15%, FIFO, ЛДВ, ИИС-3 и тариф брокера (0,3% против 0,05%). ЦФА — отдельный, полуавтоматический класс активов ([07](research/07-russian-market-instruments.md)).
16. **Качество рекомендаций измеряется на уровне сигналов, а не P&L.** Проверенной базы факторных премий на MOEX нет. Мощность тестов низкая: чтобы отличить hit rate 55% от 50%, нужно около 782 рекомендаций. Поэтому мерить нужно IC сигналов, калибровку вероятностей, неизменяемый журнал и бумажное исполнение. Облигационный relative-value-блок самый надёжный. LLM-признаки оцениваются только после даты отсечки модели или форвардом не менее 26 недель ([11](research/11-signals-and-evaluation.md)).
17. **Telegram-стек:** aiogram 3.31 (Bot API 10.3). Rich messages дают таблицы, `<details>` и кнопки внутри сообщения. Есть стриминг черновиков с кнопкой «Стоп», топики в личке, `date_time`. Проверенные UX-паттерны: «сводка → Подробнее», «распределить пополнение», журнал решений «Принять / Отложить / Пропустить», импорт через diff-превью ([09](research/09-telegram-bot-ux.md)).
18. **LLM.** Claude, OpenAI и Gemini не обслуживают Россию. В рублях с OpenAI-совместимым API работают три площадки: Yandex AI Studio, GigaChat и Cloud.ru. Резидентность данных задаётся на уровне модели: у Cloud.ru часть моделей «внешние». Бюджет на LLM — 0–5 тыс. ₽ в месяц, инфраструктура — 2,2–3 тыс. ₽, итого обычно до ~8 тыс. ₽ ([10](research/10-infra-llm-legal.md)).
19. **Право.** Бот «для себя» не подпадает под инвестиционное консультирование (39-ФЗ) и под 152-ФЗ, так как обработка идёт для личных нужд. Если давать бот другим людям, возникают индивидуальные инвестиционные рекомендации (ИИР), требование аккредитации программы (ч. 6 ст. 6.2 39-ФЗ), обязанности оператора персональных данных и необходимость договора с биржей. Политики GigaChat и Anthropic требуют, чтобы решение проверял человек ([10](research/10-infra-llm-legal.md)).

## 2. Как устроены современные финансовые ИИ-агенты

Источник раздела: [05-llm-financial-agents.md](research/05-llm-financial-agents.md), дополнения из [06](research/06-rl-and-portfolio-optimization.md) и [08](research/08-existing-solutions.md).

### 2.1. Классы систем

| Класс | Что делает LLM | Примеры | Частота | Релевантность для нас |
|---|---|---|---|---|
| 1. Мультиагентная «фирма» | Читает данные, рассуждает, выдаёт BUY/SELL/HOLD или веса | TradingAgents, FinCon, ai-hedge-fund, MarketSenseAI, ContestTrade | день — месяц | Высокая: роли, дебаты, риск-контур |
| 2. Аналитик-репортёр | Пишет отчёт или тезис, а числа считает код | FinRobot (Equity Research), GigaChat в «СберИнвестициях» | по запросу | Высокая: формат недельного отчёта |
| 3. Одиночный агент с памятью и рефлексией | Торгует одним активом и учится на исходах | FinMem, FinAgent | день | Средняя: схемы памяти |
| 4. Генератор стратегий и факторов | Формулирует гипотезы и код, бэктест их проверяет | Alpha-GPT, AlphaAgent, R&D-Agent(Q), FactFin | офлайн | Средняя: «LLM формулирует, код проверяет» |
| 5. Внутридневная техника | Индикаторы и паттерны, в том числе через vision | QuantAgent / QuantHarness | минуты — часы | Низкая |
| 6. Дообученные финансовые LLM | Сентимент, классификация, прогноз направления | FinGPT, Trading-R1, Fin-R1 | — | Средняя: классификатор как инструмент |

### 2.2. Повторяющиеся архитектурные паттерны

1. **«Models reason, software computes, agents orchestrate, systems verify»** (FinRobot, https://github.com/AI4Finance-Foundation/FinRobot). В V2 оценки DCF, DDM, LBO и comps считает код, данные приходят от семи провайдеров с failover. В ai-hedge-fund LLM формирует взгляды, а размер позиций и ордера задаёт детерминированный код с жёсткими лимитами, которые аналитики не могут переопределить (https://github.com/virattt/ai-hedge-fund/blob/main/VISION.md; VISION.md — целевое видение, многое в нём пока аспирационно).
2. **Взгляды вместо команд.** Аналитик выдаёт `conviction ∈ [−1; +1]` и `confidence`, а оптимизатор превращает их в ограниченные наклоны относительно стратегической аллокации. FinCon тоже использует внешний MV-солвер для весов ([06](research/06-rl-and-portfolio-optimization.md)).
3. **Структурированный обмен вместо диалога.** TradingAgents обменивается между агентами отчётами. Естественный язык используется только в дебатах, итог которых фиксирует фасилитатор структурированной записью. Это защищает от эффекта «испорченного телефона» (https://arxiv.org/html/2412.20138v6).
4. **Конкретные задачи вместо абстрактных ролей.** Мелкозернистая декомпозиция («Toward Expert Investment Teams», февраль 2026) значимо улучшает риск-скорректированный результат по сравнению с ролями вида «ты аналитик». Важно, чтобы промежуточные выходы были согласованы с тем, что нужно этапу решения.
5. **Два уровня моделей.** В TradingAgents `quick_think_llm` обслуживает аналитиков, `deep_think_llm` — менеджеров. С v0.6.0 провайдера можно задавать отдельно для каждого уровня.
6. **Журнал решений, расчёт исхода и рефлексия.** В TradingAgents с v0.2.4 (апрель 2026) каждое решение записывается в журнал. Когда горизонт истекает, система считает сырую доходность и альфу к бенчмарку, после чего пишет короткую рефлексию, которую читает портфельный менеджер. Обзор 2026 года добавляет обязательные правила: outcome embargo (исход недоступен до момента наблюдения), retrieval с учётом времени, provenance фактов. Позиции и лимиты хранятся как read-only-состояние, а не как «память» LLM (https://arxiv.org/html/2605.19337v2).
7. **Слоистая память с затуханием** (FinMem: окна около 14, 90 и 365 дней; скоринг recency + relevancy + importance) и **«вербальное RL»** FinCon. Во втором случае текстовые «убеждения» обновляются по траекториям P&L и адресно уходят только нужным аналитикам.
8. **«Бегущий нарратив» новостей и Chain-of-Agents для длинных отчётов** (MarketSenseAI 2.0, https://arxiv.org/html/2502.00415v2), а также макро-RAG по документам центробанков.
9. **Неизменяемый журнал с хэш-цепочкой** и сверка с брокером. Расхождение поднимается как ошибка, а не исправляется молча (ai-hedge-fund).
10. **«Аналитик → детерминированный расчёт → оформитель текста».** Так устроен референсный n8n-робот Т-Банка: Code-узел считает план («LLM не считает деньги»), второй агент только оформляет текст и не имеет права пересчитывать числа ([08](research/08-existing-solutions.md), https://habr.com/ru/companies/tbank/articles/1086714/).

### 2.3. Обзор ключевых систем

| Система | Устройство (кратко) | Результаты / критика | Что взять |
|---|---|---|---|
| **TradingAgents** (TauricResearch, v0.6.0, октябрь 2026, Apache-2.0, LangGraph, около 110 тыс. звёзд) | Параллельные аналитики (фундаментал, сентимент, новости и макро, техника) → дебаты Bull/Bear → Research Manager → Trader → три риск-аналитика → Portfolio Manager. Structured output, `PortfolioContext` (v0.5.0), чекпоинты в SQLite, журнал решений `~/.tradingagents/memory/trading_memory.md`, `settle_all_pending()`. **Методологические ловушки:**
- **Look-ahead из претрейна.** Если модель видела исход, навык прогноза и запоминание неразличимы. Запреты «не используй знания после даты X» и маскировка не работают (The Memorization Problem). У каждого факта два времени: `ref_time` (к чему относится) и `available_at` (когда стало доступно). Retrieval должен фильтровать по `available_at`.
- **Следствие для нас:** любой бэктест LLM-части на истории до даты отсечки модели будет завышен. Валидировать её можно только форвардом или на периоде после отсечки. На всей истории бэктестятся только детерминированные компоненты: скоринг, оптимизатор, правила ребалансировки.
- **Короткие окна и survivorship.** В обзоре 80 систем время сплита указано только в 62,5% работ, издержки — в 58,8%.
- **Смещение отбора** при переборе фильтров: логировать каждую попытку и показывать дефлированную оценку.
- **Недетерминированность и дрейф.** temperature=0 не устраняет разброс, плавающие алиасы моделей тихо переключаются. Нужно фиксировать точную версию модели, логировать её и для важных решений использовать self-consistency.
- **Стоимость.** Полный граф TradingAgents по каждой из 30–50 бумаг стоит $6–40 в неделю по внешней оценке. Дешевле каскад: детерминированный скрининг, затем LLM только по изменившимся бумагам и топ-кандидатам.

### 2.7. Анти-паттерны (сводка)

LLM напрямую генерирует веса или лоты. Бэктест LLM-агента до отсечки модели выдаётся за доказательство. Короткое окно на нескольких мегакапах без издержек. Перебор стратегий без учёта числа попыток. Многораундовые дебаты «на всё». Персоны «великих инвесторов». Неконтролируемая самообучающаяся память. Токен с правом торговли у агента. Плавающие алиасы моделей. Реакция на каждую новость и частые сделки. Суммаризация новостей без дат и источников. Нескорректированные ряды ISS для расчёта доходности.

**Что следует для архитектуры.** Workflow вместо автономного агента. Числа только из инструментов (`fact_id`, `available_at`) и блокирующий валидатор чисел. Схема «взгляды → оптимизатор» с непереопределяемыми лимитами. Двухслойный риск-менеджер: hard limits в коде и LLM-критик, который может только понизить уверенность или заблокировать действие. Адресные дебаты в один раунд только для новых идей и крупных изменений. Журнал с settlement и редактируемыми пользователем «убеждениями». Point-in-time по умолчанию.

## 3. RL в управлении портфелем и классические альтернативы

Источник раздела: [06-rl-and-portfolio-optimization.md](research/06-rl-and-portfolio-optimization.md), дополнения из [05](research/05-llm-financial-agents.md) и [11](research/11-signals-and-evaluation.md).

### 3.1. Доказательная база: простые бейзлайны трудно обыграть

Если результат DRL совпадает с 1/N, качество, вероятно, определяется отбором бумаг, а не выученной аллокацией. У RL надёжнее получается риск-контроль и тайминг экспозиции, чем генерация альфы.

### 3.2. Почему на MOEX особенно трудно

- **Объём данных.** Для SBER недельные свечи в ISS есть с 16.07.2007, это около 1000 баров. У многих эмитентов история короче (IPO 2020–2025).
- **Структурный разрыв 2022 года.** Торгов акциями не было с 28.02 по 23.03.2022. 24.03 торги возобновились по 33 бумагам (9:50–14:00, короткие продажи запрещены), ОФЗ торговались уже с 21.03. Потом ушли нерезиденты и сменился режим ставки. После 2022 года накоплено около 237 недель: этого хватает для shrinkage-ковариаций, но не для DRL-политики над многими активами.
- **Режимы.** Ключевая ставка 21% действовала с 28.10.2024 по 06.06.2025, сейчас 14%. Распределение после 2022 года отличается от 2007–2021, поэтому политика, обученная на старой истории, рассчитана на «другой рынок».
- **Мощность** (собственная оценка отчёта 06, проверенная при верификации). Чтобы подтвердить прирост Sharpe на 0,2 у оверлея, коррелированного с базой на 0,9–0,95, нужно около 10–20 лет при мощности около 50% и вдвое больше при мощности 80%. **Прирост от RL невозможно подтвердить на живой истории одного пользователя.** Решение о включении RL принимается по офлайн-протоколу и в shadow-режиме.
- **Серьёзных исследований RL-аллокации мультиактивного портфеля на MOEX не найдено.** Есть только тайминг отдельных инструментов (A3C на фьючерсе RTS, DQN на акциях Яндекса). FinRL и FinRL-X MOEX не поддерживают.

### 3.3. Где RL уместен, а где нет

**Уместен** (низкоразмерно, внутри жёстких границ, итоговые веса всё равно проходят через детерминированный оптимизатор):
1. **Риск-оверлей**: доля рисковой части `k ∈ [k_min, k_max]` по режиму (волатильность, ставка, спреды, сентимент-индекс). В FinRL-X прирост дал именно оверлей. CFA Institute (ноябрь 2025) называет «динамическую риск-ориентированную ребалансировку» главным портфельным применением RL и рекомендует путь offline → sim → shadow mode, плюс жёсткие лимиты, ручное одобрение и kill switch.
2. **Политика «когда торговать»**: ширина no-trade-полосы, «ребалансировать или пропустить неделю». Стартовать нужно с явной полосы и только подстраивать её.
3. **Контекстные бандиты** (RL с горизонтом 1) для ранжирования источников идей входа и персонализации подачи. Награда отложенная: избыточная доходность за 4–8 недель.

**Не уместен:** полный вектор весов для 30–60 бумаг; ЦФА и неликвидные облигации, потому что у них нет истории и ликвидности; оптимизация acceptance rate пользователя (агент начнёт угождать и закреплять поведенческие ошибки).

**Перед RL обязательно** проверить простые правила для `k` (volatility targeting, порог по ставке или сентименту, grid по 1–2 параметрам). Если RL не обыгрывает их в CPCV, он не нужен.

**Дизайн MDP** (если RL всё же делать): в state включать текущие веса (PVM по EIIE, иначе агент «не чувствует» издержки), режимные и агрегированные сентимент-признаки. Действие низкоразмерное: `k`, ширина полосы, сила BL-наклона. Reward — Differential Sharpe Ratio (Moody & Saffell) за вычетом издержек с ограничением CVaR и просадки; двойного учёта издержек избегать. Сеть маленькая (32×32), `gamma` около 0,9, не меньше 10 сидов. Инструменты: Stable-Baselines3 2.9.0 (PPO, затем SAC), Gymnasium; d3rlpy 2.8.1 — для будущего offline RL по логам (последний релиз — 02.03.2025).

### 3.4. Гибриды LLM + RL (2024–2026)

| Паттерн | Пример | Доказательность |
|---|---|---|
| Сентимент в state | HARLF (IJCAI-W 2025), FinRL Contest 2025 | HARLF: около 26% годовых и Sharpe около 1,2 на 2018–2024; переобучение не исключено |
| LLM масштабирует действие и return | FinRL-DeepSeek (февраль 2025) | Множители 0,9–1,1, два прогона, малые и разнонаправленные эффекты. **Не рекомендуется** |
| LLM проектирует state и reward офлайн | GIFT (июнь 2026) | Препринт без чисел в аннотации; интересен для исследовательского трека |
| LLM-стратег + RL-тактик | Darmanin & Vella (FLLM 2025) | Sharpe 1,10 против 0,64 на 6 акциях США, 2018–2020; это тайминг, а не портфель |
| LLM → views → Black–Litterman | arXiv 2504.14345 | Тест 10 месяцев, универсум отобран по капитализации на дату внутри теста (look-ahead и survivorship), тестов значимости нет, Ω — разброс сэмплов LLM |
| Мультиагентная LLM + внешний оптимизатор | FinCon | Архитектурно ближе всего к нашему случаю |

**Look-ahead у LLM-сигналов.** Тест LAP (Gao, Jiang, Yan, https://arxiv.org/abs/2512.23847): на Llama-3.3-70B рост LAP на одно стандартное отклонение усиливает предельный эффект сигнала на 0,067 п.п., это около 32% самостоятельного эффекта. После даты отсечки взаимодействие незначимо. Вывод: бэктест LLM-признака валиден только после даты отсечки модели. Ω для Black–Litterman калибруется по исторической ошибке прогноза, а не по разбросу ответов LLM. Если IC сигнала незначим, view обнуляется.

**Библиотеки** (по PyPI на 09.10.2026):

| Библиотека | Версия | Лицензия | Роль |
|---|---|---|---|

| cvxportfolio | 1.5.1 (06.07.2025) | GPLv3 | Заимствовать идеи моделей издержек, но не код |

**Методы.** Max-Sharpe на выборочных μ не использовать: это тот самый слабый MVO из DRL-статей. Рабочие варианты: Min-Variance или Min-CVaR с shrinkage-ковариацией (Ledoit-Wolf, OAS, Denoise); Risk Budgeting/ERC на стратегическом уровне между классами; HRP/HERC при плохо обусловленной ковариации; Black–Litterman и Entropy Pooling как точка входа для новостей и сигналов (взгляды с явной неопределённостью).

**Двухуровневая мультиактивная схема:**
- **Уровень 1 (стратегический):** ERC или Risk Budgeting по индексам-прокси бакетов. Акции — MCFTR, ОФЗ по срокам — RUGBITR*, корпоративные облигации — RUCBTRNS, а также золото, деньги и ЦФА. Бюджеты риска задаются профилем пользователя.
- **Уровень 2 (внутри бакета):** акции — Min-CVaR/HRP/BL; облигации — правила отбора и cvxpy с ограничениями по дюрации, рейтингу и эмитенту (член `c·|w − w_prev|` порождает no-trade-регион); фонды — look-through по составу; ЦФА — правила и лимиты, hold-to-maturity, ожидаемая доходность равна YTM минус PD×LGD, **ковариационные методы и RL к ЦФА не применять**.

**Политики ребалансировки:**
- Vanguard (декабрь 2024): пороговая политика 200/175 б.п. лучше календарной, +15–22 б.п. в год к ежемесячной.
- Теория no-trade-регионов (Mei, DeMiguel, Nogales 2016; Boyd et al. 2017): если портфель вне региона, торговать нужно только **до его границы**.
- **Гибрид для бота:** еженедельная проверка; сделки только по позициям за пределами полос и только до границы; отсечение мелких сделок; пополнения, купоны и дивиденды в первую очередь направляются в недовесы («бесплатная» ребалансировка).
- **Лоты:** MILP (DiscreteAllocation `lp_portfolio()` с солвером GLPK_MI или собственный в cvxpy) и проверка реализуемости. Если после округления отклонение выходит за полосу, кардинальность снижается.
- **Налоговый слой РФ:** FIFO обязателен (п. 13 ст. 214.1 НК РФ), ЛДВ 3 года, ИИС-3, НДФЛ 13/15%. В целевую функцию добавляется оценка налога при продаже, штраф за продажу лотов «почти под ЛДВ» и бонус за фиксацию убытка в конце года (по мотивам Moehle, Kochenderfer, Boyd, Ang, JOTA 2021). Подробности — в §8.6.

**Обратная связь пользователя** — это сигнал предпочтений (байесовская оценка неприятия риска λ, исключения, налоговые ограничения), а не награда за качество. Качество оценивается по контрфактическому исходу рекомендованного портфеля независимо от того, принял ли его пользователь. Подходящие инструменты: `mabwiser` 2.7.4 (LinTS) или собственная реализация.

### 3.6. Протокол валидации и поэтапный план

- **Статистика:** PBO через CSCV, Deflated Sharpe, PSR/MinTRL (López de Prado и др.). `pypbo` устарел (statsmodels 0.8.0), поэтому PBO лучше реализовать у себя и сверить с R-пакетом `pbo`.
- **Кросс-валидация:** `WalkForward` и `CombinatorialPurgedCV` в skfolio. По умолчанию `purged_size` и `embargo_size` равны 0, их нужно задавать явно: если рекомендация исполняется с задержкой, нужен purge или сдвиг.
- **Минимальный стандарт RL:** 5–10 и больше сидов; отчёт по медиане и межквартильному размаху; все бейзлайны (1/N, inverse-vol, Min-Var и Min-CVaR, ERC, HRP, B&H MCFTR, текущий портфель без ребаланса) прогоняются в той же среде; отдельные стресс-окна (2008, 2014–2015, 2020, 2022, 2024–2025); кривая Sharpe(c) при издержках 0,05 / 0,1 / 0,3 / 0,5%.
- **Поэтапный план** (предложение отчёта 06; пороги нужно утвердить):

| Этап | Содержание | Критерий перехода |
|---|---|---|
| 0. Данные и бэктест | История ISS, корпоративные действия, флаги паузы 2022 года, модель издержек тарифа | Бейзлайны воспроизводимы, тест на look-ahead пройден |
| 1. Baseline-оптимизатор (MVP) | ERC по бакетам, Min-CVaR/HRP в акциях, cvxpy для облигаций, правила для ЦФА, полосы, лоты, налоги | Walk-forward 2010–2026: не хуже 1/N и MCFTR по Sharpe, просадка меньше |
| 2. Views из сигналов | Калибровка IC → BL/EP, Ω по ошибке прогноза, LLM-сигналы только после даты отсечки | Значимый OOS IC, PBO < 0,3, DSR > 0,9 |
| 3. Бандит идей и персонализация | LinTS с отложенной наградой | Off-policy-оценка лучше случайного ранжирования |
| 4. RL-оверлей (исследовательский) | `k`, ширина полосы, сила наклона; PPO, затем SAC | CPCV: ≥70% путей лучше этапа 2 после издержек, PBO < 0,2, затем shadow-режим ≥ 26 недель |
| 5. Offline RL по логам | Через 1–2 года, d3rlpy | Достаточный объём логов |

**Что следует для архитектуры.** Принцип «оптимизатор считает, RL подстраивает, LLM объясняет и даёт сигналы». Контракт между слоями — вектор целевых весов, список сделок, обоснование и риск-отчёт (по образцу weight-centric-контракта FinRL-X). Каждая рекомендация хранит снимок входов и может быть пересчитана. Есть kill switch для отката к базовой политике.

### 4.5. Международные аналоги

- **Wealthfront** (белая книга 09.03.2026): анкета с перевесом консервативной компоненты; MVO на ожидаемой доходности по **Black–Litterman**; ограничения по классам; **пороговая ребалансировка**, при которой дивиденды и входящие деньги в первую очередь направляются в недовесы, а отклонение взвешивается против налоговой стоимости продажи.
- **PortfolioPilot** (RIA, зарегистрирован в SEC): портфельный скор, флаги рисков, «куда вложить следующие $1000»; решение за пользователем. Тарифы $20 / $49 / $99 в месяц.
- **Composer:** стратегия из текста → визуальный редактор → бэктест против бенчмарка с комиссиями и проскальзыванием.
- **Public Alpha:** жёсткий дисклеймер «экспериментальный инструмент, не рекомендация».
- **Robinhood Cortex и Agents** (Agents — 29.09.2026): дайджесты «почему бумага движется» **[частично не проверено]**.
- **RL в потребительских продуктах не обнаружен.** Индустрия использует MVO или Black–Litterman, пороговую ребалансировку и ML-прогнозы.

### 5.4. Токены

| Тип | Права | Для агента |
|---|---|---|
| **Read-only** | Портфель, операции, котировки, справочники | **Основной выбор**: торговые поручения отклоняет брокер, это вторая линия защиты помимо кода |
| Full-access / Transfer | Заявки / плюс переводы | Не нужен / никогда |
| **Токен на конкретный счёт** (уровень прав настраивается) | Один счёт | Принцип минимальных привилегий |
| Sandbox | Только песочница | Тесты |

Токен показывается **один раз**. Срок жизни — **3 месяца с даты последнего использования** (еженедельный агент продлевает его сам). Ошибка `40003` означает недействительный токен. Хранить токен в secret-store, не логировать, не передавать в LLM. Если пользователь прислал токен в чат, сообщение нужно сразу удалить (https://opensource.tbank.ru/invest/invest-contracts/-/blob/master/src/md/intro/intro/token.mdx).

### 5.6. Официальный T-Invest MCP

- Адреса: `https://invest-public-api.tbank.ru/mcp`, песочница `https://sandbox-invest-public-api.tbank.ru/mcp`. Транспорт Streamable HTTP, `Authorization: Bearer <токен T-Invest API>`, модель прав та же (https://developer.tbank.ru/invest/mcp).
- Даты: пост T_InvestAPI в Пульсе — 10.06.2026; доступ всем клиентам — 10.09.2026; разбор на Хабре — 26.09.2026.
- Функции по официальной странице: портфель, операции и налоги, котировки и стаканы, техиндикаторы, **«сводка новостей по эмитентам с оценкой рыночного сентимента»**, **анализ прогнозов инвестдомов** (включая поиск аналитиков, чьи прогнозы сбывались чаще, и «необычных изменений»), сигналы, инсайдеры, фундаментал, выплаты, а при полном доступе — заявки и переводы.
- Клиенты: Claude Code, Cursor, Qwen Code, Gemini CLI, VS Code, ChatGPT Desktop, Claude Desktop (через `npx mcp-remote`); официальные гайды по Hermes Agent (Telegram) и n8n.
- Имена инструментов официально не опубликованы, без токена сервер отвечает 401. В стороннем коде встречаются `invest_get_portfolio` и `invest_list_broker_accounts`.
- **Применимость:** источник новостей с сентиментом и инвестидей, которых нет в gRPC, — как дополнительный инструмент LLM-аналитика с маркировкой «внешний текст». Основной канал данных — gRPC SDK (детерминированность, типы, лимиты, кэш).

### 5.7. Сеть и TLS

- Документация утверждает, что «чёрных списков нет», но требует сертификаты НУЦ Минцифры. Цепочка: `*.tbank.ru → Russian Trusted Sub CA → Russian Trusted Root CA`. Для Python SDK есть `SSL_TBANK_VERIFY=True`. Индекс пакетов `opensource.tbank.ru` подписан той же цепочкой.
- Эмпирика 09.10.2026: из NL-хостинга (Амстердам, AS216139) TCP к API **не устанавливается**, из GB-сети (Лондон, AS204044) API **доступен**. Достижимость зависит от сети хостера, самый надёжный вариант — российский IP.
- Публичное ПО для широкого круга пользователей требует регистрации `appname` через `invest-public-api@tbank.ru`. Для личного бота это не нужно, но рекомендуется заголовок `x-app-name`.

| ЦФА | `Dfas`, `DfaBy`, смарт-счёт, операции | Ежедневно |

**Что следует для архитектуры.** Источник №1 — асинхронный gRPC SDK с зафиксированной версией (vendoring wheel). Над ним — анти-коррупционный слой: свои модели, `Decimal`, UTC, явные типы идентификаторов, пересчёт цен облигаций из процентов номинала. Режим «только чтение» на трёх уровнях: read-only-токен, проверка `access_level` при старте, отсутствие торговых методов в адаптере. Компонент коннектора размещается на российском IP с корнем Минцифры в trust store. Перед выдачей идей работает фильтр допустимости: квал, тесты, ИИС, ликвидность, `buy_available_flag`. Собственная копия истории хранится с первого дня.

**Что следует для архитектуры.** Слой Market Data строится как адаптеры с приоритетным списком провайдеров и failover на пустой или нулевой ответ. Нужна мастер-таблица идентификаторов (ISIN, SECID + `primary_boardid`, FIGI/UID/asset_uid, `ticker@MIC`) и модуль качества данных: `0 → NULL`, сплиты, сверка ISS ↔ T-Invest, контрактные тесты схем ISS (биржа монетизирует бесплатные блоки). Вместо онлайн-опроса — планировщик. Нужен реестр источников с health-check: доля новых элементов за опрос показывает «пробитие» ленты. Каждому источнику задаётся сетевой выход `egress` (RU или foreign) и флаг `tos_ml_allowed`.

## 7. Сентимент-анализ русскоязычных финансовых текстов

Источник раздела: [04-nlp-sentiment.md](research/04-nlp-sentiment.md), дополнения из [03](research/03-news-and-social-sources.md) и [11](research/11-signals-and-evaluation.md).

### 7.1. Какие NLP-задачи реально нужны агенту

| № | Задача | Ценность |
|---|---|---|
| T1 | Сбор и нормализация, **`first_seen_at`** | Основа корректности во времени |
| T2 | Дедупликация и кластеризация сюжетов | Не считать один факт 30 раз (репосты) |
| T3 | **Связывание с тикерами и эмитентами** | Привязка к портфелю: эмитент → все его бумаги |
| T4 | Фильтр релевантности, рекламы и слухов | Экономия перед LLM |
| T5 | Тональность к сущности | **Самая шумная и наименее ценная в «чистом» виде** |
| T6 | **Извлечение событий** | Объяснимые алерты, признаки |
| T7 | **Агрегация в метрики** (sentiment, buzz, novelty, dispersion, z-score) | Вход рекомендательного модуля и RL |
| T8 | Суммаризация для бота | UX и обоснование |

Наибольшую практическую пользу дают T3, T6 и T7.

**Готовой русской «FinBERT» промышленного качества нет.** Ни одна модель не обучена на тональности к сущности (targeted sentiment). В заголовке «X выкупает долю Y с дисконтом» тон для X и Y разный.

**Датасеты:** RuSentNE-2023 (тональность к сущностям в новостях, MIT; лучший публичный бенчмарк), RuSentiment (κ = 0,58 даже у людей), FiNeS (532 заголовка, 2022), Russian Financial News (Kaggle: 79 555 статей и свечи 176 акций, 07.2022–08.2024, без меток тональности). **Публичного корпуса «русская финансовая новость → тональность к тикеру → доходность» нет**, его придётся строить самим: LLM-разметка плюс 500–1 000 примеров, проверенных вручную.

### 7.3. Качество LLM на русском

- **RuSentNE-2023** (https://arxiv.org/abs/2305.17679): лучшая дообученная система — 66,67% F1(P,N). ChatGPT в zero-shot — 60,06% (4-е место) на предложениях, машинно переведённых на английский. Нейтральных примеров 72–74%, тональность часто неявная (выражена через действия, а не оценочные слова).
- Rusnachenko и др. (2024): zero-shot LLM примерно равны дообученному BERT-base; Flan-T5-xl с THoR превосходит прежний SOTA.
- RuSentNE-LLM-Benchmark (данные 2024 года): zero-shot F1 40–55%; перевод на английский помогает 16 моделям из 20, но не gpt-4o, Qwen2-7B, Gemma-2-9b-it и Qwen2-0.5B.
- **Публичного бенчмарка финансовой тональности на русском для GigaChat, YandexGPT, T-pro, Qwen3 и DeepSeek не найдено.** Модель выбирается на собственной золотой выборке из 600–1 000 пар «текст × тикер».

### 7.4. Предсказательная сила: эмпирика по MOEX

**Синтез.** Сигнал есть, но он нелинейный и зависит от ликвидности. Внимание (buzz) и расхождение мнений информативны не меньше знака тона. Негатив важнее позитива, поэтому сентимент полезнее как **риск-фильтр и триггер пересмотра**, чем как генератор идей на покупку. Для облигаций и ЦФА нужен событийный, а не тональный подход.

### 7.5. Рекомендуемый пайплайн

**Связывание с тикерами** строится на словаре алиасов, а не на «голом» NER. Каноническая база — справочник T-Invest (эмитент → все бумаги: обыкновенные и привилегированные акции, все выпуски облигаций). Нормализация через pymorphy3/Natasha. Ручные алиасы («Сбер», «Норникель», «ГМК», латиница, серии облигаций). Омонимы («Магнит», «Полюс», «Система») проверяет LLM по контексту. Скоринг релевантности по образцу RavenPack REL: заголовок — 1,0; лид — 0,7; два и более упоминаний — 0,5; одно — 0,2. В сентимент идут только упоминания с релевантностью ≥ 0,5. Для NER на CPU: Natasha/Slovnet (27 МБ, ORG F1 0,72–0,95).

**Дедупликация в три уровня:**
1. SHA-1 нормализованного текста.
2. MinHash LSH (`datasketch`, порог ≈ 0,8) с перепроверкой точным Jaccard.
3. Сюжеты по эмбеддингам за окно 48–72 ч: косинус ≥ 0,88 — тот же сюжет; 0,80–0,88 — продолжение. Пороги нужно калибровать.

Эмбеддинги для CPU: `deepvk/USER-bge-m3` (359M, 8k, Apache-2.0) или `USER2-base` (149M, Matryoshka). Для GPU: `ai-sage/Giga-Embeddings-instruct` (ruMTEB 69,1), `ai-forever/FRIDA`.

**Каскад:**

```
Источники → [S1] ingest + first_seen_at → [S2] дедупликация (SHA1 → MinHash → сюжеты)
 → [S3] связывание (алиасы + лемматизация; спорное → LLM)
 → [S4] правила-события по шаблонам (precision выше, чем у LLM, стоимость нулевая)
 → [S5] Tier-A энкодер (rubert-tiny2 / USER2 → релевантность, реклама, грубый тон)
 → [S6] Tier-B LLM (JSON: событие, тон к тикеру, surprise, magnitude, is_rumor/is_opinion/is_advertising)
     только для: max_prob < 0,85 | бумаги портфеля и watchlist | magnitude ≥ 2
 → [S7] хранилище (Postgres + pgvector; версия модели и промпта в каждой записи)
 → [S8] дневные признаки по тикеру → алерты / недельный дайджест / рекомендательный модуль
```

**Таксономия событий** (закрытый список) — общий язык алертов, объяснений и признаков. Акции: дивиденды (рекомендация или отмена), байбэк, SPO/допэмиссия, отчётность, гайденс, санкции, налоги и регулирование, иски и изъятие, редомициляция и делистинг. Облигации: рейтинговые действия, дефолт или техдефолт, оферта, ковенанты, реструктуризация, новый выпуск. Плюс фонды (комиссии, смена индекса), ЦФА (выпуск, платформа, регулирование) и макро (ставка, курс, нефть). Если событие есть и в API или MOEX, и в тексте, оно получает максимальную уверенность. Событие только из Telegram — потенциальный слух.

**Агрегация** (формулы отчёта 04, стартовые параметры калибруются):
- вес `w_i = r_i · n_i · c_i · q_src · exp(−ln2 · Δt_i / τ½)`;
- сглаженный сентимент с усадкой к нулю `S = Σ w_i s_i / (Σ w_i + k)`;
- buzz — число уникальных сюжетов за 24 ч и его z-score к собственной истории тикера (окно 60–120 дней, минимум 20 наблюдений);
- dispersion; новизна; моментум `S_3d − S_20d`;
- **идиосинкратический сентимент** `S_ticker − β·S_sector`;
- экспертный слой из T-Invest (апсайд консенсуса, ревизии, сигналы);
- соцсетевой слой отдельно от СМИ.

τ½: 1–2 дня для ликвидных акций, 2–5 для второго и третьего эшелона, 5–20 для облигаций и ЦФА. Вес источника `q_src`: официальное раскрытие, MOEX, ЦБ, рейтинговые агентства — 1,0; Интерфакс, ТАСС, РБК, Коммерсантъ, Ведомости — 0,9; брокерская аналитика — 0,7; авторские каналы — 0,5; форумы — 0,2–0,3; реклама (erid) — 0.

**Корректность во времени.** Признаки на дату T строятся только из текстов с `first_seen_at ≤ cutoff(T)` по торговому календарю MOEX. Тексты после окончания сессии относятся к следующему торговому дню. В рекомендательный модуль и RL уходят только агрегированные признаки с лагом ≥ 1 торгового дня. Критичные события по портфелю (дефолт, понижение рейтинга, отмена дивидендов, санкции) — сразу push-алертом.

**Дистилляция.** Первые 1–2 месяца LLM размечает всё релевантное, пользователь правит 500–1 000 примеров кнопками в боте (золотая выборка). Потом на этих данных дообучается rubert-tiny2 или USER2 с головой: «[тикер] [SEP] текст» → тон и тип события. В результате пропадает зависимость от провайдера, модель стабильна во времени, бэктесты воспроизводимы.

### 7.6. Стоимость

1 000 новостей ≈ 1,4 млн входных и 0,15 млн выходных токенов. Это около 50 ₽ на GigaChat Lite в асинхронном режиме (0,0325 ₽ за 1 000 токенов), около 155–310 ₽ на YandexGPT Lite, около $0,3–0,6 на DeepSeek V4.1-Flash. После фильтра к LLM уходит **200–500 текстов в день** (оценка). Месячный бюджет — от сотен рублей до около 10–19 тыс. ₽ на старших моделях (YandexGPT Pro 5.1, GigaChat Max). Локально T-lite-it-2.1 (8B, Apache-2.0): обработка 1 000 новостей занимает минуты на GPU и около 1–2 часов на Apple Silicon (оценка).

### 7.7. Ограничения и ловушки

- **Telegram ToS.** Компромиссный дизайн: Telegram используется только для метрик **без ML** (частоты упоминаний по словарю, всплески, просмотры, скорость). Содержательный NLP — по первоисточникам, на которые указывает всплеск. Флаг `tos_ml_allowed` в реестре источников. LLM-анализ текстов каналов — только как явно включаемая пользователем опция ([03](research/03-news-and-social-sources.md)).
- **Манипуляции и pump-каналы.** ЦБ регулярно выявляет манипулирование, пример — пресс-релиз от 08.10.2026. Всплеск внимания по неликвиду без официального подтверждения — флаг риска, а не возможность.
- **Look-ahead:** используется `first_seen_at`, а не `published_at`; задним числом отредактированные тексты и вечерние обзоры исключаются; LLM знает будущее до своей даты отсечки.
- **Дрейф провайдеров**: версия модели фиксируется в каждой записи, при смене модели — регрессия на золотой выборке.
- **ЦФА**: новостей мало, сентимент-метрики статистически бессмысленны, нужен мониторинг событий эмитента и оператора.

**Что следует для архитектуры.** NLP выделяется в отдельный сервис «текст → признаки и события» с контрактом в виде таблиц (`doc`, `doc_entity`, `doc_event`, `ticker_day_features`). Провайдер LLM сменный, портфель не отправляется зарубежным моделям. События важнее тона. Кнопки обратной связи в боте («согласен / тон неверный») — главный источник золотой выборки.

### 8.2. Акции

- **Сессии** (по анонсам, **не перепроверены по торговому календарю**): с 14.09.2026 основная сессия начинается в 9:00, утренняя — с 6:50, вечерняя — до 23:50. Сессии выходного дня (ДСВД) по акциям с марта 2025 года идут 9:50–19:00, сделки относятся к **следующему торговому дню**. Облигации торгуются в выходные с 28.03.2026 (9:50–18:00). Без ДСВД: 24–25.10 и 28–29.11.2026. В выходные ценовые коридоры уже (около ±3% по данным 2025 года), а оборот — около 7% от будничного.
- **T+1** действует с 31.07.2023. Дату последней покупки под дивиденд **нужно брать из `Dividend.last_buy_date`**, а не вычислять. Рекомендация совета директоров не гарантирует выплату (есть статус `Cancelled`). Налог 13/15%, вычеты к дивидендам не применяются.
- **Режимы и лоты**: основной режим акций — TQBR; там же сейчас и паи БПИФ. Лоты разные (GAZP, GMKN — 10), поэтому лот и шаг цены берутся из API.
- **Эшелоны** (пороги — конфигурация, а не норма): T1 — бумага в MOEXBC и ADV ≥ 1 млрд; T2 — в IMOEX и ADV ≥ 100 млн, лимит 5–7% на бумагу; T3 — ниже, лимит 2–3% и заявка ≤ 5–10% ADV. Уровень листинга слабо отражает ликвидность: MGNT, например, на уровне 3.
- В стресс рекомендация «войти по цене X» может не исполниться из-за ценовых коридоров и дискретных аукционов. Поэтому агент даёт **диапазон и тип заявки (лимитная)**.

### 8.3. Облигации

**Типы ОФЗ** (TQOB, 09.10.2026): ПД (SU26xxx, 31 выпуск), ПК — флоатеры от RUONIA (SU29xxx, 21), ИН — линкеры (4), АД (2), ОФЗ в юанях (3; купон 6–7,65% в CNY).

**Механика**, которую агент обязан учитывать: тип купона (CONSTANT, FLOATING, VARIABLE, …), НКД (цена котируется «чистой» в процентах от номинала), амортизация, put-оферты (заявку на выкуп подают заранее, в окне агента), колл-опционы, субординированные и бессрочные выпуски, замещающие облигации (`BOND_TYPE_REPLACED`), дефолт (`default_date`). **Правило доходности:** для бумаг с офертой или коллом сравнивать доходность к оферте или коллу; для флоатеров — спред к базе, а не YTM; для переменного купона доходность после оферты неизвестна.

**Кредитный цикл:**

| Период | Показатель (методики разные, напрямую не сравниваются) |
|---|---|
| 2025 | 35 эмитентов с первичными техдефолтами против 11 в 2024 году (Эксперт РА, с учётом ЦФА) |
| 1П2026 | 13 новых дефолтных компаний против 8 годом ранее, 4 из них выпускали только ЦФА (АКРА); 21 случай дефолтов и техдефолтов против 24 за весь 2025 год («Известия») |
| III кв. 2026 | «ЕвроТранс»: к началу сентября фактический дефолт по всем выпускам (~27,1 млрд руб., с учётом ЦФА ~36,8 млрд) |
| 26.09.2026 | Доходность AA/AAA ≈ 16%, B/BBB > 30%; из 38 выпусков ВДО с июня по сентябрь полностью размещены 20 |

Отсюда правило: **кредитный фильтр важнее купона**, «дешёвый» спред ВДО по умолчанию трактуется как риск.

**Рейтинги.** Четыре аккредитованных агентства: АКРА `A+(RU)`, Эксперт РА `ruA+`, НКР `A+.ru`, НРА `A+|ru|`. Для риск-модели используется нормализованная порядковая шкала, а для регуляторной проверки — таблица эквивалентов ЦБ: у НРА эквивалент AA- записан как `AA|ru|`. По оценке ЦБ, вероятность дефолта у облигаций от A+ около 1,3%.

**Неквалифицированный инвестор** (пресс-релиз ЦБ от 20.02.2025, https://www.cbr.ru/press/event/?id=23389): без теста доступны ОФЗ, субфедеральные облигации и корпоративные облигации **от A+**, кроме обеспеченных денежными требованиями (для них тест обязателен с 23.05.2025). Ограничение «только фиксированный купон» встречается в СМИ, но в пресс-релизе ЦБ его нет, поэтому **источник истины — `required_tests` выпуска**. Тест нужен для облигаций ниже порога или без рейтинга, структурных, субординированных и бессрочных выпусков, акций вне котировальных списков. Статус квала: имущественный порог 24 млн руб. с 2026 года (7060-У), с 31.08.2026 действует Указание 7402-У (пороги не перепроверены).

### 8.4. Фонды

- **БПИФ** торгуются в TQBR с маркетмейкером, iNAV публикуется в течение дня. Налог возникает только при продаже, ЛДВ применима. **ОПИФ** погашаются по СЧА с задержкой в несколько дней. **ЗПИФ** часто торгуются с дисконтом к редко публикуемой СЧА; неквалы с 2025 года могут покупать часть ЗПИФ без теста.
- **Фонды денежного рынка** — «кэш-слив» портфеля: размещают средства в РЕПО с ЦК, доходность ≈ RUONIA минус расходы. Самые ликвидные на 09.10.2026: AKMM, SBMM, LQDT, BCSD. Есть юаневые CNYM и AMNY. ### 8.7. Сводные правила для агента (чек-листы в коде)

Профиль пользователя содержит: `is_qual`, `passed_tests[]`, счета (брокерский или ИИС-3, дата открытия), ставку НДФЛ, реализованный доход с начала года, **использованный лимит ЦФА по каждому оператору**, тариф. Перед любой рекомендацией rule engine проверяет:

- **доступность**: `for_qual_investor_flag`, `required_tests ⊆ passed_tests`, `for_iis_flag`, `buy_available_flag`;
- **ликвидность**: ADV, спред, размер позиции ≤ k·ADV, эшелон;
- **лот и шаг цены**;
- **события**: `last_buy_date` ≤ N дней, статус дивиденда, отчётность в горизонте 2 недель, оферта в ближайшие 30 дней (напоминание о заявке), заседание ЦБ, выходные без ДСВД;
- **облигации**: рейтинг, тип купона, дата расчёта доходности (минимум из погашения, оферты и колла), амортизация, субординация, валюта номинала, G-спред против медианы рейтинговой группы;
- **ЦФА**: классификация по 7176-У, лимит по оператору, премия к облигациям эмитента, вторичная ликвидность;
- **концентрация**: эмитент суммарно по акциям, облигациям и ЦФА; сектор; класс;
- **налоги** (§8.6) и **маркировка** «неполное раскрытие».

LLM только объясняет результат проверок: агент советует, но не выдумывает ограничения.

## 9. Сигналы и методология оценки рекомендаций

Источник раздела: [11-signals-and-evaluation.md](research/11-signals-and-evaluation.md), дополнения из [05](research/05-llm-financial-agents.md) и [06](research/06-rl-and-portfolio-optimization.md).

### 9.1. Доказательная база по факторам

- **Международная и EM-эмпирика задаёт только априорные ожидания.** Моментум существует, но подвержен крахам (Jegadeesh & Titman 1993; Asness, Moskowitz, Pedersen 2013; Daniel & Moskowitz 2016, https://doi.org/10.1016/j.jfineco.2015.12.002). Тайм-серийный моментум устойчив на индексах и классах активов (https://doi.org/10.1016/j.jfineco.2011.11.003). Эффект низкой волатильности наблюдается и на EM (Blitz и др. 2013). Carry работает во всех классах активов (https://doi.org/10.1016/j.jfineco.2017.11.002).
- **Аномалии хрупкие.** Порог t ≈ 3, а не 2 (Harvey, Liu, Zhu 2016, https://doi.org/10.1093/rfs/hhv059). Большая часть аномалий не воспроизводится (Hou, Xue, Zhang 2020) и слабеет после публикации (McLean & Pontiff 2016). Технические правила теряют значимость после поправки на data snooping (Sullivan, Timmermann, White 1999; White 2000).
- **По MOEX проверенных работ о кросс-секционных факторных премиях за 2015–2026 годы в этой сессии не найдено.** Найденные работы касаются смежных тем: сентимент (§7.4), обратный американскому знак эффекта рычага в премии за риск (Trifonov 2023), концентрация оборота значима только в хвосте волатильности (Terentev & Vetoshkina 2026), RVI влияет на кредитные спреды (Patlasov 2024), отклонение БПИФ от СЧА связано с волатильностью и курсом (Andrianova & Petkov 2026). Все факторные эффекты для MOEX считаются гипотезами, которые нужно проверить на собственных PIT-данных.
- **Структура MOEX.** В TQBR 512 бумаг, из них 117 БПИФ; ликвидных акций около сотни. Квантильные портфели получаются по 10–20 бумаг. Нефтегаз и банки доминируют, поэтому нужна секторная нейтрализация. Чистых факторных индексов нет, есть MVBI, ICALM (с 01.10.2026), RUGROW, MIPO.
- **Мощность** (верифицированные расчёты): при недельном IC = 0,05 и σ_IC = 0,15–0,25 для t = 3 нужно 81–225 недель при мощности около 50% и 133–369 недель при 80%. Hit rate 55% против 50% требует около **782** независимых рекомендаций (около 3 лет при 5 в неделю). Годовой SR = 0,5 портфеля подтверждается примерно за 16 лет при мощности около 50% и за 31–32 года при 80%. **Вывод: доказывать полезность агента нужно через IC сигналов, калибровку вероятностей и дисциплину процесса, а не через P&L портфеля за 1–2 года.**

### 9.2. Набор сигналов по классам

| Класс | Сигналы |
|---|---|

Прогнозная дивидендная доходность и стабильность выплат (R, H/W). Value, секторно-нейтральный (R, W: фундаментал — только снимки). ### 9.3. Облигации: relative value

ISS отдаёт бесплатно `EFFECTIVEYIELD`, `DURATION`, `ZSPREADBP`, **`GSPREADBP`**, `YIELDTOOFFER` (например, у ОФЗ 26238 на 09.10.2026 `GSPREADBP` = −11, то есть бумага «дороже» кривой). КБД в ISS — модель Нельсона–Сигеля с 9 гауссовыми поправками (параметры B1–B3, T1, G1–G9; **не** Свенссон), история с 06.01.2014; у ЦБ — с 04.01.2003.

Ожидаемая избыточная доходность облигации на горизонте h при неизменной кривой:

`E[R_i − r_f·h] ≈ (y_i − r_f)·h + D_i·(G(D_i) − G(D_i − h)) − PD_i·LGD_i·h − c_i`

где первое слагаемое — carry, второе — roll-down, третье — ожидаемые кредитные потери (PD и LGD — параметры, допущения), `c_i` — издержки. Breakeven = `(carry + roll)/D` показывает, на сколько может вырасти доходность, прежде чем позиция уйдёт в минус. Кредитные факторы работают как **жёсткие фильтры** (рейтинг ниже политики, дефолт в группе, тесты) и **штрафы** (понижение рейтинга или статус «на пересмотре», расширение спреда выше 90-го перцентиля группы, отсутствие отчётности). Облигационный блок — **самый механический и надёжный**, его логично делать первым.

### 9.4. Режим рынка

Признаки (недельная частота): фаза цикла ставки, `G(1y) − КС` (около −0,3 п.п. на 09.10.2026), наклон `G(10y) − G(1y)`; реализованная волатильность MCFTR и RVI; MCFTR против MA(200) и просадка; медианный G-спред бакетов AA и A; концентрация оборота. Для MVP — 3–4 дискретных режима по порогам. Если нужны вероятностные режимы — `statsmodels` MarkovRegression (hmmlearn в режиме ограниченного сопровождения), **только `filtered_*`-вероятности** (сглаженные — прямой look-ahead) с переоценкой на расширяющемся окне. Режим задаёт множители весов сигналов и ширину no-trade-полос, **направление рынка он не прогнозирует**.

### 9.5. Конвейер ранжирования и план входа

```
PIT-вселенная (доступность, ликвидность, профиль)
 → сырые сигналы по классу → винзоризация 1/99%, rank-gauss, секторная нейтрализация
 → композит Σ w_k·z_k: веса по OOS IC со шринкажем к равным (λ = T/(T+T0), T0 ≈ 52 нед.),
   не больше 40% на один сигнал, автоотключение при IC<0 и t<−2 на 52 неделях, множители режима
 → альфа по Гринольду α_i = IC·σ_i(h)·z_i  (https://doi.org/10.3905/jpm.1989.409211)
 → чистая альфа: α_i − c_i (комиссия тарифа ×2 + спред + проскальзывание [+ налог])
 → неопределённость: квантильная модель → CQR → ACI; калиброванная P(R_i − R_bench > 0)
 → портфельная проверка (лимиты эмитента, сектора, класса)
 → план входа: лимитная зона, срок действия, инвалидация, горизонт, бенчмарк
 → LLM: только объяснение и проверка новостного фона
```

- **Порог издержек обязателен и зависит от тарифа.** Пример из отчёта 11: при IC = 0,05, σ = 8% за 4 недели и z = 2 ожидаемая избыточная доходность около 0,8%. На тарифе 0,05% круговые издержки около 0,2%, идея проходит порог. На тарифе 0,3% издержки около 0,7%, и идея почти съедена.
- **Конформные интервалы:** CQR (https://arxiv.org/abs/1905.03222) и ACI (https://arxiv.org/abs/2106.00170) дают онлайн-адаптацию к сдвигу распределения с задержкой меток на h недель. MAPIE 1.5.0 — с версии v1 API изменился; ACI проще написать самим (~20 строк). Вероятности калибруются изотонической регрессией, качество — Brier и reliability.
- **Консенсус аналитиков** полезнее через **ревизии и разброс**, чем через «потенциал до таргета», который систематически оптимистичен. API отдаёт только текущее состояние, поэтому **ежедневные снимки сохраняются с первого дня**; до 52+ недель снимков вес консенсуса нулевой или априорный. Архив `GetSignals` — бесплатный бенчмарк «экспертного» качества.
- **Вход и инвалидация.** Акции и фонды: лимитная зона `[close − k·ATR20, close]`, срок 1–2 недели; инвалидация по закрытию ниже `min(entry − m·ATR, MA200·(1−δ))` или по тезису (отмена дивиденда, понижение консенсуса, негативное событие). Облигации: целевая доходность `y ≥ G(D) + медиана спреда группы + m·MAD`, пересчитанная в цену; срок 2–4 недели; инвалидация — расширение спреда выше p90 группы, понижение рейтинга, техдефолт в группе. Параметры `k`, `m`, `δ` подбираются **один раз на класс** и фиксируются в версии конфигурации.
- **Технические индикаторы** — фильтры тайминга и риска (режим, зона входа, перегрев, ликвидность), а не ядро ранжирования. Считать их лучше самим с тестами против TA-Lib 0.8.1 (колёса с C-библиотекой); для инкрементальных алертов подходит talipp. **pandas-ta не брать**: репозиторий на GitHub недоступен, на PyPI только пре-релизы.

### 9.7. Ловушки данных (закрыть до первого бэктеста)

- **Survivorship:** ISS `listing` отдаёт `history_from`/`history_till`, в том числе по делистингованным бумагам (пагинация не подтверждена). T-Invest теряет историю старого инструмента после корпоративного действия, поэтому для истории первичен ISS.
- **Корпоративные действия:** сплиты и консолидации (например, BELU 2024, 1:8), смена тикеров и редомициляция (склейка по экономической сущности), массовые отмены дивидендов в 2022 году.
- **Смена режима БПИФ TQTF → TQBR.** Отчёт 11 указывает дату 22.06.2026 (не перепроверено), отчёты 02 и 07 видят БПИФ в TQBR. Режим не хардкодить, брать из `boards[is_primary=1]`.
- **Разрыв 2022 года:** с 28.02 по 23.03.2022 торгов акциями не было, 24.03 торговали 33 бумаги (https://www.vedomosti.ru/finance/articles/2022/03/24/914953-moskovskaya-birzha-vozobnovila-torgi), ОФЗ — с 21.03. В бэктесте позиции замораживаются, доходность начисляется скачком. Подпериоды для проверки устойчивости: 2013–2017, 2018 – 02.2022, 03.2022–2023, 2024–2026; знак IC должен совпадать минимум в трёх из четырёх.
- **PIT фундаментала и консенсуса отсутствует.** Бэктест value, quality и консенсус-сигналов по текущим снимкам — прямой look-ahead. Такие сигналы идут только форвардом.
- **Календарь:** `exchange_calendars` (XMOS) вероятно не отражает выходные сессии и паузы. Источник истины — фактические торговые дни из ISS и T-Invest, свечи с `CANDLE_SOURCE_EXCHANGE`.

### 9.8. Оценка рекомендаций

**Принципы журнала:** (1) **предрегистрация** — запись с хэшем снимка, версией конфигурации, моделью и датой её отсечки, горизонтом и бенчмарком создаётся до отправки пользователю (append-only); (2) оцениваются **все** действия, включая avoid и trim; (3) оценка **не зависит от того, исполнил ли пользователь** рекомендацию — используется бумажное исполнение, а фактические сделки анализируются отдельно; (4) те же правила применяются к сигналам брокера, консенсусу и простым бейзлайнам, чтобы понять, добавляет ли агент что-то сверх бесплатных альтернатив.

**Бумажное исполнение:** лимитная зона исполняется в первый день, когда `low ≤ H`, по цене `min(open, H)` + ½ спреда (для облигаций и неликвида дополнительно требуются сделки и `VWAP ≤ H`). Не исполнено к сроку — статус `expired` и отдельная метрика «упущенной выгоды». Инвалидация — выход на открытии следующего дня. Доход за время удержания учитывается через TR-ряды. Основная метрика считается до налогов, вспомогательная — после.

**Бенчмарки по классам:**

| Класс | Бенчмарк | История |
|---|---|---|
| Акции | **MCFTR** (IMOEX без дивидендов для оценки не годится); MCFTRR — для чувствительности | С 26.02.2003 |
| ОФЗ | **RGBITR**; RUGBITR1Y…10Y — бакет той же дюрации; RUFLGBITR — флоатеры | С 30.12.2002; RUFLGBITR — с 30.12.2022 |
| Корпоративные облигации / ВДО | **RUCBTRNS** / RUCBHYTR | С 29.12.2018 / не проверено |
| Кэш | LQDT (раньше — RUONIA) | С 22.07.2022 |
| ЦФА | RUCBTRNS или «КС + спред бакета» | Только на уровне портфеля |
| Портфель | **Policy benchmark**: стратегические веса × индексы классов, ребаланс раз в квартал | — |

**Метрики:**
- рекомендации: hit rate **только вместе с payoff ratio и expectancy**, средняя и медианная избыточная доходность после издержек, MAE/MFE, fill rate (ориентир 40–80%);
- сигналы: rank IC и его затухание на 1/4/12/26 неделях, спред терцилей;
- вероятности: Brier и Brier skill score, reliability и ECE;
- интервалы: покрытие (номинал ± 5–10 п.п.), ширина, interval score / CRPS;
- портфель: избыточная доходность и IR к policy benchmark, MDD, CVaR 95%, оборот, атрибуция по Бринсону;
- процесс: свежесть данных, доля ошибок схемы LLM.

**Статистика:** t-статистики Ньюи–Уэста при перекрывающихся горизонтах; стационарный блочный бутстрап **по неделям** (идеи одной недели — фактически одна ставка на рынок); Diebold–Mariano против бейзлайнов; DSR и PBO с честным числом вариантов; CUSUM по IC в live с порогами, зафиксированными до запуска.

**LLM-специфика.** Компоненты делятся на детерминированные (бэктест на всей истории допустим) и LLM-зависимые (оценка только после даты отсечки или форвардом). Для дат до отсечки нужны анонимизация эмитента и LAP-тест; если LAP значим, признак не используется. Русскоязычных PIT-LLM нет: ChronoGPT и DatedGPT англоязычные. В replay LLM получает данные только через инструменты с `as_of`, веб-поиск запрещён. При смене модели форвардная история начинается заново. **Shadow-режим не меньше 26 недель** — до того, как признак получит вес.

**Отчёт пользователю** — честный scorecard с доверительными интервалами и пометкой «статистически не подтверждено», пока CI включает 0. Обещания «агент обыгрывает рынок» в нём нет.

### 9.9. Протокол оценки (пороги предложены, утвердить)

| Этап | Что делаем | Критерий перехода |
|---|---|---|
| A. Данные | PIT-вселенная, TR-ряды, облигационные потоки, автотесты | Сверка TR с MCFTR и RGBITR в допуске |
| B. Сигналы (история) | Только детерминированные; IC 1/4/12 недель, t(NW), подпериоды, режимы | t > 3 (или > 2 при сильном априорном аргументе); знак IC совпадает в ≥ 3 из 4 подпериодов |
| C. Стратегия (история) | Walk-forward с издержками; бейзлайны 1/N, inverse-vol, MCFTR B&H, policy benchmark, текущий портфель | Не хуже бейзлайнов по IR после издержек; DSR > 0,9; PBO < 0,3 |
| D. Shadow (форвард) | Полный цикл с журналом; первая оценка LLM-признаков | ≥ 26 недель; покрытие в пределах номинал ± 10 п.п.; BSS ≥ 0 |
| E. Production | Еженедельный scorecard, автоотключение сигналов, ежеквартальная перекалибровка | Тревоги по IC, ECE, покрытию и просадке |
| F. Мета-уровень (бандит / RL) | Адаптация весов источников и полос | Только после ≥ 52 недель журнала |

**Что следует для архитектуры.** Исследовательский контур (Research Lab) — часть продукта: PIT feature store с `as_of`, IC-отчёты, реестр конфигураций. Модули ядра (по отчёту 11): `UniverseBuilder`, `TRSeriesBuilder`, `BondAnalytics`, `RegimeService`, `SignalEngine`, `Ranker`, `EntryPlanner`, `RecommendationJournal`, `PaperBroker`, `Evaluator`, `LLMExplainer`. Снимки «текущих» данных — фундаментал, консенсус, `interested_count`, рейтинги — сохраняются ежедневно с первого дня. LLM не влияет на числовой скоринг, пока его признаки не прошли форвардную оценку.

### 10.3. UX-паттерны

**Каналы внутри Telegram:** постоянная reply-клавиатура (`📊 Портфель · 🗓 Отчёт · 💡 Идеи / 🔔 Алерты · 💬 Спросить · ⚙️ Ещё`), команды в области видимости чата владельца, свободный текст как вопрос аналитику, опционально — топики.

**Команды:** `/start`, `/portfolio`, `/report`, `/ideas`, `/watchlist`, `/invest` (распределить пополнение), `/ips` (профиль и цели), `/import`, `/alerts`, `/journal`, `/ask`, `/status`, `/settings`, `/help`.

**Ключевые сценарии:**
- **Онбординг в 3 шага**: портфель (импорт из T-Invest или вручную), профиль и цели, расписание. Read-only-токен на один счёт вводится не в чат, а через секреты сервера или Mini App.
- **Ручное редактирование** через мастер aiogram-dialog: класс → поиск по справочнику → количество (кратность лоту) → цена и дата (нужны для налогов и ЛДВ) → счёт → подтверждение. **Отдельная форма ЦФА**: эмитент, оператор, тип, номинал × количество, ставка и периодичность, погашение, вторичный рынок. **Импорт из T-Invest — всегда через diff-превью**, ручные позиции (ЦФА) при этом не затрагиваются. Импорт CSV или XLSX — по шаблону.
- **Мастер IPS** (9 шагов: цель, горизонт, доля сбережений, реакция на −20%, допустимая просадка, денежный поток, опыт и квал, ограничения, правила ребалансировки). IPS версионируется, каждый отчёт ссылается на `ips_version`.
- **Недельный отчёт:** сообщение 1 — rich-сводка по принципу перевёрнутой пирамиды (вердикт → что произошло → таблица действий → издержки и налог → `<details>` «Почему так» → дисклеймер → кнопки «Принять всё / Отложить / Пропустить / Разобрать по одному»); сообщение 2 — альбом из 2–3 PNG; при разборе по одному — карточка на каждое действие с кнопкой `copy_text` «Скопировать заявку» для ручного ввода в приложении брокера.
- **Жизненный цикл действия:** `DRAFT → SENT → PENDING → ACCEPTED → EXECUTED / NOT_EXECUTED`, а также `POSTPONED`, `SKIPPED(reason)`, `EXPIRED`. При «Пропустить» бот спрашивает причину в один тап («не согласен», «нет денег», «налоги и срок владения»…) — ценнейший сигнал обратной связи. Исполнение подтверждается автосопоставлением с операциями T-Invest. Журнал хранится в таблицах `rebalance_report`, `rebalance_action`, `decision`, `execution`.
- **Лента идей**: карточка со скорингом, уверенностью, «влиянием на портфель» и кнопками «Почему? / Подробнее / В watchlist / Скрыть (с причиной)». Идеи не рассылаются push, а показываются по запросу и блоком «Топ-3» в недельном отчёте.
- **Алерты**: отклонение от коридора, цена из watchlist, резкая смена сентимента, события (купоны, отсечки, оферты, ЦФА), тихие часы, лимит в день, дедупликация в Redis. Каждый алерт объясняет, что случилось, почему это важно **для вашего портфеля** и что можно сделать.
- **Q&A**: стриминг с кнопкой «Стоп». Цифры только из инструментов, ссылки сносками, лимит токенов в сутки.
- **`/status`** (свежесть данных, срок токена, туннель) и **`/journal`** (принято, исполнено, качество рекомендаций).

**Лучшие практики финансового отчёта в чате:** перевёрнутая пирамида; один экран сводки (800–1 200 символов); единый формат чисел (неразрывный пробел, знак изменения, отклонения в п.п.); цвет только для фактов, а не для призывов к действию (не красить «Принять» в зелёный, без «геймификации»); указание свежести и происхождения данных; объяснимость каждого действия и вариант «если ничего не делать»; издержки и налог рядом с продажами; короткий дисклеймер; режим приватности (рубли под спойлером, `protect_content=True`); идемпотентность кнопок; тишина по умолчанию.

### 10.4. Mini App, графики, расписание

- **Mini App — фаза 2.** Для одного пользователя чат, aiogram-dialog и rich messages покрывают около 90% сценариев. Mini App нужен для массового редактирования целевых долей и интерактивных графиков. Стек: Vite + React 19 + **@tma.js/sdk 3.x** (пакеты `@telegram-apps/*` не обновляются, `init-data-node` объявлен устаревшим) + **lightweight-charts 5.2.1** (Apache-2.0, атрибуция TradingView обязательна) + FastAPI с HMAC-проверкой `initData`. `safe_parse_webapp_init_data` в aiogram не проверяет срок `auth_date`, это нужно делать самим. Mini App стоит строить как SPA, которое работает и вне Telegram (запасной канал).
- **Графики:** серверный PNG через matplotlib (OO API, Agg) в отдельном потоке, кэш `file_id`. mplfinance не обновлялся с 2023 года, kaleido ≥ 1.0 требует Chrome — не закладываться на них.
- **Планировщик:** MVP — APScheduler 3.11 в процессе (4.0 всё ещё alpha) с `SQLAlchemyJobStore`; при росте — Taskiq 0.13 + Redis, **scheduler строго в одном экземпляре**. Типовое расписание: синхронизация утром, новости каждые 15–60 минут, сканер алертов каждые 1–5 минут в торговые часы, недельный отчёт (например, в субботу в 10:00), health-check каждый час.

### 10.5. Безопасность

Whitelist по `user_id` во внешнем middleware (чужим не отвечать); команды только в области видимости владельца; read-only-токен на один счёт вне чата (секреты сервера, AES-256-GCM в БД, ключ вне БД); фильтр логов от токенов; в LLM-промптах нет номеров счетов и ФИО; `protect_content`. Переписка с ботом **не шифруется сквозным шифрованием**. Мониторинг ошибки `40003`.

### 10.6. Запасные каналы

| Канал | Плюсы | Минусы |
|---|---|---|
| Mini App как PWA | Тот же фронтенд, доступ из браузера | Своя аутентификация, домен должен быть доступен |
| E-mail-дайджест | Просто и надёжно | Нет интерактивных кнопок |
| **MAX** (VK) Bot API (`platform-api2.max.ru`) | Работает в РФ без VPN | **Создать бота могут только юрлица, ИП и самозанятые — резиденты РФ**, с верификацией и модерацией (https://dev.max.ru/docs); вопросы приватности (СОРМ); санкции ЕС против VK |

**Что следует для архитектуры.** Канал — сменный адаптер: ядро формирует доменные объекты (`PortfolioView`, `WeeklyReport`, `Idea`, `Alert`, `Answer`), рендерер Telegram превращает их в rich messages, PNG и клавиатуры. Есть второй рендерер (веб или e-mail) и fallback-рендерер на случай проблем с rich-сообщениями. Журнал решений — сущность первого класса. Детерминированное ядро: при недоступности LLM отчёт уходит «сухим». Все даты событий передаются через `date_time`.

### 11.2. Эксплуатация LLM-слоя

- **Единый OpenAI-совместимый адаптер** (PydanticAI 2.54.0 или собственный на `openai` SDK с `max_retries=0`) и реестр провайдеров в YAML: цепочки fallback, circuit breaker, семафоры под квоты, месячный лимит в ₽ на провайдера, **флаг резидентности по модели** (`external_models`), слой обезличивания для не-RU моделей. Финальный структурированный вывод оформляется вызовом инструмента `submit_*` — это обходит несовместимость `tools` и `response_format` у Yandex. Агентный цикл должен уметь работать последовательно, потому что GigaChat делает один вызов функции за ответ. LiteLLM 1.104.2 в библиотечном режиме допустим, отдельный прокси избыточен.
- **Наблюдаемость:** OpenTelemetry → **Arize Phoenix** 20.20.0 (ELv2, один сервис, SQLite или Postgres) плюс собственная таблица `llm_calls` (модель, промпт, токены, ₽, латентность). Langfuse v4 требует ≥ 4 vCPU и 16 ГБ RAM (Postgres + ClickHouse + Redis + S3), это тяжело для маленького VPS. Облачный трейсинг не использовать, потому что трассы содержат портфель. GenAI-конвенции OTel пока нестабильны: писать `gen_ai.*` и дублировать бизнес-атрибуты в `app.*`.
- **Версионирование промптов в git** (`prompts/<id>/<version>.j2` + `meta.yaml`). У каждой рекомендации есть `snapshot_id`, `prompt_version`, `model` и сырой ответ.
- **Evals:** золотая разметка новостей (macro-F1), **фактическая верность чисел — жёсткий гейт с нулём расхождений** в runtime и CI, tool-calling-сценарии, compliance (дисклеймер, нет «гарантированной доходности», нет бумаг, недоступных неквалу), попарное LLM-as-judge другой моделью. Инструменты: собственный pytest-харнесс или promptfoo.
- **Экономия:** кэш данных; кэш ответов LLM по ключу `(role, model, prompt_version, sha256(...))`; кэш промптов у провайдера (статичный префикс первым); асинхронный и batch-режимы; отсев до LLM.
- **Надёжность:** фиксировать точные id моделей; режим деградации, при котором без LLM уходит числовой отчёт; ежедневный health-check провайдеров.

**Безопасность эксплуатации:** токен T-Invest только на чтение; секреты вне git (Docker secrets или sops+age); SSH только по ключам, наружу открыт только SSH; UI Phoenix доступен через SSH-туннель; шифрование «в покое» (Bot Developer Terms Telegram этого требуют); ежедневный зашифрованный `pg_dump` в S3 в РФ; обезличивание для любой не-RU модели; внешний текст помечается как данные.

### 11.5. Правовые аспекты

> Обзор для проектирования, а не юридическая консультация.

**39-ФЗ «О рынке ценных бумаг»** (ред. от 04.08.2026, https://legalacts.ru/doc/federalnyi-zakon-ot-22041996-n-39-fz-o/):
- **ст. 6.1** — инвестиционное консультирование это **услуга клиенту по договору** через индивидуальные инвестиционные рекомендации (ИИР). Оказывать её могут только ЮЛ или ИП, состоящие в СРО и включённые в реестр ЦБ. Признаки ИИР может устанавливать базовый стандарт СРО;
- **ст. 6.2** — ИИР даётся с учётом инвестпрофиля (доходность, срок, риск); **ч. 6: если ИИР предоставляются с помощью программ для ЭВМ, программа подлежит аккредитации** (ЦБ может передать эти полномочия СРО);
- **статьи 6.3 в действующей редакции нет**. Единый реестр инвестсоветников ЦБ существует (файл от 09.10.2026), реестра аккредитованных программ на странице реестров ЦБ нет. Кто аккредитует программы (НАУФОР) — не проверено.

**152-ФЗ:** ч. 2 ст. 1 — закон не распространяется на обработку физлицом **исключительно для личных и семейных нужд**. Для других пользователей возникают обязанности оператора, включая **локализацию баз в РФ** (ч. 5 ст. 18). Трансграничная передача (ст. 12) в этой сессии не проверялась.

**Сценарии:**

| Сценарий | Вывод |
|---|---|
| **1. Только для себя** (self-hosted, мой портфель, мой токен) | **Допустимо**: нет клиента и услуги, исключение «личных нужд» по 152-ФЗ, данные ISS с задержкой используются лично. Нужно сохранять human-in-the-loop, автосделок нет |
| 2. Бот для 2–5 друзей или семьи | **Серая зона**: адресные рекомендации конкретным людям по существу похожи на ИИР, для друзей вы становитесь оператором ПД; показ котировок третьим лицам требует договора с биржей; GigaChat п. 6.2. Лучше open-source или self-host — каждый запускает свой экземпляр со своим токеном |
| 3. Платный или публичный бот с персональными рекомендациями | Инвестиционное консультирование: ЮЛ или ИП, СРО, реестр ЦБ, инвестпрофиль, форма ИИР, **аккредитация программы**; полный набор обязанностей оператора ПД; договоры с биржей и СМИ |
| 4. Публичный канал с общей аналитикой без учёта портфеля | Вероятно, не ИИР (зависит от признаков базового стандарта, не проверено); остаются риски по законодательству о манипулировании |

**Прочее:**
- Telegram Bot Developer Terms: privacy policy, минимизация данных, удаление по запросу, **шифрование в покое с ключом отдельно**, запрет скрейпинга для ИИ.
- Telegram API ToS п. 1.5 (см. §6.6, §7.7).
- VPN: прямого запрета для физлица не найдено; правовой статус серверного туннеля к `api.telegram.org` — **серая зона**, рекламировать и распространять такое решение нельзя.
- T-Invest: для публичного ПО нужна регистрация `appname`.
- СМИ: хранить и показывать резюме со ссылкой.

**Рекомендуемый дисклеймер** (под каждым сообщением с рекомендацией): «Аналитический материал сформирован автоматически программой для личного использования её владельцем с применением ИИ (модель: {model}). Не является индивидуальной инвестиционной рекомендацией, офертой или предложением услуг. Решение о сделках принимаете вы. Доходность в прошлом не гарантирует доходности в будущем. Данные могут быть неполными или задержанными (котировки MOEX — до 15 минут).» В многопользовательском сценарии дисклеймер **не превращает** персональную рекомендацию в «не-ИИР»: регулятор оценивает существо, а не подпись.

**Что следует для архитектуры.** Правовой режим фиксируется в конфиге (`deployment_mode: personal`): whitelist владельца, без регистрации других пользователей, дисклеймер и раскрытие ИИ в каждом сообщении, удаление данных по команде. Переход в режим `family` или `public` возможен только по отдельному правовому решению. Портфель не покидает РФ: для портфельного контекста используются только модели с внутренним размещением.
